# ส่วนที่ 1 — โค้ดและการทำงานของแบบจำลอง (พัฒนาเพิ่มจากรายงาน #2)

รายงาน #2 นำเสนอเพียง *แนวทาง* รอบนี้ได้ implement เป็นระบบที่รันได้จริงบน Google Colab (Tesla T4) ครบทั้ง pipeline ตั้งแต่เตรียมข้อมูล → SEIR baseline → LLM residents → LLM leader

## 1.1 สถาปัตยกรรมโดยรวม

ระบบปิด feedback loop ระหว่าง 2 ส่วนตามที่เสนอใน #2:

```
ประชาชน (LLM) เลือกกิจกรรม ── สัดส่วน action ──► ContactModel แปลงเป็น q_out
        ▲                                                   │
        │ สถานการณ์เมื่อวาน (ยอดเคส, มาตรการ, อาการตัวเอง)      ▼
   SEIR (รายวัน) ◄──────────── beta_eff = f(q_out, นโยบาย) ───┘
        ▲
   ผู้นำ (LLM) เลือกระดับมาตรการทุก 7 วัน  (เฉพาะเงื่อนไข D)
```

## 1.2 โครงสร้างโค้ด (แพ็กเกจ `gabm/`)

| โมดูล | หน้าที่ |
|---|---|
| `seir.py` | SEIR เชิงกลไก เดินทีละวันด้วย `solve_ivp`, ตรวจอนุรักษ์ S+E+I+R=N, คำนวณ final size |
| `contacts.py` | **mapping จาก action → ระดับการสัมผัส → `beta_eff`** (หัวใจของ #2 ที่สัญญาว่าจะทำให้โปร่งใส) |
| `llm.py` | backend (transformers 4-bit / vLLM / mock), prompt ประชาชน, การ validate JSON + retry + fallback |
| `policy.py` | เงื่อนไข B (rule-based) และผู้นำรายสัปดาห์ (เงื่อนไข D) |
| `sim.py` | daily loop เงื่อนไข A–D พร้อม checkpoint ทุกวัน |
| `agents.py`, `io.py`, `analysis.py` | persona/health, บันทึกผล (run id = hash ของ config+persona+seed), metric & plot |

## 1.3 กลไกสำคัญ (พร้อมโค้ดจริง)

**(ก) การเชื่อมพฤติกรรม→โรค อย่างโปร่งใส** — จุดที่รายงาน #2 ระบุว่า "การขยาย action จะมีความหมายก็ต่อเมื่อมี contact mapping ที่ตรวจสอบได้" ระดับการสัมผัสนอกบ้านต่อ action มาจากเมทริกซ์ Prem et al. (2021) ของไทย:

```python
# gabm/contacts.py — c_out[a] ต่อ action, และ beta_eff
self.c_out = {
    "stay_home":        0.0,
    "work_onsite":      work_per_worker + p["f_work_other"] * loc["others"],
    "essential_errand": p["f_errand"]  * loc["others"],
    "visit_family":     p["f_visit"]   * loc["others"] + p["f_visit_home"] * self.home,
}
self.base_out = sum(self.baseline_mix[a] * self.c_out[a] for a in self.actions)
self.w_home   = self.home / (self.home + self.base_out)

def beta_eff(self, beta0, q_out, q_policy=1.0):
    return beta0 * (self.w_home + (1 - self.w_home) * q_out * q_policy)
```

การสัมผัสในครัวเรือนถูกเก็บไว้เสมอ ดังนั้น `stay_home` ไม่เท่ากับการสัมผัสเป็นศูนย์ — ต่างจาก action แบบทวิภาคในงานที่ 1 และ 3

**(ข) การตัดสินใจของ LLM + การตรวจความถูกต้อง** — ทุกโมเดลใช้ prompt เดียวกัน ตอบเป็น JSON เท่านั้น ระบบ parse → ตรวจว่า action อยู่ในชุดที่อนุญาต → ถ้าผิดลองใหม่ 1 ครั้ง → ถ้ายังผิดใช้ action เดิม (flag `fallback`) และบันทึก raw output ทุกครั้ง (ไม่มี fallback เงียบ):

```python
# gabm/llm.py — decide_batch (ย่อ)
raw = backend.generate(prompts, seed=seed, **kw)              # 1) generate
for r in raw: choice, reason, err = parse_choice(r, allowed)  # 2) parse+validate JSON
...                                                           # 3) retry เฉพาะอันที่ผิด
for j, rec in enumerate(records):
    rec["valid"] = rec["choice"] is not None
    rec["fallback"] = not rec["valid"]
    if rec["fallback"]: rec["choice"] = fallbacks[j]          # 4) fallback = action เดิม
```

**(ค) เงื่อนไข B และผู้นำ** — เงื่อนไข B ใช้ตัวปรับพฤติกรรมของ Aoki & Ghaffarzadegan `m = 1/(1+α·cases7)`; ผู้นำเลือกระดับ `open/limited/strict` ซึ่งกำหนด `q_policy = 1 − k·d` และ action ที่ถูกห้าม โดยไม่แตะ state ของ SEIR โดยตรง

## 1.5 เงื่อนไขการทดลองและสภาพแวดล้อม

|---|---|---|

# ส่วนที่ 2 — ผลการทดลองเบื้องต้น (6 การทดลอง)

> เกณฑ์กำหนด "อย่างน้อย 3 การทดลอง" — รายงานนี้นำเสนอ 6 การทดลอง โดย **การทดลองที่ 3, 4, 6 คือแกนหลัก** ของวิธีที่เสนอ ส่วนที่ 1, 2, 5 เป็นการตรวจสอบความถูกต้องและความเป็นไปได้

## การทดลองที่ 1 — ตรวจความถูกต้องของ SEIR (เงื่อนไข A เทียบ B)

**วัตถุประสงค์:** ยืนยันว่าแกนกลไกโรคถูกต้องก่อนใส่พฤติกรรม LLM
**ผล:** รัน R₀ = β₀·infectious_days = 0.2×10 = **2.0**

| | A (ไม่ตอบสนอง) | B (rule-based) |
|---|---|---|
| attack rate 30 วัน | 3.9% | 2.8% |
| attack rate 180 วัน | **79.1%** | 46.5% |
| วันพีค (180 วัน) | วันที่ 87 | — |

ค่า final size เชิงทฤษฎีจาก `z = 1 − e^(−R₀z)` ที่ R₀=2 ให้ z ≈ **0.797** ซึ่งตรงกับผลจำลอง A (0.791) → **SEIR ทำงานถูกต้อง** และ S+E+I+R = N ผ่านทุกวัน (`check_conservation`) เงื่อนไข B ที่มีการลดการออกตามยอดเคสกด attack rate ลงเหลือ 46.5% ตามคาด

## การทดลองที่ 4 — ผู้นำ LLM รายสัปดาห์ (เงื่อนไข D เทียบ C) ★แกนหลัก

**วัตถุประสงค์:** วัดผลเพิ่มของการมีผู้นำ (ablation D vs C) ตามแนว Aoki & Ghaffarzadegan

| โมเดล | attack rate C | attack rate D | ลดลง |
|---|---|---|---|
| Typhoon-8B | 2.40% | 1.65% | **−31.4%** |
| Qwen2.5-7B | 5.46% | 3.51% | **−35.8%** |

**เส้นทางนโยบายของผู้นำ (ทุก seed):** `open → limited → limited → limited → limited` — ทั้งสองโมเดล**ไม่เคยยกระดับเป็น "strict" เลย** แม้ยอดเคสจะเพิ่มถึง ~50–65 ต่อแสนต่อวัน โดยให้เหตุผลซ้ำว่า "ถ่วงดุลกับการทำมาหากินของประชาชน"
**การตีความ:** การเพิ่มชั้นผู้นำช่วยลดการระบาดจริง ~1 ใน 3 แต่พฤติกรรมผู้นำของสองโมเดลแทบเหมือนกัน → **ความต่างของผล D มาจากพฤติกรรมของประชาชน ไม่ใช่จากผู้นำ** สอดคล้องกับ policy inertia ที่ Aoki & Ghaffarzadegan รายงาน
_รูป: `outputs/figures/05_leader_typhoon8b.png`, `05_leader_qwen7b.png`_

## การทดลองที่ 5 — Sensitivity ของโครงสร้างการสัมผัส (เงื่อนไข B)

**วัตถุประสงค์:** ผลไวต่อพารามิเตอร์ contact ตัวใด

| พารามิเตอร์ | ช่วงที่กวาด | attack rate (30 วัน) |
|---|---|---|
| `w_home_scale` | 0.5 → 1.5 | 2.54% → 2.95% |
| `f_errand` | 0.3 → 0.7 | 2.80% → 2.77% (แทบนิ่ง) |
| `f_visit` | 0.15 → 0.5 | 2.79% → 2.78% (แทบนิ่ง) |

**ผล:** ไวต่อสัดส่วนการสัมผัสในครัวเรือน (`w_home`) มากที่สุด ส่วน `f_errand`/`f_visit` แทบไม่กระทบในกรอบ 30 วัน

## การทดลองที่ 6 — ความแตกต่างเชิงพฤติกรรมระหว่างโมเดล (robustness) ★แกนหลัก

**วัตถุประสงค์:** ตรวจว่าความต่างของ 2 โมเดลเป็นสัญญาณจริงหรือเป็นเพียง stochastic noise — ตอบประเด็น internal validity ที่ Ferencz et al. เน้น

- ช่องว่าง attack rate ใน C = 0.031 ขณะที่ส่วนเบี่ยงเบนมาตรฐานระหว่าง seed เพียง 0.0002–0.0006
- **ช่องว่างระหว่างโมเดล ≈ 53 เท่าของ noise ระหว่าง seed** → ความต่างเป็น finding ที่แข็งมาก ไม่ใช่ความบังเอิญ
- ไม่มีโมเดลใดเลือก `visit_family` เลยจาก ~7,200 การตัดสินใจ

**นัยสำคัญ:** การเลือก LLM มีผลต่อข้อสรุปของ GABM อย่างมีนัย — ยืนยันข้อกังวลเรื่อง internal/cultural validity และเป็นเหตุผลที่โครงงานนี้ควบคุม prompt/schema ให้เหมือนกันทุกโมเดล

# ส่วนที่ 3 — ข้อค้นพบเบื้องต้นและข้อจำกัด

**ข้อค้นพบ**
1. Pipeline ทำงานครบและผ่านเกณฑ์เทคนิค (schema valid 100%, fallback 0%, VRAM พอดี T4)
2. **Typhoon (จูนไทย) ให้พฤติกรรมสมจริงและระมัดระวังกว่า Qwen** — การเลือกโมเดลเปลี่ยนผลอย่างมาก
3. ชั้นผู้นำลดการระบาด −31% ถึง −36% แต่ผู้นำเลือกมาตรการระดับกลางเสมอ

**ข้อจำกัด (ยอมรับตามแนวงานที่ทบทวน)**
- เป็น **scenario study ไม่ใช่ forecast ที่ calibrate** — เทียบเชิงคุณภาพเท่านั้น (เช่นเดียวกับ Williams et al. และ Aoki & Ghaffarzadegan)
- กรอบ 30 วัน และพารามิเตอร์หลายตัว (WFH ability, income loss) ยังเป็น assumption
- ทำ sensitivity เฉพาะเงื่อนไข B ยังไม่ครบแกน `wfh_scale` ที่กระทบ prompt ของ LLM โดยตรง
- ข้อสรุปจำกัดอยู่กับ 2 โมเดลและ quantization 4-bit ที่ทดลอง
