# 1. บทคัดย่อ (Abstract)

แบบจำลองโรคระบาดที่ใช้ LLM เป็นผู้ตัดสินใจ (generative agent-based modeling, GABM) พัฒนาและตรวจสอบในบริบทตะวันตกเป็นหลัก เมื่อจะใช้กับประชากรไทย ทางเลือกที่เป็นธรรมชาติคือเปลี่ยนไปใช้โมเดลที่จูนด้วยภาษาไทย งานนี้ทดสอบว่าทางเลือกนั้นเปลี่ยนพฤติกรรมของ agent อย่างไร เราสร้างแบบจำลอง SEIR ของจังหวัดสังเคราะห์ (N = 1,000,000, R₀ = 2.0) ที่มี LLM agent 40 ตัวเลือกกิจกรรมรายวันจากสี่ตัวเลือก การออกแบบเป็น 2×2 (ตระกูลโมเดล × การจูนภาษาไทย) ได้แก่ `llama8b`/`typhoon8b` และ `qwen7b`/`openthaigpt7b` พร้อมตัวควบคุม `seallm7b` การตัดสินใจรวม 410,400 ครั้งไม่มี fallback เลย ผลหลักคือการจูนภาษาไทยกลับเครื่องหมายระหว่างตระกูล attack rate สะสม 180 วันในตระกูล Llama ลดลง 0.1814 (0.8195 เป็น 0.6381) ส่วนในตระกูล Qwen เพิ่มขึ้น 0.0266 (0.8325 เป็น 0.8591) ในเงื่อนไขที่มีผู้นำ LLM ผลเป็น −0.344 และ +0.056 ตามลำดับ ค่า exact permutation p = 0.0022 ทั้งสองตระกูล ซึ่งเป็นค่าต่ำสุดที่ n = 6 ให้ได้ ค่านี้จึงสะท้อนจำนวน seed ไม่ใช่ความแรงของหลักฐาน ความแรงของหลักฐานพิจารณาจากขนาดของผลข้างต้น `seallm7b` (0.8449) อยู่ในกลุ่มโมเดลฐาน ผลชี้ว่ากลไกคือกรอบการให้เหตุผลและระดับที่โมเดลใช้ข้อความใน prompt โดยกรอบ "รายได้" ลดจาก 54% เป็น 19% ในตระกูล Llama แต่เพิ่มจาก 56% เป็น 65% ในตระกูล Qwen ผู้นำ LLM รายงานสถานการณ์ถูกต้องทุกสัปดาห์ แต่เลือกระดับ `strict` เพียง 5 ครั้งจาก 702 ผลหลักคงเครื่องหมายเดิมเมื่อสลับลำดับตัวเลือก กวาดพารามิเตอร์ และเปลี่ยน `baseline_mix` ข้อจำกัดสำคัญคือทุก seed ใช้ `persona_seed` เดียวกัน การสุ่มบุคลิกซึ่งน่าจะเป็นความไม่แน่นอนที่ใหญ่กว่าจึงยังไม่ถูกสุ่มเลย นัยเชิงปฏิบัติคือการเลือกโมเดลที่จูนภาษาท้องถิ่นไม่อาจใช้แทนการตรวจสอบความสมเหตุสมผลได้

# 2. บทนำ (Introduction)

แบบจำลอง SEIR เชิงกลไกอธิบายการแพร่เชื้อได้ดี แต่รองรับพฤติกรรมมนุษย์ได้จำกัด ทั้งที่พฤติกรรมกำหนดเส้นทางการระบาดโดยตรง Williams et al. (2023) ชี้ว่างานที่ผูกกับข้อมูลจริงส่วนใหญ่ป้อนพฤติกรรมแบบ exogenous (เช่นอนุกรมเวลาการเดินทาง) และมีส่วนน้อยที่ให้พฤติกรรมตอบสนองต่อสถานะโรคแบบ endogenous แนวทาง GABM ใช้ LLM เป็นตัวแทนที่ตัดสินใจรายวันโดย modeler ไม่ต้องเขียนกฎล่วงหน้า พฤติกรรมจึงเป็น endogenous โดยธรรมชาติ

แนวทางนี้เปิดคำถามเรื่อง *พฤติกรรมที่เห็นเป็นของใคร* Ferencz et al. (2026) ตั้งคำถามว่าพฤติกรรมของ LLM agent เป็นการจำลองมนุษย์ หรือเป็นเพียง *behavioral prior* ที่ติดมากับโมเดลแต่ละตัว ปัญหานี้มีสองระดับ ระดับ internal validity คือถ้าเปลี่ยน LLM แล้วผลการระบาดเปลี่ยน ข้อสรุปเชิงนโยบายก็ไม่มีความหมาย ระดับ cultural validity คือสมมติฐานที่มักใช้โดยไม่ตรวจสอบว่า "บอก LLM ว่า agent เป็นคนประเทศ X แล้วจะได้พฤติกรรมแบบประเทศ X"

ปัญหาระดับหลังเด่นชัดกว่านอกบริบทตะวันตก เพราะ LLM ส่วนใหญ่ฝึกด้วยข้อมูลภาษาอังกฤษเป็นหลัก ทางแก้ที่ดูเป็นธรรมชาติที่สุดสำหรับประชากรไทยคือใช้โมเดลที่ **จูนด้วยภาษาไทย** การแทรกแซงนี้แรงกว่าการใส่ป้ายประเทศลงใน prompt เพราะเปลี่ยนน้ำหนักของโมเดลเอง

เท่าที่ผู้เขียนทบทวน ยังไม่มีงานทดสอบทางแก้นี้โดยตรง และการเปรียบเทียบโมเดลที่จูนไทยกับที่ไม่จูนมักข้ามตระกูลไปพร้อมกัน จึงแยกไม่ออกว่าความต่างมาจาก *การจูน* หรือ *ตระกูลโมเดล* งานนี้จึงใช้การออกแบบ 2×2 เพื่อแยกสองปัจจัย และตั้งคำถามวิจัยสองข้อ

- RQ1: การจูนภาษาไทยเปลี่ยนพฤติกรรมของ LLM agent ในแบบจำลองโรคระบาดหรือไม่ และในทิศทางใด เมื่อควบคุมตระกูลโมเดลแล้ว
- RQ2: ถ้าเปลี่ยน กลไกคืออะไร และตรวจสอบได้จากสิ่งที่โมเดลผลิตออกมาหรือไม่

ผู้นำ LLM (เงื่อนไข D) ถูกเพิ่มเข้ามาเพื่อตอบคำถามย่อยว่าความต่างระหว่างโมเดลมาจากประชาชนหรือจากผู้กำหนดนโยบาย ผลของส่วนนี้รายงานใน §5.5 บทความนี้มีผลงานสามประการ ประการแรกคือการออกแบบ 2×2 ที่แยกการจูนภาษาออกจากตระกูลโมเดล ประการที่สองคือหลักฐานว่าผลของการจูนกลับเครื่องหมายระหว่างตระกูล พร้อมกลไกที่ตรวจสอบได้จากข้อความของโมเดล ประการที่สามคือหลักฐานเชิงปริมาณว่าผู้นำ LLM อ่านสถานการณ์ถูกแต่ไม่แปลงเป็นการเลือกนโยบายที่ต่างออกไป

# 3. งานที่เกี่ยวข้อง (Related Work)

งานสามชิ้นเป็นฐานของโครงงานนี้ และวางคำถามต่อกันเป็นลำดับ

Williams et al. (2023) เสนอ Generative Agent-Based Model ที่ใช้ gpt-3.5-turbo เป็น representative proxy ของมนุษย์ โดยไม่บังคับกฎการตัดสินใจ งานนี้ทดลองสามเงื่อนไขที่เพิ่มข้อมูลป้อนกลับทีละชั้น (base run, self-health feedback, full feedback) ที่ n = 100 และ n = 1,000 และใช้ชื่อไวรัสและเมืองสมมติเพื่อเลี่ยง bias จาก COVID-19 ช่องว่างที่เหลือคือการตัดสินใจเป็นทวิภาค (อยู่บ้านหรือออกไปทำงาน) จึงแยกการสัมผัสจากงาน ธุระ และครัวเรือนไม่ได้ นอกจากนี้งานนี้ใช้โมเดลเดียว และเทียบกับโลกจริงเชิงคุณภาพเท่านั้น

Ferencz et al. (2026) เสนอ Epi-LLM framework ที่รวม LLM เข้ากับ agent-based epidemic model บน Starsim และ epi-game ที่เก็บจากมนุษย์จริง งานนี้เปรียบเทียบสี่โมเดล (DeepSeek V3, Llama 3 70B, Nemotron 120B, GPT-OSS 120B) เพื่อแยกผลของสถาปัตยกรรมออกจากขนาด ซึ่งเป็นตรรกะเดียวกับที่เราใช้แยกการจูนออกจากตระกูล นอกจากนี้ยังทดสอบ geographic label experiment ที่กำหนดให้ agent อยู่ China, Iraq, Kenya หรือ UK ช่องว่างที่เหลือคือป้ายประเทศใน prompt เป็นการแทรกแซงเชิงวัฒนธรรมที่อ่อนที่สุด และยังไม่มีงานทดสอบการจูนน้ำหนักด้วยภาษาท้องถิ่น

Aoki & Ghaffarzadegan (2026) ย้ายความสนใจไปที่ผู้กำหนดนโยบาย โดยให้ generative AI agent สวมบทนายกเทศมนตรีเลือกระดับการปิดกิจการทุก 7 วัน ใน SEIR ที่มี N = 1 ล้านคน β₀ = 0.2 ต่อวัน ระยะฟักตัว 4 วัน และระยะแพร่เชื้อ 10 วัน งานนี้พบว่านโยบายสัปดาห์ก่อนเป็นตัวทำนายที่แรงที่สุด (p<0.001) ซึ่งบ่งชี้ policy inertia และพบว่า knowledge intervention ลด cumulative cases ลงหนึ่งในสาม เรารับพารามิเตอร์โรคและสูตรพฤติกรรมของเงื่อนไข B มาจากงานนี้ ช่องว่างที่เหลือคือประชาชนในงานนั้นเป็นสมการ `b = 1/(1 + k·C)` ไม่ใช่ LLM จึงแยกไม่ได้ว่าผลมาจากผู้นำหรือประชาชนคนละเท่าไร

งานนี้ต่อจากทั้งสามชิ้นโดยให้ LLM ตัดสินใจครบสองระดับ (ประชาชน 40 agents และผู้นำ 1 agent) ใช้ action สี่ทางเลือกแทนทวิภาค เปรียบเทียบโมเดล open-weight ขนาด 7–8B ห้าตัวที่จัดเป็น 2×2 และใช้การจูนน้ำหนักเป็นการแทรกแซงเชิงวัฒนธรรม

# 4. วิธีการ (Methods)

## 4.1 แกน SEIR และการแปลงพฤติกรรมเป็นการสัมผัส

ระบบแยกส่วนที่ตัดสินใจ (LLM) ออกจากส่วนที่คำนวณการแพร่เชื้อ (SEIR) โดยสื่อสารกันผ่านตัวเลขเดียวคือ **contact modifier** ผู้นำและประชาชนไม่แตะ state ของ SEIR โดยตรง SEIR เดินทีละวันด้วย `solve_ivp` และตรวจ S + E + I + R = N ทุกวัน พารามิเตอร์โรคสามค่ารับจาก Aoki & Ghaffarzadegan (2026) และมีสถานะ `literature` ใน `data/parameter_sources.csv` ได้แก่ β₀ = 0.2 ต่อวัน ระยะฟักตัว 4 วัน และระยะแพร่เชื้อ 10 วัน จึงได้ R₀ = 2.0 ส่วนขนาดประชากร N = 1,000,000 และสัดส่วนเริ่มต้น E = I = 0.002 มีสถานะ `assumption` เพราะเป็นจังหวัดสังเคราะห์ ไม่ได้อ้างอิงจังหวัดใดจริง

อัตราการแพร่ที่มีผลคือ

> β_eff = β₀ · [ w_home + (1 − w_home) · q̄_out · q_policy ]

ระดับการสัมผัสต่อ action มาจากเมทริกซ์สัมผัสตามสถานที่ของไทยใน Prem et al. (2021) คอลัมน์ `adult_20_64` ซึ่งให้ home 4.98, work 3.857, school 0.037 และ others 5.147 คนต่อวัน ผู้ที่เลือก `stay_home` ยังคงมีการสัมผัสในครัวเรือน การอยู่บ้านจึงไม่เท่ากับการสัมผัสเป็นศูนย์ ซึ่งต่างจาก action ทวิภาคในงานที่ทบทวน

ค่า w_home = 0.507 คือสัดส่วนการสัมผัสที่เกิดในบ้านและไม่ขึ้นกับการตัดสินใจรายวัน จึงเป็นเพดานบนของสิ่งที่พฤติกรรมเปลี่ยนได้ ค่านี้คำนวณจาก `employment_rate`, `f_work_other`, `f_errand`, `f_visit` และ `baseline_mix` ซึ่งทุกตัวมีสถานะ `assumption` ตัวเลข 0.507 จึงเป็นค่าที่ได้จากสมมติฐาน ไม่ใช่ปริมาณที่วัดได้ (ความไวต่อค่านี้ทดสอบใน §5.6)

q̄_out คือค่าเฉลี่ยถ่วงน้ำหนักของการสัมผัสสัมพัทธ์ตามสัดส่วน action ที่ agent เลือกจริงในวันนั้น การสัมผัสสัมพัทธ์ของแต่ละ action คือ `work_onsite` 1.257, `visit_family` 0.918, `essential_errand` 0.770 และ `stay_home` 0.507 โดยนิยาม ประชากรที่เลือกตาม `baseline_mix` จะได้ q̄_out = 1 พอดี ดังนั้น q̄_out > 1 หมายถึง agent ออกนอกบ้านมากกว่าวันปกติ

## 4.2 เงื่อนไขการทดลอง

| เงื่อนไข | สิ่งที่กำหนดพฤติกรรม | q̄_out |
|---|---|---|
| A | ไม่มี (SEIR ล้วน) | = 1 เสมอ |
| B | กฎตอบสนองต่อยอดเคส `m(t) = 1/(1 + α·cases7)` ตาม Aoki & Ghaffarzadegan (α เป็น `literature`) | = m(t) |
| C | ประชาชนเป็น LLM 40 agents เลือกหนึ่งใน 4 action | จากสัดส่วน action ที่เลือก |
| D | C บวกผู้นำ LLM เลือกระดับมาตรการทุก 7 วัน | C บวก `q_policy` และ action ที่ถูกห้าม |

ผู้นำเลือก `open`, `limited` หรือ `strict` ซึ่งให้ `q_policy = 1 − k·d` โดย k = 0.8 (`literature`) และ d = 0.0, 0.4, 0.8 ตามลำดับ ค่า d ทั้งสามระดับมีสถานะ `assumption` โดยอิงช่วง stringency ของ OxCGRT สำหรับไทย ระดับ `strict` ห้าม `visit_family` ด้วย เงื่อนไข D ถูกกำกับด้วย gate คือจะรันก็ต่อเมื่อเงื่อนไข C ของโมเดลนั้นเสร็จครบสาม seed และ `fallback_rate` ต่ำกว่า 5%

| Qwen 2.5 7B | `qwen7b` — Qwen2.5-7B-Instruct | `openthaigpt7b` — OpenThaiGPT |

ตัวควบคุม `seallm7b` จูนด้วยหลายภาษาในเอเชียตะวันออกเฉียงใต้แต่ไม่เจาะจงไทย จึงใช้แยกผลของ *ภาษาไทยโดยเฉพาะ* ออกจากผลของ *การจูนภาษาระดับภูมิภาค* ทุกโมเดลโหลดแบบ 4-bit nf4 ผ่าน transformers บน A100-40GB และใช้ prompt, schema, persona และ seed ชุดเดียวกัน ความต่างที่วัดได้จึงมาจากน้ำหนักโมเดลเท่านั้น

ประชากรสังเคราะห์มี 40 persona สร้างจาก marginal distribution ใน `config/base.yaml` ด้วย `persona_seed = 2026` คงที่ มีหกกลุ่มอาชีพ ได้แก่ เกษตร/ประมง 11, ค้าขาย/บริการ 8, การผลิต/ก่อสร้าง 7, ไม่ได้ทำงาน 6, ออฟฟิศ 5 และภาครัฐ 3 แต่ละ persona มีอายุ อาชีพ ความสามารถทำงานจากบ้าน (บรรทัด `Can work from home`) ระดับการสูญเสียรายได้ ขนาดครัวเรือน และอื่น ๆ

prompt เป็นภาษาอังกฤษ และให้ตอบ JSON `{"action": ..., "reason": <ไม่เกิน 15 คำ>}` ช่องทางเดียวที่สถานะโรคป้อนกลับถึง agent คือบรรทัดยอดเคสรายงานต่อแสนประชากร คำตอบถูก parse และตรวจ ถ้าผิดจะลองใหม่หนึ่งครั้ง ถ้ายังผิดจะใช้ action ของวันก่อนพร้อมติดธง `fallback` ระบบบันทึก raw output ทุกครั้ง

## 4.4 การทดลองและสถิติ

ทุกรันยาว 180 วัน เงื่อนไข C ใช้ 6 seeds ทั้งห้าโมเดล เงื่อนไข D ใช้ 6 seeds ในสี่โมเดลของการออกแบบ 2×2 และ 3 seeds ในตัวควบคุม `seallm7b` รันหลักจึงรวม 57 รัน (C 30 รัน และ D 27 รัน) และมีการตัดสินใจรวม 410,400 ครั้ง เงื่อนไข A และ B ไม่มีองค์ประกอบสุ่มจึงรันครั้งเดียว ทุกรันมี `run_id` เป็น hash ของคอนฟิกที่มีผลจริง และมี `runtime.json` เขียนเมื่อรันจบเท่านั้น การทดสอบความคงทนใช้ seed 1 เพียง seed เดียว

ผลของการจูนคือ attack rate ของโมเดลจูนลบโมเดลฐานในตระกูลเดียวกัน ทดสอบด้วย **exact permutation test** โดยถือ seed เป็นหน่วย สลับป้ายครบ C(12, 6) = 924 แบบ และรายงาน p สองหาง

# 5. ผลการทดลอง (Results)

## 5.1 การตรวจสอบแกน SEIR

เงื่อนไข A ที่วันที่ 180 ให้ attack rate 0.795 แต่การระบาดยังไม่สิ้นสุด (ยังมีผู้ติดเชื้อ 0.38% ของประชากร) ค่านี้จึงยังไม่ใช่ final size เราจึงรัน A ต่อจนลู่เข้า ซึ่งไม่มีต้นทุน GPU ผลคือ 0.798176 คงที่ตั้งแต่วันที่ 365 และไม่เปลี่ยนอีกที่ 730 และ 1,095 วัน

คำตอบเชิงวิเคราะห์ที่ใช้เทียบได้คือ *s* = *s*₀·exp(−R₀(1 − *s*)) ไม่ใช่สูตร final size มาตรฐาน *z* = 1 − exp(−R₀*z*) = 0.796812 เพราะแบบจำลองหว่านเชื้อเริ่มต้น E = I = 0.002 ทำให้ *s*₀ = 0.996 ไม่ใช่ 1 สูตรที่ตรงกับเงื่อนไขเริ่มต้นให้ 0.798176 ซึ่งตรงกับเงื่อนไข A ที่ลู่เข้าแล้วถึงทศนิยมหกตำแหน่งตั้งแต่วันที่ 365 เมื่อปล่อยหางให้หมดจริงที่ 730 วัน ค่าทั้งสองต่างกันเพียง 3.8 × 10⁻¹³ ซึ่งอยู่ในระดับความคลาดเคลื่อนของ integrator (`rtol = 1e-8`) รายละเอียดอยู่ใน `scripts/analysis/seir_validation.py` แกนกลไกโรคจึงถูกต้อง

การเปรียบเทียบเงื่อนไขทั้งหมดต่อจากนี้ใช้ค่า ณ วันที่ 180 เท่ากันทุกเงื่อนไข ซึ่งเทียบกันได้แม้บางเงื่อนไขยังไม่จบ ค่า A ที่ใช้เป็นจุดอ้างอิงจึงเป็น 0.795 และเงื่อนไข B ให้ 0.469

## 5.2 ความน่าเชื่อถือของชั้น LLM

จากการตัดสินใจ 410,400 ครั้ง ไม่มี fallback เกิดขึ้นเลย (เงื่อนไข C 43,200 ครั้งต่อโมเดล และเงื่อนไข D 43,200 ครั้งต่อโมเดล ยกเว้น `seallm7b` ที่ 21,600 ครั้ง) schema ถูกต้องตั้งแต่ครั้งแรก 99.81–100% โมเดลที่ต่ำที่สุดคือ `seallm7b` ที่ 99.81% โดย retry 60 ครั้งในเงื่อนไข C และ 31 ครั้งในเงื่อนไข D แล้วผ่านทั้งหมด ไม่มีรันใดถูกตัดกลางคัน ชั้น LLM จึงไม่ใช่แหล่งของความแปรปรวนในผลต่อไปนี้ และเงื่อนไข D ผ่าน gate ในทุกโมเดล

## 5.3 ผลหลัก: การจูนภาษาไทยกลับเครื่องหมายระหว่างตระกูล (RQ1)

![](../outputs/figures/04_2x2_localisation.png)

*รูปที่ 1: attack rate สะสม 180 วัน แยกตาม 2×2 ซ้าย: เงื่อนไข C ขวา: เงื่อนไข D ตัวเลขบนแท่งคือผลของการจูน เส้นประคือเงื่อนไข A (0.795) (`outputs/figures/04_2x2_localisation.png`)*

*ตารางที่ 1: เงื่อนไข C เฉลี่ย 6 seeds (SD ในวงเล็บ)*

| โมเดล | บทบาท | attack rate |
|---|---|---|
| `llama8b` | ฐาน, Llama | 0.8195 (0.0017) |
| `typhoon8b` | จูนไทย, Llama | 0.6381 (0.0040) |
| `qwen7b` | ฐาน, Qwen | 0.8325 (0.0051) |

ผลของการจูนในตระกูล Llama คือ −0.1814 และในตระกูล Qwen คือ +0.0266 exact permutation test ให้ p = 0.0022 ทั้งสองตระกูล

ค่า p นี้เป็นค่าต่ำสุดที่การออกแบบ n = 6 ต่อโมเดลให้ได้ (924 การสลับ) ค่า p ที่ถึงค่าต่ำสุดเช่นนี้สะท้อนจำนวน seed ไม่ใช่ความแรงของหลักฐาน ความแรงของหลักฐานจึงอยู่ที่ขนาดของผลที่รายงานข้างต้น ที่ n = 3 เพดานอยู่ที่ p = 0.10 การเพิ่มเป็น 6 seeds จึงทำให้รายงาน p ต่ำกว่า 0.05 ได้ แต่ไม่ได้เพิ่มหลักฐานใหม่

SD ข้าม seed ที่ต่ำมากเป็นผลของประชากร N = 1,000,000 ซึ่งกลบความผันผวนเชิงสุ่มของ SEIR ค่านี้ไม่ได้หมายความว่า LLM ตอบเหมือนกันทุกครั้ง seed ทั้งหกใช้ `persona_seed` เดียวกัน (ดู §7) ข้อสรุปในหัวข้อนี้จึงครอบคลุมเฉพาะการสุ่มบุคลิกชุดเดียว

*ตารางที่ 2: เงื่อนไข D เฉลี่ย 6 seeds (`seallm7b` 3 seeds)*

| โมเดล | attack rate | ผลของการจูน |
|---|---|---|
| `llama8b` → `typhoon8b` | 0.6083 → 0.2641 | −0.344 |
| `qwen7b` → `openthaigpt7b` | 0.6691 → 0.7252 | +0.056 |
| `seallm7b` (ควบคุม) | 0.6927 | — |

เครื่องหมายของผลในเงื่อนไข D ตรงกับเงื่อนไข C และได้ p = 0.0022 เท่ากัน ซึ่งเป็นค่าต่ำสุดของการออกแบบที่ n = 6 ขนาดของผลในเงื่อนไข D ใหญ่กว่าในเงื่อนไข C ทั้งสองตระกูล `seallm7b` อยู่ในกลุ่มเดียวกับโมเดลฐานทั้งสอง (C = 0.8449) ผลจึงชี้ว่าการจูนภาษาระดับภูมิภาคอย่างเดียวไม่ก่อผลแบบที่การจูนไทยก่อในตระกูล Llama ตัวควบคุมนี้เป็นโมเดลเดียว และ `final_report_TH.md` ไม่ได้ระบุตระกูลฐานของมัน จึงตัดคำอธิบายอื่นออกไม่ได้

ที่วันที่ 180 เงื่อนไข A ให้ attack rate 0.795 และเงื่อนไข B ให้ 0.469 ในเงื่อนไข C ค่าเฉลี่ย q̄_out ของ `llama8b` คือ 1.104, `qwen7b` 1.178, `seallm7b` 1.220 และ `openthaigpt7b` 1.285 ซึ่งทั้งสี่เกิน 1 หมายความว่า agent ในสี่จากห้าโมเดลออกนอกบ้านมากกว่าวันปกติทั้งที่มีโรคระบาด ส่วน `typhoon8b` อยู่ที่ 0.645 ผลนี้ผูกกับ `baseline_mix` ที่เป็น `assumption` (ดู §5.6 และ §7)

การจูนเปลี่ยนกรอบ "รายได้" คนละทิศในสองตระกูล ในตระกูล Llama กรอบนี้ลดจาก 54% (`llama8b`) เหลือ 19% (`typhoon8b`) ส่วนในตระกูล Qwen เพิ่มจาก 56% (`qwen7b`) เป็น 65% (`openthaigpt7b`) ทิศนี้ตรงกับเครื่องหมายของผลใน §5.3 ทั้งสองตระกูล ไม่มีโมเดลใดเขียนเหตุผลเป็นภาษาไทยเลย แม้สองโมเดลที่จูนไทย (prompt เป็นภาษาอังกฤษ) การจูนจึงส่งผลที่เนื้อหาของการตัดสินใจมากกว่าภาษาของเอาต์พุต

หลักฐานชุดนี้มีขอบเขตสามประการ ประการแรก การจัดกรอบใช้การจับคำด้วย regex แบบไม่สนตัวพิมพ์ (`scripts/analysis/reason_analysis.py`) โดยกรอบ "รายได้" คือ `income|earn|money|wage|pay|รายได้|เงิน|ค่าจ้าง` กรอบไม่แยกขาดจากกัน ข้อความเดียวเข้าได้หลายกรอบ ผลรวมจึงเกิน 100% ได้ ประการที่สอง ตัวเลขมาจาก seed 1 เท่านั้น ไม่ใช่ค่าเฉลี่ยหก seed อย่างในตารางของ §5.3 ประการที่สาม การจับคำไม่เข้าใจการปฏิเสธ ความสอดคล้องระหว่างกรอบกับเครื่องหมายของผลจึงเป็นความสัมพันธ์ที่ตรวจสอบซ้ำได้ ไม่ใช่การพิสูจน์เชิงสาเหตุ

การเปรียบเทียบ `wfh_scale = 0.5` กับ `1.0` ที่ seed 1 ให้การทดลองแทรกแซงที่สะอาด รันสองรันต่างกันที่ agent 13 คนเดียว และต่างกันเพียงบรรทัด `Can work from home` (`no` เป็น `yes`) ส่วนที่เหลือเหมือนกัน ผลนี้เทียบกับความต่างระดับประชากรบนบรรทัดเดียวกัน ซึ่งใช้เงื่อนไข C ทั้งหก seed เฉพาะ agent ในกำลังแรงงาน 34 คน อีก 6 คนที่ไม่ได้ทำงานไม่มีบรรทัด WFH ใน prompt จึงถูกตัดออก

`openthaigpt7b` ตอบ `work_onsite` ทั้ง 180 วันไม่ว่าบรรทัดนั้นเป็นอะไร ไม่มีคำตอบใดใน 7,200 คำตอบเปลี่ยน และเส้นทางการระบาดเหมือนกันถึงทศนิยมหกตำแหน่ง ลำดับของสองการวัดตรงกันเกือบทุกตำแหน่ง (`llama8b` กับ `typhoon8b` ต่างกันเพียง 0.006 ซึ่งถือว่าเสมอ) ผลชี้ว่าสิ่งที่ต่างกันระหว่างโมเดลคือระดับที่โมเดลอ่านและใช้ข้อความใน prompt ไม่ใช่ความระมัดระวังโดยรวม

ผลนี้มีขอบเขตจำกัดสองประการ กลุ่ม "ทำงานจากบ้านได้" มาจาก agent เพียง 4 คน ทิศทางจึงมั่นคงแต่ทศนิยมตำแหน่งที่สองไม่ใช่ค่าที่แม่น นอกจากนี้จำนวน agent ที่ทำงานจากบ้านได้ในการกวาดแกนนี้มีเพียง 3, 4 หรือ 6 คนจาก 40

![](../outputs/figures/05_leader_policy_paths.png)

*รูปที่ 3: เส้นทางนโยบายรายสัปดาห์ (แถบพื้นหลัง) เทียบกับยอดเคสที่ผู้นำเห็น (เส้น) ห้าแผงแรกคือ seed 1 ของแต่ละโมเดล แผงล่างขวาคือ `llama8b` seed 2 ซึ่งเป็นรันเดียวที่ยกระดับเป็น `strict` เส้นประที่ 528 คือยอดเคสเดียวที่เคยกระตุ้น `strict` (`outputs/figures/05_leader_policy_paths.png`)*

จาก 702 การตัดสินใจ (27 รัน × 26 สัปดาห์) `strict` ถูกเลือกเพียง 5 ครั้ง ในสองรันคือ `llama8b` seed 2 และ seed 6 รันส่วนใหญ่ที่เหลือเลือก `open` ในสัปดาห์แรกแล้วเปลี่ยนเป็น `limited` และคงอยู่ตลอดที่เหลือ สองรันที่ยกระดับเป็นสองรันที่ผู้นำเห็นยอดเคสสูงสุด *ต่ำที่สุด* ในหก seed ของโมเดลเดียวกัน (528 และ 602 เทียบกับ 625, 644, 645 และ 653) ส่วน `openthaigpt7b` เห็นยอดเคส 986 ต่อแสนต่อวันแต่ยังเลือก `limited` เพราะเห็นว่าสถานการณ์ "stable" การยกระดับจึงไม่ใช่ฟังก์ชันของความรุนแรง ผลที่ D ดีกว่า C ชี้ว่าเกิดจากการตั้งระดับ `limited` ค้างไว้ ซึ่งเทียบเท่านโยบายคงที่

ส่วนต่าง C−D รวมสองทางที่นโยบายลงมือพร้อมกัน ทางแรกคือช่องทางกลไก (ตัวคูณ `q_policy` ในสมการ β_eff) ทางที่สองคือช่องทางพฤติกรรม (ประกาศและการห้ามกิจกรรมที่เปลี่ยน prompt ของประชาชน) เราแยกสองทางนี้โดยประกอบอนุกรมจาก `daily.csv` แล้วเดิน SEIR ซ้ำ โดยไม่ต้องรันเพิ่ม (`scripts/analysis/policy_decomposition.py`)

*ตารางที่ 3: การแยกช่องทางนโยบาย (เฉลี่ย 6 seeds; `seallm7b` 3 seeds)*

| โมเดล | C | D | ช่องทางกลไก | ช่องทางพฤติกรรม | q̄_out ลดลง C→D |
|---|---|---|---|---|---|
| `typhoon8b` | 0.638 | 0.264 | 0.184 | 0.218 | 35.8% |
| `llama8b` | 0.819 | 0.608 | 0.129 | 0.058 | 18.7% |
| `qwen7b` | 0.833 | 0.669 | 0.113 | 0.030 | 14.9% |
| `seallm7b` | 0.845 | 0.693 | 0.110 | 0.029 | 11.5% |
| `openthaigpt7b` | 0.859 | 0.725 | 0.107 | 0.016 | 9.7% |

ใน 13 จาก 15 รัน ค่า `q_policy` เฉลี่ยเท่ากันที่ 0.6924 (`open` สัปดาห์แรกแล้ว `limited` 173 วัน) ข้อยกเว้นคือ `llama8b` seed 2 (0.6427) และ `typhoon8b` seed 3 (0.6800) ผู้นำจึงแทบเหมือนกันทุกโมเดล และช่องทางกลไกจึงเกือบคงที่ (0.107–0.135 ในสี่โมเดล)

ช่องทางพฤติกรรมต่างกันราวสิบสามเท่า (0.218 ใน `typhoon8b` เทียบ 0.016 ใน `openthaigpt7b`) ความต่างของผลในเงื่อนไข D (0.264–0.725) จึงมาจากประชาชน ไม่ใช่ผู้นำ ลำดับของช่องทางพฤติกรรมและการลด q̄_out ตรงกับลำดับความไวต่อ prompt ใน §5.4 ที่หัวแถวและท้ายแถว (`typhoon8b` มากสุด `openthaigpt7b` น้อยสุด)

การแยกช่องทางมีขอบเขตสามประการ ประการแรก ค่าเฉลี่ย `q_policy` 0.6924 มาจากระดับ d = 0.4 ของ `limited` ซึ่งเป็น `assumption` ข้างต้น ประการที่สอง ช่องทางกลไกวัดเป็นส่วนต่างของ attack rate จึงพ่วงความโค้งของเส้น final size ซึ่งทำให้ค่าของ `typhoon8b` สูงกว่า ส่วนการลดลงของ q̄_out เป็นตัววัดที่ไม่พ่วงความโค้งนี้ ประการที่สาม การแยกไม่ใช่ counterfactual ที่สะอาด ส่วนตกค้างอยู่ระหว่าง −0.029 ถึง +0.025

## 5.6 ความคงทน

ตารางด้านล่างสรุปผลของการจูนที่ seed 1 ภายใต้การตรวจสามแบบ ได้แก่ การสลับลำดับตัวเลือกใน prompt (`rev` กลับลำดับ, `visitfirst` ย้าย `visit_family` ขึ้นต้น) การกวาดพารามิเตอร์ และการเปลี่ยน `baseline_mix`

| การตรวจ | ผลจูนในตระกูล Llama | ผลจูนในตระกูล Qwen |
|---|---|---|
| ลำดับ `base` (seed 1) | −0.176 | +0.028 |
| ลำดับ `rev` | −0.292 | +0.096 |
| ลำดับ `visitfirst` | −0.450 | +0.058 |
| `baseline_mix` ทางเลือก (`work_onsite` = 0.67) | −0.226 | +0.031 |

เครื่องหมายของผลไม่เปลี่ยนในทุกแถว แต่ขนาดขยับมากในตระกูล Llama (−0.176 ถึง −0.450) สัดส่วนกิจกรรมรายตัวก็ไม่คงทน (`essential_errand` ของ `qwen7b` อยู่ที่ 0.681 เมื่ออยู่อันดับสอง แต่ 0.000 เมื่ออยู่อันดับสุดท้าย) สัดส่วน action จึงอ้างเป็นตัวเลขเดี่ยวไม่ได้ ส่วนการเทียบระหว่างโมเดลภายใต้ลำดับเดียวกันยังใช้ได้

การกวาดพารามิเตอร์สี่แกนแกนละสามค่า (`w_home_scale`, `f_errand`, `f_visit`, `wfh_scale` ที่ seed 1 และ 180 วัน) ขยับ attack rate ของเงื่อนไข C ได้มากที่สุด 0.025 (`typhoon8b` บนแกน `wfh_scale`; `outputs/figures/04_sensitivity_C.png`) เทียบกับผลการจูน 0.181 สามแกนแรกรันบน `llama8b` เท่านั้น (เหตุผลคืองบ GPU ไม่ใช่การออกแบบ) มีเพียง `wfh_scale` ที่รันครบห้าโมเดล และเงื่อนไข C ทำงานใกล้เพดานของการระบาดอยู่แล้ว ความคงทนที่รายงานจึงส่วนหนึ่งเป็นผลของตำแหน่งบนเส้น final size และจำกัดอยู่ในระบอบที่ทดสอบ ไม่ได้ครอบคลุมทุกระบอบ

เมื่อเปลี่ยน `baseline_mix` เป็นขอบบนที่ป้องกันได้ (ทุกคนที่มีงานทำไปทำงานนอกบ้านในวันปกติ) ข้อสรุปหลักคงอยู่ ส่วนข้อสังเกตรองว่า agent LLM ทำให้การระบาดแย่กว่าไม่มีการตอบสนองเลยอ่อนลง จากสี่โมเดลเหลือสาม (`qwen7b`, `openthaigpt7b`, `seallm7b` ยังสูงกว่า A) โดย `llama8b` ลงมาอยู่ที่ 0.783 ต่ำกว่า A (0.795) และ q̄_out ของมันเป็น 0.971 ตัวเลข q̄_out จึงผูกกับสมมติฐาน ไม่ใช่ปริมาณที่วัดได้

# 6. อภิปราย (Discussion)

การจูนภาษาไทยไม่มีทิศทางที่แน่นอน ในตระกูล Llama การจูนพาโมเดลไปทางระมัดระวัง (attack rate ต่ำกว่า A) ส่วนในตระกูล Qwen การจูนเพิ่ม attack rate ผลที่เห็นจึงน่าจะมาจากปฏิสัมพันธ์ระหว่างโมเดลฐานกับข้อมูลที่ใช้จูน ไม่ใช่จากการมีอยู่ของการจูน ข้อสรุปนี้มาจากสองตระกูลเท่านั้น และการออกแบบนี้ไม่ได้แยกว่าข้อมูลจูนส่วนใดเป็นต้นเหตุ `seallm7b` อยู่กับโมเดลฐาน ซึ่งชี้ว่าการจูนภาษาระดับภูมิภาคทั่วไปไม่ก่อผลแบบเดียวกัน การที่ไม่มีโมเดลใดเขียนเหตุผลเป็นภาษาไทยสอดคล้องกับการที่การจูนเปลี่ยน behavioral prior มากกว่าความสามารถทางภาษาที่สังเกตได้

ในเชิงกลไก หลักฐานสองชุดที่คำนวณคนละวิธีให้ลำดับหัวท้ายเดียวกัน ชุดแรกคือการพลิก `Can work from home` ของ agent 13 และชุดที่สองคือความต่างระดับประชากรบนบรรทัดเดียวกัน ความไวต่อประกาศนโยบายใน §5.5 ให้ลำดับเดียวกันอีกชุดหนึ่ง จึงชี้ว่าสิ่งที่ต่างกันคือระดับที่โมเดลใช้ข้อมูลใน prompt ความสัมพันธ์นี้เป็นความสัมพันธ์ข้ามห้าโมเดล ไม่ใช่การทดสอบเชิงสาเหตุ

ผลของผู้นำใน §5.5 แสดงว่าข้อความ `reason` กับการกระทำแยกจากกันได้ การอ่านกรอบการให้เหตุผลของประชาชนใน §5.4 ว่าเป็น *คำอธิบาย* ของพฤติกรรมจึงมีขอบเขตจำกัดเช่นกัน สิ่งที่วัดได้คือสองอย่างเกิดร่วมกัน ไม่ใช่ว่ากรอบเป็นสาเหตุ

ผู้นำ LLM ทำหน้าที่เป็นนโยบายคงที่ในทางปฏิบัติ นโยบายไม่เปลี่ยนใน 25 จาก 26 สัปดาห์ในเกือบทุกรัน แม้ยอดเคสถึง 986 ต่อแสนต่อวัน ผลนี้เป็นกรณีอิ่มตัวของ policy inertia ที่ Aoki & Ghaffarzadegan (2026) รายงาน เพราะประชาชนในงานนี้เป็น LLM ด้วย เราจึงแยกได้ว่าความต่างของผลมาจากประชาชน ซึ่งงานของพวกเขาแยกไม่ได้โดยโครงสร้าง ประโยชน์ที่เห็นของผู้นำ (D ต่ำกว่า C) จึงไม่ได้สะท้อนประสิทธิผลของผู้นำ LLM

การรัน `typhoon8b` ถึง 365 วันที่ seed 1 พบว่าส่วนต่าง C−D แคบลงจาก 0.359 เหลือ 0.258 (ราว 72%) การรันนี้เป็นการสำรวจ ไม่ใช่การวัดข้ามโมเดล ตัวเลข attack rate ที่ 180 วันจึงเป็นค่า ณ วันนั้น ไม่ใช่ขนาดสุดท้ายของการระบาด

การเลือกโมเดลที่จูนภาษาท้องถิ่นไม่อาจใช้แทนการตรวจสอบความสมเหตุสมผลได้ เพียงการเปลี่ยนโมเดล attack rate ของเงื่อนไข C ก็เคลื่อนในช่วง 0.638–0.859 ซึ่งกว้างกว่าผลของการเพิ่มชั้นผู้นำในบางโมเดล การเลือก LLM จึงเป็นการตัดสินใจเชิงแบบจำลองที่สำคัญไม่น้อยกว่าการเลือกโครงสร้างแบบจำลอง ผู้ที่จะใช้ GABM กับประชากรนอกบริบทตะวันตกควรจัดการเปรียบเทียบแบบ factorial รายงานหลายโมเดล ตรวจ position bias ของลำดับตัวเลือก และดูความหลากหลายของเหตุผล เพราะ reason collapse ในตระกูล Qwen มองไม่เห็นจาก attack rate ข้อเสนอนี้ตั้งบนโมเดลห้าตัวในสองตระกูลและประชากรสังเคราะห์หนึ่งชุด จึงเป็นข้อเสนอเชิงระมัดระวัง ไม่ใช่กฎทั่วไป

# 7. ข้อจำกัด (Limitations)

ข้อจำกัดที่สำคัญที่สุดคือทุก seed ใช้ `persona_seed` เดียวกัน (2026) การเพิ่ม seed ของ LLM และของการจำลองลดความไม่แน่นอนรอบ ๆ การสุ่มบุคลิกชุดเดียวเท่านั้น ส่วนการสุ่มบุคลิกเองไม่เคยถูกสุ่มเลยแม้ครั้งเดียว และน่าจะเป็นความไม่แน่นอนที่ใหญ่กว่า เหตุผลที่เชื่อเช่นนั้นมาจากผลใน §5.4 การเปลี่ยนคุณลักษณะบรรทัดเดียวของ agent เพียงหนึ่งคนจาก 40 คนย้ายคำตอบของ `typhoon8b` ไป 111 จาก 180 วัน และจำนวน agent ที่ทำงานจากบ้านได้ในจังหวัดสังเคราะห์มีเพียง 3 ถึง 6 คน ค่า p = 0.0022 ใน §5.3 และ SD ที่ต่ำมากข้าม seed จึงอธิบายความไม่แน่นอนรอบ persona ชุดเดียวเท่านั้น ไม่ได้แสดงความมั่นใจต่อการสุ่มประชากร การแก้ที่ตรงที่สุดคือรันซ้ำภายใต้หลาย `persona_seed` ซึ่งยังไม่ได้ทำ

ข้อจำกัดอื่นเรียงตามความร้ายแรงต่อการตีความดังนี้

1. ค่า q̄_out มากกว่า 1 ในสี่จากห้าโมเดล หมายความว่า agent ออกนอกบ้านมากกว่าวันปกติระหว่างการระบาด ผลนี้ขึ้นกับ `baseline_mix` ซึ่งเป็น `assumption` ไม่มีแหล่งอ้างอิง ภายใต้ค่าทางเลือกที่อนุรักษ์นิยมที่สุดเหลือสามโมเดล ผลการจูนไม่ขึ้นกับค่านี้ แต่ข้อสังเกตว่า C รุนแรงกว่า A ขึ้นกับมัน ตัวเลข q̄_out ทุกค่าจึงผูกกับสมมติฐาน
2. ผู้นำเทียบเท่านโยบายคงที่ เพราะ `strict` ถูกใช้ 5 ครั้งจาก 702 ผลของเงื่อนไข D จึงไม่สะท้อนประสิทธิผลของผู้นำ LLM
3. การใช้ 40 agents แทนประชากรหนึ่งล้านคนเป็นการ scale ซึ่งผลทุกค่าในบทความนี้อยู่ภายใต้ขอบเขตนั้น
4. ผลทั้งหมดมาจากโมเดล 7–8B ที่ quantize แบบ 4-bit เท่านั้น ข้อสรุปจึงจำกัดอยู่ที่ขนาดและความแม่นยำนี้ การ quantize อาจกระทบพฤติกรรมในทางที่ไม่ได้วัด
5. งานนี้เป็น scenario study ไม่ใช่ forecast ที่ calibrate จังหวัดเป็นประชากรสังเคราะห์ พารามิเตอร์ 18 จาก 28 ตัวมีสถานะ `assumption` และมีเพียง 5 ตัวที่เป็น `data` การเทียบกับโลกจริงเป็นเชิงคุณภาพเท่านั้น
6. ตัวควบคุม `seallm7b` ในเงื่อนไข D ยังมี 3 seeds เพดาน p = 0.10 จึงรายงานเป็นนัยสำคัญไม่ได้สำหรับตัวควบคุมนี้ ส่วนเงื่อนไข C ที่ 6 seeds ได้ p = 0.0022 ซึ่งเป็นค่าต่ำสุดตามที่อธิบายใน §5.3
7. กรอบเวลา 180 วันไม่ใช่ final size ซึ่งตรวจกับ `typhoon8b` เพียง seed เดียวที่ 365 วัน และยังไม่ได้ตรวจกับโมเดลอื่น
8. ความคงทนบางส่วนอนุมานจากกลไก ไม่ได้วัดตรง การกวาดสามแกนรันบน `llama8b` เท่านั้น และเป็นแบบทีละแกน (one-at-a-time) จึงจับปฏิสัมพันธ์ไม่ได้ สัดส่วน action รายตัวก็ไม่คงทนต่อลำดับตัวเลือก
9. ขนาดครัวเรือนไม่ได้เข้าสู่แบบจำลอง `household_size` อยู่ใน persona แต่ w_home เป็นค่าเดียวทั้งประชากร
10. กรอบการให้เหตุผลมาจาก seed 1 และใช้การจับคำด้วย regex ที่กรอบไม่แยกขาดจากกัน (ดู §5.4)

# 8. สรุป (Conclusion)

งานนี้ถามว่าการจูนภาษาไทยทำให้ LLM agent จำลองพฤติกรรมในแบบจำลองโรคระบาดต่างไปอย่างไร โดยใช้การออกแบบ 2×2 ที่แยกตระกูลโมเดลออกจากการจูน จากการตัดสินใจ 410,400 ครั้งที่ไม่มี fallback ผลที่วัดได้คือการจูนกลับเครื่องหมายระหว่างตระกูล ในเงื่อนไข C ผลของการจูนคือ −0.1814 ใน Llama และ +0.0266 ใน Qwen ส่วนในเงื่อนไข D คือ −0.344 และ +0.056 ตามลำดับ ตัวควบคุม `seallm7b` อยู่กับโมเดลฐาน ผลชี้ว่ากลไกคือกรอบการให้เหตุผลและระดับการใช้ข้อความใน prompt

ผู้นำ LLM อ่านถูกแต่เลือกนโยบายเดิม ผลหลักคงทนต่อลำดับตัวเลือก การกวาดพารามิเตอร์ และ `baseline_mix` ส่วนข้อสังเกตรองว่า agent LLM แย่กว่าไม่ตอบสนองเลยอ่อนลงเมื่อเปลี่ยนสมมติฐาน ข้อจำกัดที่หนักที่สุดคือ `persona_seed` เดียว การศึกษานี้จึงเป็น scenario study ที่ชี้ทิศทาง ไม่ใช่การพิสูจน์ขนาดของผล

งานถัดไปที่ชัดเจนที่สุดมีสี่ข้อ ได้แก่ รันซ้ำภายใต้หลาย `persona_seed` ทดสอบ knowledge intervention ของ Aoki & Ghaffarzadegan กับ dissociation ในเงื่อนไข D ให้ w_home แปรตามขนาดครัวเรือนจริง และขยายเงื่อนไข D เป็น 6 seeds
