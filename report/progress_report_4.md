## 1.1 การออกแบบ 2×2 (ส่วนที่เพิ่มจากรายงาน #3)

รายงาน #3 เปรียบเทียบ typhoon8b (จูนไทย, ฐาน Llama-3.1-8B) กับ qwen7b (ไม่จูน, ฐาน Qwen2.5-7B) ซึ่งต่างกันสองปัจจัยพร้อมกัน จึงแยกไม่ได้ว่าผลมาจากอะไร รายงานนี้แก้ด้วยการเติมอีกสองช่อง จนได้การออกแบบ **2×2 factorial** ตามตารางต่อไปนี้

| | โมเดลฐาน (ไม่จูนไทย) | จูนภาษาไทย |
|---|---|---|
| Llama 3.1 8B | `llama8b` (Meta) | `typhoon8b` (SCB10X) |
| Qwen 2.5 7B | `qwen7b` (Alibaba) | `openthaigpt7b` (OpenThaiGPT) |

ตัวควบคุมเพิ่มเติมคือ `seallm7b` (SeaLLM, จูนหลายภาษาเอเชียตะวันออกเฉียงใต้ ไม่เจาะจงไทย) ซึ่งใช้ตรวจว่าผลที่พบเป็นผลของ "ภาษาไทยโดยเฉพาะ" หรือเป็นผลของ "การจูนภาษาในภูมิภาค" โดยทั่วไป ทุกโมเดลใช้ prompt เดียวกัน schema เดียวกัน persona ชุดเดียวกัน และ seed เดียวกัน ความต่างที่วัดได้จึงมาจากน้ำหนักของโมเดลเท่านั้น

## การทดลองที่ 7 — การจูนภาษาไทยส่งผลอย่างไร (2×2) ★แกนหลักของรายงานนี้

การทดลองนี้แยกผลของ "การจูนภาษาไทย" ออกจาก "ตระกูลโมเดล" ตามคำถามที่รายงาน #3 ตั้งไว้ ตารางต่อไปนี้แสดง attack rate สะสม 180 วัน เฉลี่ย 3 seeds โดยค่าในวงเล็บคือ SD ข้าม seed เริ่มจากเงื่อนไข C (ประชาชนเป็น LLM)

| | โมเดลฐาน | จูนไทย | ผลของการจูน |
|---|---|---|---|
| Llama 3.1 8B | 0.819 (0.001) | 0.640 (0.004) | −0.179 |
| Qwen 2.5 7B | 0.830 (0.002) | 0.858 (0.004) | +0.028 |

ในเงื่อนไข D (มีผู้นำ LLM) ผลเป็นดังนี้

| | โมเดลฐาน | จูนไทย | ผลของการจูน |
|---|---|---|---|
| Llama 3.1 8B | 0.608 (0.021) | 0.264 (0.015) | −0.344 |
| Qwen 2.5 7B | 0.669 (0.017) | 0.725 (0.008) | +0.056 |

ตัวควบคุม `seallm7b` ให้ 0.845 ในเงื่อนไข C และ 0.693 ในเงื่อนไข D ซึ่งอยู่ในกลุ่มเดียวกับโมเดลฐาน และไม่ได้ระมัดระวังแบบ typhoon8b

*ค่า C ที่แสดงเป็นค่าเฉลี่ย 6 seeds และค่า D เป็นค่าเฉลี่ย 6 seeds เช่นกัน ยกเว้นตัวควบคุม `seallm7b` ซึ่งเงื่อนไข D ยังมี 3 seeds ค่าเดิมที่เขียนไว้เมื่อ 2026-11-09 มาจาก 3 seeds และเครื่องหมายของผลไม่เปลี่ยนเมื่อขยาย*

![](../outputs/figures/04_2x2_localisation.png)

*รูปที่ 1: ผลของการจูนภาษาไทยในสองตระกูลโมเดล ลูกศรแสดงทิศและขนาดของผล เส้นประคือเงื่อนไข A ที่ไม่มีการตอบสนองเชิงพฤติกรรม*

ผลของการจูนภาษาไทยกลับเครื่องหมายระหว่างสองตระกูล การจูนไทยบนฐาน Llama ทำให้เอเจนต์ระมัดระวังขึ้นอย่างมาก ส่วนการจูนไทยบนฐาน Qwen ทำให้ระมัดระวังน้อยลงเล็กน้อย สมมติฐานที่ว่า "โมเดลที่จูนภาษาไทยย่อมจำลองพฤติกรรมคนไทยได้ดีกว่า" จึงใช้เป็นกฎทั่วไปไม่ได้ สิ่งที่กำหนดพฤติกรรมคือโมเดลฐานและข้อมูลที่ใช้จูน ไม่ใช่การมีอยู่ของการจูนภาษา ข้อนี้ตอบคำถามที่ค้างจากรายงาน #3 โดยตรง และเกี่ยวข้องกับงาน GABM ที่เลือกโมเดลตามภาษาของประชากรเป้าหมาย

ตารางต่อไปนี้เทียบทุกเงื่อนไขกับ baseline โดยแถว C เป็นค่าเฉลี่ย 3 seeds

| เงื่อนไข | attack rate | peak I | peak day | q̄_out |
|---|---|---|---|---|
| A — SEIR ไม่ตอบสนอง | 0.795 | 11.0% | 87 | 1.000 (นิยาม) |
| B — rule-based | 0.469 | 3.8% | 105 | 0.475 |
| C typhoon8b | 0.640 | 6.4% | 117 | 0.647 |
| C llama8b | 0.819 | 12.0% | 82 | 1.103 |
| C qwen7b | 0.830 | 13.1% | 76 | 1.169 |
| C seallm7b | 0.845 | 13.6% | 76 | 1.219 |
| C openthaigpt7b | 0.858 | 14.6% | 72 | 1.280 |

~~เงื่อนไข A ให้ 0.795 ตรงกับ final size เชิงวิเคราะห์ของ R₀ = 2.0 (0.797)~~ *แก้ 2026-11-11:* ข้อความเดิมไม่ถูกต้อง 0.795 คือ attack rate ที่วันที่ 180 ซึ่งการระบาดยังไม่จบ (เหลือผู้ติดเชื้อ 0.38%) และ 0.797 มาจากสูตรที่สมมติประชากรอ่อนแอทั้งหมด เมื่อรันจนลู่เข้าได้ 0.798176 ตรงกับสูตรที่คิด S₀/N = 0.996 (ส่วนต่าง 3.8×10⁻¹³) รายละเอียดอยู่ในการทดลองที่ 14 ค่า 0.795 ยังใช้เป็นจุดอ้างอิงที่วันที่ 180 ได้ โดยเรียกว่า attack rate สะสม 180 วัน ไม่ใช่ final size

4 ใน 5 โมเดลให้ `q̄_out > 1` ซึ่งหมายความว่าเอเจนต์ออกนอกบ้านมากกว่าประชากรฐาน ทั้งที่กำลังมีโรคระบาด ผลนี้ขึ้นกับพารามิเตอร์ `contacts.baseline_mix` (สัดส่วนกิจกรรมของประชากรในวันปกติ) ซึ่งมีสถานะ `assumption` ใน `data/parameter_sources.csv` และยังไม่มีแหล่งอ้างอิง ถ้าค่าจริงของ `work_onsite` ในวันปกติสูงกว่า 0.55 ที่สมมติไว้ ข้อสรุปว่า "C รุนแรงกว่า A" อาจไม่คงอยู่ รายงานนี้จึงยังไม่เคลมข้อสังเกตนี้เป็นผล

## การทดลองที่ 8 — ผู้นำ LLM ตอบสนองต่อสถานการณ์จริงหรือไม่ ★แกนหลัก

ผล (ข) พบว่าผู้นำอ่านข้อมูลถูกต้อง โดยเมื่อตรวจฟิลด์ `reason` เทียบกับตัวเลขที่ป้อนเข้า prompt ทุกสัปดาห์ พบว่ารายงานแนวโน้มตรงทุกครั้ง (rising, stable, falling ตามลำดับ) และอ้างตัวเลขได้ถูก ตัวอย่างคือ typhoon8b สัปดาห์ที่ 18 ตอบว่า *"215.0 cases per 100,000 people per day, stable trend, 15% on-site work"* ไม่มี fallback และไม่มี retry เลยในการตัดสินใจของผู้นำทั้ง 702 ครั้ง

ผล (ค) พบว่าการเลือกระดับนโยบายแทบไม่ขึ้นกับสิ่งที่ผู้นำอ่าน เส้นทางนโยบายรายสัปดาห์ (o = open, l = limited, s = strict, 26 สัปดาห์) เป็นดังนี้

```
llama8b       seed 1   olllllllllllllllllllllllll    ยอดเคสสูงสุด 625
llama8b       seed 2   olllllllllllssssllllllllll    ยอดเคสสูงสุด 528  ← รันเดียวที่ใช้ strict
llama8b       seed 3   olllllllllllllllllllllllll    ยอดเคสสูงสุด 644
qwen7b        seed 1   olllllllllllllllllllllllll    ยอดเคสสูงสุด 832
openthaigpt7b seed 1   olllllllllllllllllllllllll    ยอดเคสสูงสุด 986
typhoon8b     seed 1   olllllllllllllllllllllllll    ยอดเคสสูงสุด 228
```

จาก 702 การตัดสินใจ (27 รัน × 26 สัปดาห์) `strict` ถูกเลือกเพียง 5 ครั้งและอยู่ในสองรัน หลักฐานสองข้อชี้ว่าการยกระดับไม่ได้เป็นฟังก์ชันของความรุนแรง

1. สองรันที่ยกระดับ (llama8b seed 2 และ seed 6) เป็นสองรันที่ผู้นำเห็นยอดเคสสูงสุดต่ำที่สุดในหก seeds ของโมเดลเดียวกัน (528 และ 602 เทียบกับ 625, 644, 645 และ 653) ถ้าการยกระดับขึ้นกับจำนวนเคส อีกสี่ seed ต้องยกระดับก่อน แต่ไม่ยกเลยสักรัน
2. openthaigpt7b เห็นยอดเคส 986 ต่อแสนต่อวัน ซึ่งสูงเกือบสองเท่าของจุดที่ llama8b ยกระดับ แต่ยังคงเลือก `limited` โดยให้เหตุผลว่าสถานการณ์ "stable"

สิ่งที่ llama8b seed 2 ทำได้ถูกต้องคือผ่อนลงหลังยกระดับเมื่อเคสลดลง (strict สัปดาห์ที่ 12–15 ขณะเคส 528 ลดเป็น 470 แล้วกลับเป็น limited ที่ 440) ซึ่งเป็นพฤติกรรม closed-loop ที่พึงประสงค์ แต่เกิดขึ้นในสองรันจาก 27 รัน

ผลข้างต้นเปลี่ยนความหมายของเงื่อนไข D ในสามประการ

- ผลที่ว่า "D ดีกว่า C" ไม่ใช่ผลของนโยบายที่ปรับตามสถานการณ์ แต่เป็นผลของการตั้งระดับ `limited` ค้างไว้ตลอด ซึ่งเทียบเท่ากับการใส่ระดับนโยบายคงที่เข้าไปในแบบจำลอง
- ความต่างของ D ระหว่างโมเดล (0.268 ถึง 0.723) มาจากประชาชนตอบสนองต่อ `limited` ไม่เท่ากัน ไม่ได้มาจากผู้นำ เพราะผู้นำตัดสินใจเหมือนกันแทบทั้งหมด ข้อนี้ยืนยันและขยายข้อสังเกตจากรายงาน #3 และการทดลองที่ 15 วัดข้อนี้ตรง ๆ ด้วยการแยกช่องทางของนโยบาย
- สิ่งที่พบคือ **dissociation** ระหว่างการให้เหตุผลกับการเลือก กล่าวคือโมเดลสรุปสถานการณ์ได้ถูกต้องแต่ไม่แปลงเป็นการกระทำ นี่เป็น negative result ที่มีน้ำหนักกว่าการสรุปว่าผู้นำช่วยลดการระบาด และสอดคล้องกับ policy inertia ที่ Aoki & Ghaffarzadegan รายงานไว้ แต่รุนแรงกว่า

กลไกที่น่าจะเป็นคือ ทุกเหตุผลมีโครงสร้างเดียวกันว่า "ถ่วงดุลสุขภาพกับการทำมาหากิน" ซึ่ง `limited` เป็นตัวเลือกกลางที่สนองกรอบนี้ได้เสมอ โมเดลจึงยึดตัวเลือกกลางโดยไม่คำนึงถึงระดับความรุนแรง

## การทดลองที่ 10 — วิเคราะห์เหตุผลเชิงคุณภาพ (ตามแผนรายงาน #3 ข้อ 3) ★แกนหลัก

*รูปที่ 2: ซ้ายคือสัดส่วนเหตุผลที่ไม่ซ้ำกัน ขวาคือสัดส่วนเหตุผลที่อ้างถึงรายได้ การจูนภาษาไทยลดกรอบรายได้ในตระกูล Llama แต่เพิ่มในตระกูล Qwen*

ข้อค้นพบ (ก) คือตระกูล Qwen เกิด **reason collapse** โดย qwen7b และ openthaigpt7b ผลิตเหตุผลที่ไม่ซ้ำกันเพียง 17–19% ของการตัดสินใจ และเหตุผลเดียวครอบคลุมถึง 16% ขณะที่ตระกูล Llama และ SeaLLM อยู่ที่ 65–77% ผลนี้ตอบคำถามที่ค้างจากรายงาน #3 ว่า qwen7b เลือกไปทำงานซ้ำ ๆ เพราะผลิตเหตุผลซ้ำ ๆ โดยไม่ได้ประเมินสถานการณ์ใหม่ในแต่ละวัน

ข้อค้นพบ (ข) คือกลไกของผล 2×2 อยู่ที่กรอบการให้เหตุผล การจูนภาษาไทยเปลี่ยนกรอบที่โมเดลใช้คิด และเปลี่ยนคนละทิศในสองตระกูล

- ในตระกูล Llama การจูนไทยลดกรอบ "รายได้" ลงจาก 54% เหลือ 19% และเพิ่มกรอบ "ความจำเป็น/ความระมัดระวัง" ตามมาด้วยการที่เอเจนต์อยู่บ้านมากขึ้นและการระบาดเล็กลง
- ในตระกูล Qwen การจูนไทยเพิ่มกรอบ "รายได้" จาก 56% เป็น 65% และทำให้ความหลากหลายของเหตุผลยุบลงอีก ตามมาด้วยการที่เอเจนต์ออกไปทำงานมากขึ้นและการระบาดใหญ่ขึ้น

ผลการทดลองที่ 7 จึงไม่ได้เกิดจากความบังเอิญเชิงตัวเลข แต่มีกลไกที่ตรวจสอบได้ในข้อความที่โมเดลผลิตออกมา ความต่างอยู่ที่กรอบที่โมเดลใช้ตีความสถานการณ์ (เศรษฐกิจ เทียบกับ ความปลอดภัย) ซึ่งเป็นสิ่งที่ข้อมูลการจูนกำหนด

ไม่มีโมเดลใดตอบเหตุผลเป็นภาษาไทยเลย แม้แต่สองโมเดลที่จูนไทย เพราะ prompt เป็นภาษาอังกฤษ การจูนภาษาไทยจึงส่งผลที่ *เนื้อหาการตัดสินใจ* ไม่ใช่ที่ภาษาของเอาต์พุต ซึ่งเป็นข้อค้นพบที่ไม่ได้คาดไว้ นอกจากนี้พบ language leakage เป็นภาษาจีนหนึ่งครั้งในเหตุผลของผู้นำ qwen7b

## การทดลองที่ 12 — `visit_family` ไม่ถูกเลือก และความไวของพารามิเตอร์

รายงาน #3 ตั้งข้อสังเกตว่า "ไม่มีโมเดลใดเลือกเยี่ยมญาติ" ซึ่งขัดกับภาพจำเรื่องครอบครัวขยายในบริบทไทย การทดลองนี้ตรวจว่าเป็นพฤติกรรมจริงหรือเป็นข้อบกพร่องของการออกแบบ โดยอาศัยหลักฐานสามชั้น

1. ชั้นแรก ผลนี้ไม่ใช่ artefact ของลำดับ เมื่อยก `visit_family` ขึ้นเป็นตัวเลือกแรกในสองลำดับ (การทดลองที่ 9) ได้ส่วนแบ่งสูงสุดเพียง 1.8% (llama8b) และ qwen7b กับ openthaigpt7b ยังเป็น 0.000 พอดี
2. ชั้นที่สอง `visit_family` ไม่สำคัญเชิงระบาดวิทยาอยู่แล้ว ระดับการสัมผัสสัมพัทธ์ของ `visit_family` คือ 0.918 ซึ่งต่ำกว่าค่าเฉลี่ยของประชากร (1.0) เพราะการเยี่ยมญาติแทนที่การไปทำงาน (1.257)

## การทดลองที่ 14 — ตรวจแกน SEIR จนลู่เข้า

*(เพิ่มเมื่อ 2026-11-11)*

การทดลองที่ 7 (และการทดลองที่ 1 ของรายงาน #3) อ้างว่า attack rate ของเงื่อนไข A ที่ 180 วัน (0.795) "ตรงกับ final size เชิงวิเคราะห์ (0.797)" เมื่อตรวจใหม่พบว่าเป็นการเทียบที่ไม่ถูกสองชั้น คือ (1) ที่ 180 วันการระบาดยังไม่จบ และ (2) สูตร `z = 1 − exp(−R₀z)` สมมติว่าเริ่มต้นจากประชากรที่อ่อนแอทั้งหมด การทดลองนี้จึงตรวจใหม่ให้ถูกต้อง

เงื่อนไข A ไม่เรียก LLM เลย จึงรัน SEIR ต่อจนลู่เข้าได้โดยไม่มีต้นทุน GPU (`scripts/analysis/seir_validation.py` ผลใน `outputs/analysis/seir_validation.csv` และรัน 180 วันเดิมคือ `A_none_s0_a0b266ce`) ผลเป็นดังตารางต่อไปนี้

แกน SEIR จึงถูกต้อง และถูกต้องกว่าที่รายงานก่อนยืนยันไว้ การที่ 0.795 "ใกล้" 0.797 ในรายงานก่อนเป็นความบังเอิญของค่าที่ยังไม่ลู่เข้ากับสูตรที่ไม่ตรงเงื่อนไข ไม่ใช่การตรวจสอบ รายงานนี้แก้ข้อความดังกล่าวในการทดลองที่ 7 แล้ว

ผลนี้มีขอบเขตสามข้อ

- ค่า 0.795 ของเงื่อนไข A ที่ใช้เป็นเส้นอ้างอิงในรูปและตารางทุกที่ เป็นค่า ณ วันที่ 180 ไม่ใช่ final size การเทียบข้ามเงื่อนไขใช้ค่าที่ 180 วันเท่ากันทุกเงื่อนไข จึงยังเทียบกันได้ โดยเรียกค่านี้ว่า "attack rate สะสม 180 วัน"

1. ผลของการจูนภาษาไทยกลับเครื่องหมายระหว่างตระกูลโมเดล ในเงื่อนไข C 6 seeds ผลเป็น Llama −0.1814 และ Qwen +0.0266 (ที่ 3 seeds เป็น −0.179 และ +0.028 เครื่องหมายไม่เปลี่ยน) exact permutation test ให้ p = 0.0022 ทั้งสองตระกูล ซึ่งเป็นพื้นของการออกแบบที่ n = 6 ค่า p นี้จึงรายงานคู่กับขนาดผลเสมอ *(การทดลองที่ 7, 13)* ในเงื่อนไข D ที่ 6 seeds ผลเป็น Llama −0.344 และ Qwen +0.056 และได้ p = 0.0022 ทั้งสองตระกูลเช่นเดียวกัน ขนาดของผลในเงื่อนไข D ใหญ่กว่าในเงื่อนไข C ผลทั้งหมดนี้ชี้ว่า "จูนไทยแล้วจำลองคนไทยได้ดีกว่า" ไม่เป็นจริงเป็นกฎทั่วไป

ข้อ 1–7 เป็นข้อจำกัดที่กระทบการตีความผล

1. `contacts.baseline_mix` เป็น assumption ที่ยังไม่มีแหล่งอ้างอิง และข้อสังเกตที่ว่า "C รุนแรงกว่า A" ขึ้นกับพารามิเตอร์นี้โดยตรง จึงยังไม่เคลมเป็นผล *(สถานะ ณ 2026-11-11: รันตรวจแล้วโดยตั้ง `work_onsite = 0.67` ใน `final_report_TH.md` §5.9 ผลการจูนยังคงเครื่องหมายเดิม แต่จำนวนโมเดลที่ attack rate สูงกว่า A ลดจากสี่เหลือสาม ข้อสรุปข้างต้นจึงยังคงเดิมว่าไม่เคลมข้อสังเกตนี้เป็นผล)*
2. สัดส่วนกิจกรรมรายตัวไม่คงทนต่อลำดับใน prompt (การทดลองที่ 9) การเปรียบเทียบระหว่างโมเดลยังใช้ได้เพราะควบคุมลำดับให้เหมือนกัน แต่ตัวเลขเดี่ยวใช้อ้างไม่ได้
3. กรอบ 180 วันยังไม่พอสำหรับโมเดลที่ระบาดช้า เงื่อนไข D ของ typhoon8b มี peak ที่วันที่ 166 และวันสุดท้ายยังมีผู้ติดเชื้อ 2.1% ของประชากร ตัวเลข 0.268 จึงเป็น *attack rate สะสม 180 วัน* ไม่ใช่ขนาดการระบาดสุดท้าย ทุกตารางในรายงานนี้ใช้นิยามดังกล่าว เช่นเดียวกับค่า 0.795 ของเงื่อนไข A (การทดลองที่ 14) *(สถานะ ณ 2026-11-11: `final_report_TH.md` §5.10 รัน typhoon8b ที่ 365 วัน 1 seed แล้ว ส่วนต่าง C−D เหลือ 72% ของค่าที่ 180 วัน จึงบรรเทาแต่ไม่ลบข้อจำกัดนี้ และยังไม่ได้ตรวจกับโมเดลอื่น)*
4. ขนาดครัวเรือนไม่เข้าแบบจำลอง ค่า `household_size` ถูกบอกแก่เอเจนต์เป็นข้อความใน persona แต่ไม่ได้ถูกใช้คำนวณการสัมผัสในครัวเรือน (`w_home` เป็นค่าเดียวกันทั้งประชากร)
5. ทุก seed ใช้ persona ชุดเดียวกัน seed ทั้งหกของเงื่อนไข C (และสามของ D) ใช้ `persona_seed` เดียวกัน (2026) การเพิ่ม seed จึงลดเฉพาะความผันผวนที่มาจากการสุ่มของ SEIR และของ LLM *บนประชากร 40 คนชุดเดิม* ขณะที่การสุ่ม persona เองซึ่งน่าจะเป็นความไม่แน่นอนที่ใหญ่กว่า ยังไม่เคยถูกสุ่มเลย หลักฐานที่ชี้ว่าแหล่งนี้ใหญ่คือการแทรกแซง agent เดียวในการทดลองที่ 16 ซึ่งเปลี่ยนบรรทัดเดียวของ agent เดียวแล้วย้ายคำตอบของ `typhoon8b` ไป 111 จาก 180 วัน (เป็นข้อบ่งชี้ ไม่ใช่การวัดขนาดความไม่แน่นอนจาก persona) ค่า p = 0.0022 ในการทดลองที่ 13 จึงตอบเฉพาะคำถามว่า ภายใต้ประชากรชุดนี้ ความต่างระหว่างโมเดลเป็นสัญญาณรบกวนจาก seed หรือไม่ และไม่ได้ตอบว่าผลจะคงอยู่เมื่อสุ่มประชากรชุดใหม่
6. การแยกช่องทางนโยบายไม่ใช่ counterfactual ที่สะอาด (การทดลองที่ 15) ส่วนตกค้าง −0.029 ถึง +0.025 คือ interaction ที่ไม่ได้แยก และขนาดของช่องทางกลไกขึ้นกับ `policy_levels_d` ซึ่งมีสถานะ `assumption` ตัวเลขทั้งหมดเป็นค่า 3 seeds
7. ผลการอ่านคุณลักษณะใน prompt อยู่บน agent จำนวนน้อย (การทดลองที่ 16) คอลัมน์ "ทำงานจากบ้านได้" มาจาก 4 agent จาก 34 คน และกลุ่ม `notwork` มี 6 agent ทั้งคู่ขึ้นกับสัดส่วนอาชีพซึ่งเป็น `assumption` ทิศทางของผลมั่นคงกว่าตัวเลข

ข้อ 8–12 เป็นข้อจำกัดเชิงขอบเขต

8. งานนี้เป็น scenario study ไม่ใช่ forecast ที่ calibrate จึงเทียบเชิงคุณภาพเท่านั้น (เช่นเดียวกับ Williams et al. และ Aoki & Ghaffarzadegan)
9. Sensitivity ยังเป็นแบบ one-at-a-time และครอบคลุมโมเดลไม่เท่ากัน *(ปรับจากฉบับ 2026-11-09 ที่ระบุว่าทำบนเงื่อนไข B เท่านั้นและขาดแกน `wfh_scale` ซึ่งไม่ตรงกับสถานะปัจจุบัน)* ขณะนี้กวาดบนเงื่อนไข C แล้ว โดยสามแกนที่เกี่ยวกับโครงสร้างการสัมผัสรันบน `llama8b` เท่านั้น และ `wfh_scale` รันครบห้าโมเดล ทุกรันใช้ seed 1 ที่ 180 วัน (`final_report_TH.md` §5.8) ความคงทนของอีกสี่โมเดลต่อสามแกนแรกจึงอนุมานจากกลไกร่วม ไม่ได้วัดโดยตรง
10. เงื่อนไข C และ D ใช้ 6 seeds ยกเว้นเงื่อนไข D ของตัวควบคุม `seallm7b` ซึ่งมี 3 seeds *(แทนข้อความเดิม "3 seeds ต่อเงื่อนไข")* ทั้งสองเงื่อนไขให้ p = 0.0022 ซึ่งชนพื้นของการออกแบบพอดี จึงบอกจำนวน seed ไม่ได้บอกความแรงของหลักฐาน และต้องอ้างคู่กับขนาดของผลเสมอ ส่วนค่า SD ที่ต่ำมาก (0.001–0.030) มาจากประชากร N = 1,000,000 ซึ่งกลบความผันผวนเชิงสุ่มของ SEIR ไม่ได้หมายความว่า LLM ตอบเหมือนกันทุกครั้ง
11. การใช้ 40 เอเจนต์แทนประชากรหนึ่งล้านคนเป็นการ scale ที่ผลทุกค่าในรายงานนี้อ่านได้ภายใต้การแทนดังกล่าวเท่านั้น
12. ข้อสรุปจำกัดอยู่กับ 5 โมเดลขนาด 7–8B ที่ quantize แบบ 4-bit `mistral7b` ซึ่งวางไว้เป็น negative control ไม่ได้รันในชุด 180 วัน (ตัดสินใจยกเลิกเพื่อประหยัดคิว GPU ตาม `report/working_notes_TH.md` §8) จึงยังไม่มี negative control ในการเปรียบเทียบ

## 4.3 งานที่เสนอเพิ่มจากผลรอบนี้

ข้อเสนอต่อไปนี้เรียงตามความสำคัญ

1. สุ่ม persona หลายชุด โดยเปลี่ยน `persona_seed` แล้วรันเงื่อนไข C ซ้ำอย่างน้อยกับ 2×2 เพื่อวัดความไม่แน่นอนจากประชากรสังเคราะห์ ซึ่งเป็นแหล่งที่ยังไม่เคยถูกสุ่มและน่าจะใหญ่กว่า seed (ข้อจำกัดข้อ 5) run id ผูกกับ persona จึงไม่ชนกับรันเดิม จำนวนชุด persona และงบ GPU: [ต้องเติม]
2. รันเงื่อนไขที่ปิด `q_policy` เพื่อวัดช่องทางพฤติกรรมให้สะอาด โดยให้ประชาชนเห็นประกาศของนโยบายและตั้ง `q_policy = 1` แทนการประมาณจากการประกอบอนุกรมใหม่ (ข้อจำกัดข้อ 6)
3. เพิ่มจำนวน agent ที่ทำงานจากบ้านได้ เพราะคอลัมน์ซ้ายของการทดลองที่ 16 มี 4 agent เท่านั้น ตัวเลือกคือเพิ่มจำนวน agent หรือปรับ `occupation_share_office` ซึ่งเป็น `assumption` และการปรับนี้จะระบุเป็นการเปลี่ยนสมมติฐาน (ข้อจำกัดข้อ 7)
4. ตรวจกลุ่ม `notwork` ว่าเหตุใด `qwen7b` และ `openthaigpt7b` เลือก `essential_errand` เกือบทุกวัน และ `seallm7b` เลือก `work_onsite` ราวหนึ่งในห้า โดยแยกว่าเป็นพฤติกรรมของโมเดลหรือผลของการที่ prompt ไม่มีทางเลือกที่ผูกกับสถานะไม่ทำงาน (ยังเป็นสมมติฐาน ไม่ได้ทดสอบ)
5. Counterbalancing โดยสุ่มลำดับตัวเลือกรายเอเจนต์รายวัน เพื่อขจัด position bias ที่พบในการทดลองที่ 9 (แผนเดิมข้อ 5)
6. ปรับ prompt ของผู้นำ เพื่อทดสอบว่า dissociation ในการทดลองที่ 8 แก้ได้ด้วยการออกแบบ prompt หรือเป็นข้อจำกัดของโมเดลเอง การทดลองที่ 15 ชี้ว่าถ้าแก้ได้ ผลต่อความต่างระหว่างโมเดลจะผ่านช่องทางพฤติกรรม (แผนเดิมข้อ 6)
