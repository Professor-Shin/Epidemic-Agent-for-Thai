# 1. บทนำ

## 1.1 ที่มาและความสำคัญ

แบบจำลองโรคระบาดเชิงกลไกอย่าง SEIR อธิบายการแพร่เชื้อได้ดี แต่จัดการกับ **พฤติกรรมมนุษย์** ได้ไม่ดีนัก
ทั้งที่พฤติกรรมเป็นตัวกำหนดเส้นทางการระบาดโดยตรง Williams et al. (2023) ชี้ว่าแม้ modeler จะยอมรับความสำคัญของ
พฤติกรรม แต่งานที่ ground กับข้อมูลจริงส่วนใหญ่ยังป้อนพฤติกรรมเข้ามาแบบ **exogenous** คือใช้อนุกรมเวลาของ
การเดินทางหรือฤดูกาลเป็นข้อมูลนำเข้า มีเพียงส่วนน้อยที่กำหนดพฤติกรรมแบบ **endogenous** ให้ตอบสนองต่อสถานะ
ของโรคที่กำลังดำเนินอยู่ การขาด endogenous formulation นี้ทำให้เกิดความเอนเอียงในการพยากรณ์ระยะยาว เพราะ
แบบจำลองไม่สามารถจับได้ว่าประชาชนจะปรับตัวอย่างไรเมื่อสถานการณ์เปลี่ยน

อุปสรรคที่ทำให้แก้ปัญหานี้ยากมีสี่ประการ: พฤติกรรมมนุษย์ซับซ้อนและหลากหลายข้ามบุคคล ชุมชน และวัฒนธรรม ·
ยังไม่มีทฤษฎีที่ผ่านการ validate ว่ามนุษย์เปลี่ยนพฤติกรรมอย่างไรเมื่อเผชิญโรคระบาด · ความร่วมมือกับนักสังคมศาสตร์
และพฤติกรรมศาสตร์ยังจำกัด · และการได้ข้อมูลพฤติกรรมที่เชื่อถือได้เพื่อ validate กลไกทำได้ยาก

การมาถึงของ Large Language Model เปิดทางให้แก้อุปสรรคสองข้อแรกได้บางส่วน แนวทาง **Generative Agent-Based
Modeling (GABM)** ใช้ LLM เป็นตัวแทนของมนุษย์ที่ตัดสินใจเองในแต่ละวัน โดย modeler ไม่ต้องเขียนกฎการตัดสินใจ
ลงไปล่วงหน้า พฤติกรรมจึงเป็น endogenous โดยธรรมชาติ

## 1.2 ปัญหาที่ยังเปิดอยู่: พฤติกรรมที่เห็นเป็นของใคร

แต่แนวทางนี้เปิดคำถามใหม่ที่ร้ายแรงกว่าเดิม Ferencz et al. (2026) ตั้งคำถามตรง ๆ ว่า **พฤติกรรมที่ LLM agent
แสดงออกมานั้นเป็นของใคร** — เป็นการจำลองมนุษย์จริง หรือเป็นเพียง *behavioral prior* ที่ติดมากับโมเดลแต่ละตัว
จากข้อมูลฝึกและกระบวนการ alignment

คำถามนี้สำคัญในสองระดับ ระดับ **internal validity** คือถ้าเปลี่ยน LLM แล้วผลการระบาดเปลี่ยน ข้อสรุปเชิงนโยบาย
ที่ได้ก็ไม่มีความหมาย และระดับ **cultural validity** คือสมมติฐานที่นักวิจัยจำนวนมากใช้โดยไม่ตรวจสอบ ว่า
*"บอก LLM ว่า agent เป็นคนประเทศ X แล้วจะได้พฤติกรรมแบบประเทศ X"*

ปัญหา cultural validity แหลมคมเป็นพิเศษนอกบริบทตะวันตก เพราะ LLM ส่วนใหญ่ฝึกด้วยข้อมูลภาษาอังกฤษเป็นหลัก
ถ้าจะใช้ GABM จำลองประชากรไทย ทางแก้ที่ดูเป็นธรรมชาติที่สุดคือเลือกใช้โมเดลที่ **จูนด้วยภาษาไทย** ซึ่งเป็นการ
แทรกแซงที่แรงกว่าการใส่ป้ายกำกับประเทศลงใน prompt อย่างมาก เพราะเปลี่ยนน้ำหนักของโมเดลเอง

**แต่ยังไม่มีงานใดทดสอบว่าวิธีนี้ได้ผลจริงหรือไม่** และปัญหาเชิงการออกแบบคือ เมื่อเปรียบเทียบโมเดลที่จูนไทย
กับโมเดลที่ไม่จูน มักเป็นการเปรียบเทียบข้ามตระกูลไปด้วยพร้อมกัน จึงแยกไม่ออกว่าความต่างที่เห็นมาจาก
*การจูนภาษา* หรือจาก *ตระกูลโมเดล*

## 1.3 คำถามวิจัย

- **RQ1** การจูนภาษาไทยเปลี่ยนพฤติกรรมของ LLM agent ในแบบจำลองโรคระบาดหรือไม่ และเปลี่ยนไปในทิศทางใด
  เมื่อควบคุมตระกูลโมเดลแล้ว
- **RQ2** ถ้าเปลี่ยน กลไกที่ทำให้เปลี่ยนคืออะไร สามารถตรวจสอบได้จากสิ่งที่โมเดลผลิตออกมาหรือไม่
- **RQ3** ผู้นำ LLM ที่ตัดสินใจเชิงนโยบายรายสัปดาห์ตอบสนองต่อสถานการณ์ระบาดที่เห็นหรือไม่

## 1.4 สิ่งที่งานนี้นำเสนอ

1. **การออกแบบ 2×2 (ตระกูลโมเดล × การจูนภาษา)** ซึ่งแยกสองปัจจัยที่งานก่อนหน้าปะปนกันออกจากกัน
   โดยใช้ `llama8b`/`typhoon8b` และ `qwen7b`/`openthaigpt7b` พร้อมตัวควบคุมระดับภูมิภาค `seallm7b`
2. **หลักฐานว่าผลของการจูนภาษาไทยกลับเครื่องหมายระหว่างสองตระกูล** การจูนทำให้ตระกูลหนึ่งระมัดระวังขึ้นมาก
   แต่ทำให้อีกตระกูลระมัดระวังน้อยลง
3. **กลไกที่ตรวจสอบได้จากข้อความ** การวิเคราะห์เหตุผล 36,000 รายการพบว่าการจูนเปลี่ยน *กรอบ* ที่โมเดลใช้
   ตีความสถานการณ์ และเปลี่ยนคนละทิศในสองตระกูล ซึ่งตรงกับเครื่องหมายของผลที่วัดได้
4. **หลักฐานเชิงปริมาณว่าผู้นำ LLM แยกขาดระหว่างการให้เหตุผลกับการกระทำ** โดยรายงานสถานการณ์ถูกต้อง
   ทุกสัปดาห์แต่เลือกนโยบายเดิมแทบตลอด
5. **ชุดการทดสอบความคงทนที่งาน GABM ส่วนใหญ่ไม่ทำ** โดยเฉพาะการสลับลำดับตัวเลือกใน prompt เพื่อแยก
   พฤติกรรมจริงออกจาก position bias

# 2. งานที่เกี่ยวข้อง

งานสามชิ้นที่เป็นฐานของโครงงานนี้วางคำถามต่อกันเป็นลำดับ: ชิ้นแรกแสดงว่า LLM ใช้จำลองพฤติกรรมประชาชนได้
ชิ้นที่สองตั้งคำถามว่าพฤติกรรมนั้นเชื่อถือได้แค่ไหน และชิ้นที่สามย้ายความสนใจจากประชาชนไปที่ผู้กำหนดนโยบาย

## 2.1 GABM กับพฤติกรรมประชาชน — Williams et al. (2023)

งานนี้เสนอ Generative Agent-Based Model ที่ใช้ generative agents เป็น representative proxies ของมนุษย์
โดย **ไม่มีการบังคับกฎการตัดสินใจใด ๆ จาก modeler** ซึ่งเป็นจุดที่ต่างจาก ABM ดั้งเดิมอย่างชัดเจน

การทดลองแบ่งเป็นสามเงื่อนไขที่เพิ่มข้อมูลป้อนกลับทีละชั้น: *base run* ที่ agent รู้เพียง persona ของตัวเอง ·
*self-health feedback* ที่เพิ่มอาการเจ็บป่วยของตนเอง · และ *full feedback* ที่เพิ่มข่าวยอดผู้ติดเชื้อในชุมชน
implementation ใช้ Python + Mesa กับ gpt-3.5-turbo-0301 อายุ agent สุ่มแบบ uniform ในช่วง 18–64 ปี
บุคลิก Big Five ให้โอกาส 50/50 ระหว่างขั้วบวกและลบของแต่ละ trait ระยะโรคกำหนดไว้ 6 วัน โดยวันที่ 1–2 ไม่มีอาการ
แต่แพร่เชื้อได้ วันที่ 3 และ 6 ไอเล็กน้อย และวันที่ 4–5 มีไข้และไอ

จุดที่น่าสนใจเชิงวิธีวิทยาคือผู้เขียนใช้ **ชื่อไวรัสและชื่อเมืองสมมติ** เพื่อเลี่ยง bias เรื่อง COVID-19 ที่ฝังอยู่ใน LLM
อยู่แล้ว ประชากรทดลองมี n = 100 ในรอบแรกและ n = 1,000 ในรอบขยาย contact rate 5 และ infectivity 0.1
ให้ R₀ ≈ 3 (รอบขยายทดสอบ R₀ = 2, 2.5 และ 3 ด้วย) วิเคราะห์จาก decision log รายบุคคลรายวันประมาณ
67,000 observations

**ข้อจำกัดที่เปิดช่องไว้:** การตัดสินใจเป็นทวิภาค (อยู่บ้าน หรือออกไปทำงาน) ซึ่งแยกการสัมผัสจากงาน ธุระ
และครัวเรือนออกจากกันไม่ได้ และใช้โมเดลเดียว จึงไม่ได้ตอบว่าผลขึ้นกับการเลือกโมเดลหรือไม่ นอกจากนี้
การเทียบกับโลกจริงเป็นเชิงคุณภาพเท่านั้น ไม่มีการ fit กับ epidemic curve ของประเทศใด

## 2.2 พฤติกรรมเป็นของใคร — Ferencz et al. (2026), Epi-LLM

งานนี้ใกล้เคียงกับคำถามของโครงงานนี้ที่สุด และเป็นงานที่กำหนดช่องว่างที่เราเข้าไปเติม

ผู้เขียนเสนอ **Epi-LLM framework** ซึ่งอ้างว่าเป็นงานแรกที่รวม LLM เข้ากับ agent-based epidemic model
และ behavioural epi-game ที่เก็บจากมนุษย์จริง โดยมีองค์ประกอบดังนี้ แบบจำลองโรคสร้างบน Starsim ใช้ SEIR
ระยะ 15 วันและคำนวณการแพร่เชื้อรายชั่วโมง · เครือข่ายการสัมผัสเป็น dynamic random network ที่
parameterize จาก empirical contact degree distribution ของ AUIB epigame โดย fit ด้วย log-normal ·
agent เลือกกักตัวหรือไม่แบบทวิภาครายวันภายใต้ **economic trade-off ที่เป็นตัวเลขจริง** คือได้ 5 แต้มถ้ากักตัว
เทียบกับ 10–15 แต้มถ้าออกไปใช้ชีวิต · และ agent ถูก initialize ด้วย health beliefs สี่มิติจาก Health Belief
Model ที่ดึงค่ามาจากคำตอบ survey ของมนุษย์จริงในการศึกษา AUIB epigame ที่ American University of
Iraq-Baghdad

การเปรียบเทียบโมเดลออกแบบมาอย่างรัดกุม: ทดสอบ 4 โมเดลคือ DeepSeek V3, Llama 3 70B, Nemotron 120B
และ GPT-OSS 120B ซึ่งครอบคลุมสองตระกูลสถาปัตยกรรม (dense transformer และ Mixture-of-Experts)
ที่สเกล 70B–120B **เพื่อแยกผลของสถาปัตยกรรมออกจากผลของขนาดโมเดล** — ตรรกะการออกแบบเดียวกับที่
โครงงานนี้ใช้แยกการจูนภาษาออกจากตระกูลโมเดล

ส่วนที่เกี่ยวข้องกับเราโดยตรงที่สุดคือ **geographic label experiment** ซึ่งกำหนดให้ agent อยู่ที่ China, Iraq,
Kenya หรือ UK อันเป็นสี่ภูมิภาคที่มีบรรทัดฐานการปฏิบัติตามมาตรการและบริบทการกำกับดูแลสาธารณสุขต่างกัน
อย่างชัดเจน เพื่อทดสอบสมมติฐานว่าป้ายกำกับประเทศเพียงอย่างเดียวให้พฤติกรรมตามประเทศนั้นหรือไม่

**ช่องว่างที่เหลือไว้:** การใส่ป้ายกำกับประเทศลงใน prompt เป็น **การแทรกแซงเชิงวัฒนธรรมที่อ่อนที่สุด**
เท่าที่ทำได้ คือเปลี่ยนแค่ข้อความนำเข้าโดยไม่แตะโมเดล ยังไม่มีงานใดทดสอบการแทรกแซงที่แรงกว่านั้น
คือ **การจูนน้ำหนักโมเดลด้วยภาษาและข้อมูลท้องถิ่น** ว่าจะให้ cultural validity ได้หรือไม่
โครงงานนี้เข้าไปเติมช่องว่างนั้นโดยตรง

## 2.3 ผู้นำ LLM และ policy inertia — Aoki & Ghaffarzadegan (2026)

งาน GABM ก่อนหน้าเน้นพฤติกรรมของประชาชน แต่ในความเป็นจริง การตัดสินใจเชิงนโยบายซ้ำ ๆ ของผู้บริหาร
ก็เป็นปัจจัยหลักเช่นกัน และเป็นการตัดสินใจภายใต้ feedback ที่ซับซ้อน ซึ่งเป็นสถานการณ์ที่มนุษย์มักทำได้แย่
เมื่อระบบมี delay และ feedback loop คำถามของงานนี้คือ AI agent จะทำได้ดีแค่ไหน และอะไรทำให้ทำได้ดีขึ้น

ผู้เขียนสร้าง generative AI agent สวมบทบาทนายกเทศมนตรีชื่อ Jennifer ที่ฝังอยู่ใน SEIR environment
ประชากร 1 ล้านคน β₀ = 0.2 ต่อวัน ระยะฟักตัว 4 วัน ระยะแพร่เชื้อ 10 วัน **โครงงานนี้รับพารามิเตอร์โรคชุดนี้
มาใช้ทั้งหมด** เพื่อให้เปรียบเทียบกันได้

การแตกองค์ประกอบของอัตราการแพร่เป็น β = β₀ · b · g · ε โดย b คือการปรับพฤติกรรมโดยสมัครใจ g คือ
มาตรการรัฐในช่วง 0–1 และ ε คือสัญญาณรบกวนรายวัน โดย α = 0.8 หมายความว่ามาตรการเข้มสุดลดการแพร่ได้ 80%
การทดลองแบ่งเป็น World 1 ที่นโยบายเป็นตัวแปรเดียว (b = 1) และ World 2 ที่เพิ่มพฤติกรรมสมัครใจ
**b = 1/(1 + k·C₍t−1₎)** ซึ่งให้ยอดผู้ป่วยที่ล่าช้ามีผลต่อพฤติกรรมป้องกัน — **เงื่อนไข B ของโครงงานนี้
รับสูตรดังกล่าวมาใช้โดยตรง**

agent เลือกระดับการปิดกิจการ 0–100% ทุก 7 วัน จำลอง 365 วัน และเริ่มตัดสินใจในสัปดาห์ที่ 6 ความจำใช้
recency-weighted stochastic retrieval โดยเก็บ tuple ของสัปดาห์ ระดับมาตรการ และยอดจริง แล้วสุ่มดึง
5 เหตุการณ์ด้วยน้ำหนัก exp(0.1(i−n)) LLM ที่ใช้คือ GPT-5 nano ผ่าน OpenAI API ที่ temperature 1.0
ใช้ราว 520 API calls ต่อ ensemble run การออกแบบเป็น 2×4 คือสอง world คูณสี่ configuration
(Base / Knowledge / Ensemble 10 agents / Ensemble + Knowledge) โดย **knowledge intervention**
คือข้อความประมาณ 200 คำที่อธิบาย feedback loop ของการระบาดให้ agent ฟัง

ผลที่ได้ใน World 1 เทียบกับ base: knowledge ลด cumulative cases ลงหนึ่งในสาม · **ensemble เพียงอย่างเดียว
กลับทำให้แย่ลงหนึ่งในสาม** · และ ensemble + knowledge ลดลงครึ่งหนึ่ง ส่วนใน World 2 ความต่างระหว่าง
เงื่อนไขบีบแคบลงเพราะพฤติกรรมสมัครใจกดการแพร่อยู่แล้ว

ผลจาก regression ของการตัดสินใจเป็นส่วนที่เกี่ยวข้องกับเรามากที่สุด: ยอดผู้ป่วยสัปดาห์ก่อนทำนายทั้งการพยากรณ์
(p<0.001) และระดับมาตรการ (p<0.01) แต่ **นโยบายสัปดาห์ก่อนเป็นตัวทำนายที่แรงที่สุด (p<0.001) ซึ่งบ่งชี้
policy inertia ที่สูงมาก** และความรุนแรงที่ระลึกได้จากความจำมี coefficient ติดลบ (p<0.001) ซึ่งบ่งชี้
adaptation หรือ normalization ต่อสถานการณ์เลวร้าย

ข้อสรุปของผู้เขียนคือ AI-assisted policymaking ที่ได้ผลต้องเป็นการผสาน AI เข้ากับโครงสร้างความรู้เชิงโดเมน
ที่ scaffold การให้เหตุผลเชิงสาเหตุ ไม่ใช่การปล่อยความสามารถดิบของโมเดล ผู้เขียนยอมรับข้อจำกัดว่า SEIR ที่ใช้
ไม่มี spatial heterogeneity, age structure, healthcare capacity หรือ economic feedback และ agent
ได้ข้อมูลผู้ป่วยรายสัปดาห์ที่สมบูรณ์แบบ ต่างจากผู้กำหนดนโยบายจริงที่เผชิญ reporting delay และ measurement error

**ช่องว่างที่เหลือไว้:** ประชาชนในงานนี้ไม่ใช่ LLM agent แต่เป็นสมการ `b = 1/(1 + k·C)` จึงแยกไม่ได้ว่า
ผลลัพธ์ที่ได้มาจากผู้นำหรือจากประชาชนคนละเท่าไร

# 3. วิธีการ

## 3.1 สถาปัตยกรรมโดยรวม

ระบบปิด feedback loop ระหว่างสองส่วนที่แยกจากกันอย่างชัดเจน คือ **ส่วนที่ตัดสินใจ** (LLM) กับ
**ส่วนที่คำนวณการแพร่เชื้อ** (SEIR) โดยสื่อสารกันผ่านตัวเลขเดียวคือ contact modifier

```
ประชาชน (LLM) เลือกกิจกรรม ── สัดส่วน action ──► ContactModel แปลงเป็น q_out
        ▲                                                   │
        │ สถานการณ์เมื่อวาน (ยอดเคส, มาตรการ, อาการตัวเอง)      ▼
   SEIR (รายวัน) ◄──────────── beta_eff = f(q_out, นโยบาย) ───┘
        ▲
   ผู้นำ (LLM) เลือกระดับมาตรการทุก 7 วัน  (เฉพาะเงื่อนไข D)
```

การแยกนี้สำคัญเพราะทำให้ตรวจสอบได้ว่าความต่างระหว่างโมเดลมาจากพฤติกรรมล้วน ๆ ไม่ใช่จากการที่ LLM
ไปแตะ state ของโรคโดยตรง โครงสร้างโค้ดแบ่งเป็นแพ็กเกจ `gabm/` ที่มีโมดูล `seir.py` (กลไกโรค),
`contacts.py` (การแปลง action เป็นการสัมผัส), `llm.py` (backend และการตรวจความถูกต้องของคำตอบ),
`policy.py` (เงื่อนไข B และผู้นำ), `sim.py` (daily loop), `agents.py`, `io.py` และ `analysis.py`

## 3.2 กลไกโรค

SEIR เชิงกลไกเดินทีละวันด้วย `solve_ivp` พร้อมตรวจการอนุรักษ์ S + E + I + R = N ทุกวัน พารามิเตอร์รับมาจาก
Aoki & Ghaffarzadegan (2026) ทั้งชุด: ประชากร N = 1,000,000 · β₀ = 0.2 ต่อวัน · ระยะฟักตัว 4 วัน ·
ระยะแพร่เชื้อ 10 วัน จึงได้ **R₀ = β₀ × infectious_days = 2.0** สัดส่วนผู้มีอาการ 0.7 และเริ่มต้นด้วย
ผู้ติดเชื้อระยะฟักตัวและระยะแพร่เชื้ออย่างละ 0.2% ของประชากร

## 3.3 การแปลงพฤติกรรมเป็นการสัมผัส

นี่คือจุดเชื่อมที่ต้องโปร่งใสที่สุด เพราะการขยายจาก action ทวิภาคเป็นสี่ทางเลือกจะมีความหมายก็ต่อเมื่อ
แต่ละทางเลือกแปลงเป็นระดับการสัมผัสที่ตรวจสอบได้ ระดับการสัมผัสต่อ action มาจากเมทริกซ์การสัมผัสตามสถานที่
ของไทยใน Prem et al. (2021) คอลัมน์ `adult_20_64` ซึ่งให้ค่า home 4.98 · work 3.857 · school 0.037 ·
others 5.147 คนต่อวัน

```python
# gabm/contacts.py
self.c_out = {
    "stay_home":        0.0,
    "work_onsite":      work_per_worker + p["f_work_other"] * loc["others"],
    "essential_errand": p["f_errand"]  * loc["others"],
    "visit_family":     p["f_visit"]   * loc["others"] + p["f_visit_home"] * self.home,
}
self.base_out = sum(self.baseline_mix[a] * self.c_out[a] for a in self.actions)
self.w_home   = self.home / (self.home + self.base_out)

def beta_eff(self, beta0, q_out, q_policy=1.0):
    return beta0 * (self.w_home + (1 - self.w_home) * q_out * q_policy)
```

ค่าที่ได้จากคอนฟิกหลักเป็นดังนี้ โดย `base_out` = 4.835 และ `w_home` = 0.507 และระดับการสัมผัสสัมพัทธ์
คำนวณจาก `(1 − w_home)·(c_out / base_out) + w_home`

| action | c_out (คนต่อวัน) | การสัมผัสสัมพัทธ์ |
|---|---|---|
| `work_onsite` | 7.356 | **1.257** |
| `visit_family` | 4.034 | 0.918 |
| `essential_errand` | 2.573 | 0.770 |
| `stay_home` | 0 | 0.507 |

ประเด็นสำคัญคือ **`stay_home` ไม่เท่ากับการสัมผัสเป็นศูนย์** เพราะการสัมผัสในครัวเรือนถูกเก็บไว้เสมอ
ซึ่งต่างจาก action แบบทวิภาคของ Williams et al. และ Epi-LLM ที่การอยู่บ้านมักหมายถึงการตัดการสัมผัสทิ้ง
ค่า `w_home` = 0.507 หมายความว่าครึ่งหนึ่งของการสัมผัสทั้งหมดเกิดในบ้านและไม่ขึ้นกับการตัดสินใจรายวัน
ซึ่งเป็นเพดานบนของสิ่งที่พฤติกรรมจะเปลี่ยนได้

ค่า `q_out` คือค่าเฉลี่ยถ่วงน้ำหนักของการสัมผัสสัมพัทธ์ตามสัดส่วนที่ agent เลือกจริงในวันนั้น โดยนิยามแล้ว
ประชากรฐานที่เลือกตาม `baseline_mix` จะให้ `q_out` = 1 พอดี ดังนั้น **`q_out` > 1 หมายถึง agent
ออกนอกบ้านมากกว่าวันปกติ**

## 3.4 ประชากรสังเคราะห์และ persona

สร้าง 40 persona จาก marginal distribution ที่กำหนดใน `config/base.yaml` ด้วย `persona_seed` คงที่
แบ่งเป็นหกกลุ่มอาชีพ ได้แก่ เกษตร/ประมง 11 คน · ค้าขาย/บริการ 8 คน · การผลิต/ก่อสร้าง 7 คน ·
ไม่ได้ทำงาน 6 คน · พนักงานออฟฟิศ 5 คน · และภาครัฐ 3 คน แต่ละ persona มีคุณลักษณะที่เข้าไปอยู่ใน prompt
โดยตรง คือกลุ่มอายุ อาชีพ ความสามารถทำงานจากบ้าน ระดับการสูญเสียรายได้ ขนาดครัวเรือน การอยู่ร่วมกับ
ผู้สูงอายุหรือผู้ป่วยเรื้อรัง การรับรู้ความรุนแรงของโรค ความไว้วางใจข้อมูลทางการ และสถานะ essential worker

prompt ของประชาชนมีโครงสร้างดังนี้ (ตัวอย่างจริงจากวันที่ 0)

```
You are simulating the daily choice of one resident in a synthetic epidemic scenario set in a
province in Thailand. A new respiratory infection is spreading. Decide as this person would.

Resident profile:
- Age group: 40-49
- Main activity: farmer or fisher (own account)
- Can work from home: no                              ← แกน wfh_scale เปลี่ยนบรรทัดนี้
- Income loss if you do not go out to work: high
- Household size: 3 people                            ← ไม่ได้เข้าแบบจำลอง ดูหัวข้อ 7
- Lives with an elderly or chronically ill person: no
- How serious you think this disease is: medium
- Trust in official health information: high
- Your work is considered essential

Today is day 0 of the simulation.
- Your health: You feel healthy and have no symptoms.
- Newly reported cases in your province today: 0.0 per 100,000 (7-day average 0.0; trend: unknown)
- Current government measures: None. Normal activities are allowed.

Choose exactly ONE main activity for today:
- stay_home / work_onsite / essential_errand / visit_family
Reply with JSON only: {"action": "...", "reason": "<at most 15 words>"}
```

บรรทัด *Newly reported cases* คือช่องทางเดียวที่สถานะของโรคป้อนกลับมาถึง agent และเป็นสิ่งที่ทำให้พฤติกรรม
เป็น endogenous ตามที่หัวข้อ 1.1 อธิบาย

## 3.5 การตรวจความถูกต้องของคำตอบ

ทุกโมเดลใช้ prompt เดียวกันและ schema เดียวกัน ระบบ parse คำตอบ ตรวจว่า action อยู่ในชุดที่อนุญาต
ถ้าผิดจะลองใหม่หนึ่งครั้ง และถ้ายังผิดจะใช้ action ของวันก่อนพร้อมติดธง `fallback` โดย**บันทึก raw output
ทุกครั้งไม่ว่าจะสำเร็จหรือไม่** จึงไม่มี fallback ที่เกิดขึ้นเงียบ ๆ

## 3.6 เงื่อนไขการทดลอง

| เงื่อนไข | สิ่งที่กำหนดพฤติกรรม | q_out |
|---|---|---|
| **A** | ไม่มี — SEIR ล้วน | = 1 เสมอ |
| **B** | กฎตอบสนองต่อยอดเคส `m(t) = 1/(1 + α·cases7)` ตาม Aoki & Ghaffarzadegan | = m(t) |
| **C** | ประชาชนเป็น LLM 40 agents เลือก 4 ทางเลือก | จากสัดส่วน action ถ่วงน้ำหนัก |
| **D** | C บวกผู้นำ LLM ที่เลือกระดับมาตรการทุก 7 วัน | C บวก `q_policy` และ action ที่ถูกห้าม |

ระดับมาตรการสามระดับให้ค่า `q_policy = 1 − k·d` โดย k = 0.8 และ d เป็น 0.0 สำหรับ `open`,
0.4 สำหรับ `limited` และ 0.8 สำหรับ `strict` ซึ่งระดับสุดท้ายห้าม `visit_family` ด้วย ผู้นำไม่แตะ state
ของ SEIR โดยตรงแม้แต่น้อย

**เงื่อนไข D ถูกกำกับด้วย gate** คือจะรันก็ต่อเมื่อเงื่อนไข C ของโมเดลนั้นเสร็จครบทั้งสาม seed และมี
`fallback_rate` ต่ำกว่า 5% เพื่อไม่ให้ชั้นผู้นำถูกวางทับบนพฤติกรรมประชาชนที่ไม่น่าเชื่อถือ

ทุกรันมี `run_id` เป็น hash ของเงื่อนไข โมเดล seed และคอนฟิกที่มีผลจริง ทำให้รันที่ทำบน Colab กับบนเซิร์ฟเวอร์

ตัววิเคราะห์จึงข้ามโฟลเดอร์ที่ไม่มีไฟล์นี้โดยอัตโนมัติ ซึ่งหมายความว่ารันที่ถูกตัดกลางคันจะไม่ปนเข้ามาในผล

พารามิเตอร์ทุกตัวมีแถวใน `data/parameter_sources.csv` พร้อมสถานะว่าเป็น `data` (5 ตัว) · `literature`
(5 ตัว) · หรือ `assumption` (18 ตัว) ซึ่งเป็นข้อมูลที่ใช้ตัดสินในหัวข้อ 7

# 5. ผลการทดลอง

ลำดับการนำเสนอเริ่มจากการยืนยันว่าเครื่องมือถูกต้องก่อน แล้วจึงเสนอผลหลัก กลไกที่อธิบายผลหลัก
และปิดท้ายด้วยการทดสอบความคงทน

## 5.1 การตรวจสอบแกน SEIR

เงื่อนไข A ซึ่งไม่มีการตอบสนองเชิงพฤติกรรมเลยให้ attack rate ที่วันที่ 180 เท่ากับ **0.795** เทียบกับ
final size เชิงวิเคราะห์ของการระบาดที่ R₀ = 2.0 ซึ่งเท่ากับ **0.797** ความคลาดเคลื่อน 0.002 ยืนยันว่า
แกนกลไกโรคทำงานถูกต้องที่กรอบเวลา 180 วัน เงื่อนไข B ที่ใช้กฎตอบสนองของ Aoki & Ghaffarzadegan
ให้ 0.469 ซึ่งต่ำกว่า A อย่างชัดเจนตามที่คาด

## 5.2 ความน่าเชื่อถือของชั้น LLM

| เงื่อนไข | การตัดสินใจต่อโมเดล | schema ถูกตั้งแต่ครั้งแรก | fallback |
|---|---|---|---|
| C | 21,600 | 99.85–100% | **0.0%** |
| D | 21,600 | 99.85–100% | **0.0%** |

จากการตัดสินใจทั้งสิ้น 216,000 ครั้ง **ไม่มี fallback เกิดขึ้นแม้แต่ครั้งเดียว** โมเดลที่ต่ำที่สุดคือ `seallm7b`
ที่ 99.85% โดยมีการ retry 32 ครั้งแล้วผ่านทั้งหมด และไม่มีรันใดถูกตัดกลางคัน ชั้น LLM จึงไม่ใช่แหล่งของ
ความแปรปรวนในผลที่รายงานต่อไปนี้

## 5.3 ผลหลัก — การจูนภาษาไทยกลับเครื่องหมายระหว่างตระกูล (RQ1)

## 5.4 กลไก — การจูนภาษาเปลี่ยนกรอบการให้เหตุผล (RQ2)

เพื่อตอบว่าอะไรทำให้ผลในหัวข้อ 5.3 เกิดขึ้น เราวิเคราะห์ฟิลด์ `reason` ที่โมเดลเขียนกำกับทุกการตัดสินใจ
จำนวน 7,200 รายการต่อโมเดล (seed 1) รวม 36,000 รายการ

![](../outputs/figures/04_reason_diversity.png)

*รูปที่ 2 — ซ้าย: สัดส่วนเหตุผลที่ไม่ซ้ำกัน ขวา: สัดส่วนเหตุผลที่อ้างถึงรายได้*

| โมเดล | เหตุผลที่ไม่ซ้ำกัน | เหตุผลที่พบบ่อยที่สุด | สัดส่วนของเหตุผลนั้น | กรอบ "รายได้" | กรอบ "ความจำเป็น" |
|---|---|---|---|---|---|
| `llama8b` | **76.5%** | "Work is considered essential and income loss is high…" | 0.7% | 54% | 34% |
| `typhoon8b` | 65.2% | "work is considered essential" | 2.4% | **19%** | 36% |
| `seallm7b` | 64.8% | "I need to maintain my income…" | 2.0% | 59% | 24% |
| `qwen7b` | **19.0%** | "Need income to support family" | 11.6% | 56% | 32% |
| `openthaigpt7b` | **17.1%** | "Need income to support family" | **16.0%** | **65%** | 23% |

**ข้อค้นพบที่หนึ่ง: ตระกูล Qwen เกิด reason collapse** โมเดลทั้งสองตัวในตระกูลนี้ผลิตเหตุผลที่ไม่ซ้ำกัน
เพียง 17–19% ของการตัดสินใจทั้งหมด และเหตุผลประโยคเดียวครอบคลุมถึง 16% ในกรณีของ `openthaigpt7b`
ขณะที่ตระกูล Llama และ SeaLLM อยู่ที่ 65–77% นี่คือคำอธิบายว่าเหตุใดตระกูล Qwen จึงเลือกไปทำงานซ้ำ ๆ
— **เพราะมันผลิตเหตุผลซ้ำ ๆ ไม่ได้ประเมินสถานการณ์ใหม่ในแต่ละวัน**

**ข้อค้นพบที่สอง: การจูนภาษาไทยเปลี่ยนกรอบที่โมเดลใช้คิด และเปลี่ยนคนละทิศในสองตระกูล**

| ตระกูล | กรอบ "รายได้" | ทิศของผลใน 5.3 |
|---|---|---|
| `llama8b` → `typhoon8b` | 54% → **19%** | −0.179 |
| `qwen7b` → `openthaigpt7b` | 56% → **65%** | +0.028 |

ในตระกูล Llama การจูนไทยลดกรอบ "รายได้" ลงเกือบสามเท่าและเพิ่มกรอบ "ความจำเป็นและความระมัดระวัง"
agent จึงอยู่บ้านมากขึ้นและการระบาดเล็กลง ส่วนในตระกูล Qwen การจูนไทยกลับ **เพิ่ม** กรอบ "รายได้"
และทำให้ความหลากหลายของเหตุผลยุบลงอีก agent จึงออกไปทำงานมากขึ้นและการระบาดใหญ่ขึ้น
**ทิศทางของการเปลี่ยนแปลงในกรอบการให้เหตุผลตรงกับเครื่องหมายของผลในหัวข้อ 5.3 ทั้งสองตระกูล**
ผลหลักจึงไม่ใช่ความบังเอิญเชิงตัวเลข แต่มีกลไกที่ตรวจสอบได้ในข้อความที่โมเดลผลิตออกมาจริง

**ข้อสังเกตที่ไม่ได้คาดไว้:** ไม่มีโมเดลใดเขียนเหตุผลเป็นภาษาไทยเลย แม้แต่สองโมเดลที่จูนภาษาไทย
เพราะ prompt ที่ให้ไปเป็นภาษาอังกฤษ **การจูนภาษาไทยจึงส่งผลที่ *เนื้อหาของการตัดสินใจ* ไม่ใช่ที่
*ภาษาของเอาต์พุต*** ซึ่งเป็นข้อค้นพบที่ขัดกับความคาดหมายตามสัญชาตญาณ และยืนยันว่าสิ่งที่การจูนเปลี่ยน
คือ behavioral prior ไม่ใช่เพียงความสามารถทางภาษา

## 5.5 ผู้นำ LLM รายงานสถานการณ์ถูกต้องแต่ไม่แปลงเป็นการกระทำ (RQ3)

ชั้นผู้นำลด attack rate ได้ในทุกโมเดล

| โมเดล | C | D | ส่วนต่าง | ยอดเคสสูงสุดที่ผู้นำเห็น (ต่อแสนต่อวัน) |
|---|---|---|---|---|
| `typhoon8b` | 0.640 | 0.268 | −0.371 | 228 |
| `llama8b` | 0.819 | 0.601 | −0.218 | 644 |
| `qwen7b` | 0.830 | 0.666 | −0.164 | 832 |
| `seallm7b` | 0.845 | 0.693 | −0.152 | 824 |
| `openthaigpt7b` | 0.858 | 0.723 | −0.135 | 986 |

เมื่อตรวจ `leader.jsonl` โดยละเอียดกลับพบข้อเท็จจริงสองอย่างที่ต้องแยกจากกัน

**ผู้นำอ่านข้อมูลได้ถูกต้อง** การตรวจฟิลด์ `reason` เทียบกับตัวเลขที่ป้อนเข้า prompt ทุกสัปดาห์พบว่า
รายงานแนวโน้มตรงกับที่ป้อนทุกครั้ง และอ้างตัวเลขได้ถูก เช่น `typhoon8b` ในสัปดาห์ที่ 18 ตอบว่า
*"215.0 cases per 100,000 people per day, stable trend, 15% on-site work"* ซึ่งถูกต้องทั้งสามค่า
และไม่มี fallback หรือ retry เลยใน 390 การตัดสินใจ

**แต่การเลือกระดับนโยบายแทบไม่ขึ้นกับสิ่งที่อ่าน**

![](../outputs/figures/05_leader_policy_paths.png)

*รูปที่ 3 — เส้นทางนโยบายรายสัปดาห์ (แถบสีพื้นหลัง) เทียบกับยอดผู้ป่วยที่ผู้นำเห็น (เส้น)
เส้นประที่ 528 คือระดับเดียวที่เคยกระตุ้นให้โมเดลใดยกระดับเป็น `strict`*

จากการตัดสินใจทั้งหมด **390 ครั้ง (15 รัน × 26 สัปดาห์) `strict` ถูกเลือกเพียง 4 ครั้ง และอยู่ในรันเดียว**
ที่เหลือทุกรันเลือก `open` ในสัปดาห์แรกตอนที่ยังไม่มีผู้ป่วย แล้วเปลี่ยนเป็น `limited` และคงอยู่อย่างนั้น
ตลอด 25 สัปดาห์ที่เหลือ

หลักฐานสองข้อที่ชี้ว่าการยกระดับไม่ได้เป็นฟังก์ชันของความรุนแรง

1. **รันเดียวที่ยกระดับคือ `llama8b` seed 2 ซึ่งมียอดเคสสูงสุดต่ำที่สุดในสาม seed ของโมเดลเดียวกัน**
   (528 เทียบกับ 625 และ 644) ถ้าการยกระดับขึ้นกับจำนวนเคส seed 1 และ 3 ย่อมต้องยกระดับก่อน แต่ไม่ยก
2. **`openthaigpt7b` เห็นยอดเคส 986 ต่อแสนต่อวัน ซึ่งสูงเกือบสองเท่าของจุดที่ `llama8b` ยกระดับ
   และยังคงเลือก `limited`** โดยให้เหตุผลว่าสถานการณ์ "stable"

สิ่งที่ `llama8b` seed 2 ทำได้ถูกต้องคือหลังยกระดับแล้วผ่อนลงเมื่อเคสลดลง โดยใช้ `strict` ในสัปดาห์ที่ 12–15
ขณะเคสลดจาก 528 เป็น 470 แล้วกลับเป็น `limited` ที่ระดับ 440 ซึ่งเป็นพฤติกรรม closed-loop ที่พึงประสงค์
แต่เกิดขึ้นครั้งเดียวใน 390 ครั้ง จึงถือเป็นเหตุบังเอิญมากกว่าความสามารถ

**การตีความ** ผลที่ว่า D ดีกว่า C **ไม่ใช่ผลของนโยบายที่ปรับตามสถานการณ์** แต่เป็นผลของการตั้งระดับ
`limited` ค้างไว้ตลอด ซึ่งเทียบเท่ากับการใส่ระดับนโยบายคงที่เข้าไปในแบบจำลองโดยไม่ต้องใช้ LLM เลย
และเนื่องจากผู้นำทุกโมเดลตัดสินใจเหมือนกันแทบทั้งหมด **ความต่างของผลในเงื่อนไข D ที่กว้างถึง 0.268–0.723
จึงมาจากประชาชน ไม่ได้มาจากผู้นำ**

กลไกที่น่าจะเป็นคือทุกเหตุผลมีโครงสร้างเดียวกัน คือการถ่วงดุลระหว่างสุขภาพกับการทำมาหากิน ซึ่ง `limited`
เป็นตัวเลือกกลางที่สนองกรอบนี้ได้เสมอไม่ว่าสถานการณ์จะเป็นอย่างไร

## 5.6 ความสมเหตุสมผลของพฤติกรรม

เพื่อยืนยันว่า agent ตอบสนองต่อเงื่อนไขส่วนบุคคลอย่างมีเหตุผล ไม่ใช่เลือกแบบสุ่ม เราตรวจสองมิติ

**แยกตามกลุ่มอาชีพ** — สัดส่วนที่เลือก `stay_home` (seed 1)

| notwork (ไม่ได้ทำงาน) | 0.320 | 0.897 | 0.019 | **0.003** | 0.774 |
| manuf (โรงงาน) | 0.150 | 0.417 | 0.083 | 0.018 | 0.062 |
| public (ภาครัฐ) | 0.037 | 0.424 | 0.000 | 0.000 | 0.002 |

| trade (ค้าขาย) | 0.001 | 0.061 | 0.024 | 0.011 | 0.008 |

ทุกโมเดลให้กลุ่ม office ซึ่งทำงานจากบ้านได้อยู่บ้านมากที่สุด และให้กลุ่ม trade และ agri ซึ่งมีรายได้รายวัน

`typhoon8b` ให้อยู่บ้าน 89.7% ขณะที่ `openthaigpt7b` ให้อยู่บ้านเพียง 0.3% และส่งออกไปทำธุระแทบทุกวัน
ทั้งที่ไม่มีภาระต้องไปทำงาน

ข้อจำกัดเชิงตรรกะของแบบจำลองทำงานถูกต้อง: **ไม่มี agent ในกลุ่ม `notwork` เลือก `work_onsite`

## 5.7 ความคงทนต่อลำดับตัวเลือกใน prompt

LLM มีแนวโน้มเลือกตัวเลือกตามตำแหน่งในรายการ ซึ่งถ้าไม่ตรวจก็ไม่มีทางรู้ว่าพฤติกรรมที่วัดได้เป็นการตัดสินใจจริง
หรือเป็น artefact ของการเรียงลำดับ เราจึงรันซ้ำทั้งห้าโมเดลที่ seed 1 ด้วยลำดับตัวเลือกสามแบบ

- `base` — `[stay_home, work_onsite, essential_errand, visit_family]`
- `rev` — กลับลำดับทั้งหมด
- `visitfirst` — ย้าย `visit_family` ขึ้นเป็นตัวแรก

แถว `base` คือรันหลักที่ seed 1 ซึ่งเป็นเหตุให้ค่าต่างจากตารางในหัวข้อ 5.3 เล็กน้อย (เช่น `seallm7b` 0.846 เทียบกับ 0.845) เพราะหัวข้อ 5.3 รายงานค่าเฉลี่ยของสาม seed

ผลนี้มีนัยสำคัญสองข้อ ข้อแรกคือ **ไม่ควรเคลมสัดส่วนกิจกรรมรายตัวเป็นตัวเลขเดี่ยว** การรายงานที่ถูกต้อง
ต้องเป็นช่วงข้ามลำดับ ข้อที่สองคือการเปรียบเทียบ *ระหว่างโมเดล* ภายใต้ลำดับเดียวกันยังใช้ได้ เพราะทุกโมเดล
เผชิญลำดับเดียวกัน ซึ่งเป็นเหตุผลที่โครงงานควบคุม prompt ให้เหมือนกันทุกโมเดลตั้งแต่ต้น

**ประเด็น `visit_family`** ตัวเลือกนี้แทบไม่ถูกเลือกเลยในทุกโมเดล เมื่อยกขึ้นเป็นตัวเลือกแรกในสองลำดับ
ได้ส่วนแบ่งสูงสุดเพียง 1.8% (`llama8b`) ส่วน `qwen7b` และ `openthaigpt7b` เป็น 0.000 พอดีแม้อยู่อันดับแรก
จึงสรุปได้ว่าเป็นพฤติกรรมจริงของโมเดล ไม่ใช่ข้อบกพร่องของการออกแบบ ประกอบกับระดับการสัมผัสสัมพัทธ์
ของ `visit_family` ที่ 0.918 ซึ่งต่ำกว่าค่าเฉลี่ยประชากร ผลกระทบเชิงระบาดวิทยาจึงน้อยมาก
**โมเดลทั้งห้าใช้กรอบ "ลดการสัมผัส" แบบสากล มากกว่ากรอบวัฒนธรรมเฉพาะถิ่นเรื่องความผูกพันในครอบครัว
แม้แต่โมเดลที่จูนภาษาไทย**

ข้อมูลจากสำนักงานสถิติแห่งชาติสนับสนุนพฤติกรรมนี้มากกว่าจะขัดแย้ง สำมะโนประชากรและเคหะ 2553 ให้
ขนาดครัวเรือนเฉลี่ย 3.1 คนและครัวเรือนคนเดียว 18.4% (เพิ่มจาก 9.4% ในปี 2543) ส่วน Digital Census

อย่างต่อเนื่อง

# 6. อภิปราย

## 6.1 ต่อยอดจาก Ferencz et al. — การจูนภาษาก็ยังไม่รับประกัน cultural validity

Ferencz et al. (2026) ตั้งคำถามว่าการบอก LLM ว่า agent มาจากประเทศใดประเทศหนึ่งจะให้พฤติกรรมแบบ
ประเทศนั้นหรือไม่ และทดสอบด้วย geographic label ใน prompt ซึ่งเป็น **การแทรกแซงเชิงวัฒนธรรมที่อ่อนที่สุด
เท่าที่ทำได้** เพราะเปลี่ยนเพียงข้อความนำเข้าโดยไม่แตะตัวโมเดล

โครงงานนี้ทดสอบการแทรกแซงที่แรงกว่านั้นมาก คือ **การจูนน้ำหนักของโมเดลด้วยภาษาและข้อมูลไทย**
ซึ่งเป็นสิ่งที่ผู้ใช้งาน GABM ในบริบทไทยน่าจะเลือกทำเป็นอันดับแรก และคำตอบที่ได้คือ **ยังไม่เพียงพอ**

หลักฐานสามชั้นสนับสนุนข้อสรุปนี้ ชั้นแรกคือผลของการจูนกลับเครื่องหมายระหว่างสองตระกูล (−0.179 เทียบ +0.028)
ซึ่งหมายความว่า *สิ่งที่กำหนดพฤติกรรมคือปฏิสัมพันธ์ระหว่างโมเดลฐานกับข้อมูลที่ใช้จูน ไม่ใช่การมีอยู่ของการจูน*
ชั้นที่สองคือ `seallm7b` ซึ่งจูนทั้งภูมิภาคเอเชียตะวันออกเฉียงใต้ กลับอยู่ในกลุ่มเดียวกับโมเดลฐานทั้งสองตัว
แสดงว่าการจูนภาษาในภูมิภาคโดยทั่วไปก็ไม่ได้ให้ผลแบบเดียวกับการจูนภาษาไทยในตระกูล Llama ชั้นที่สามคือ
ไม่มีโมเดลใดเขียนเหตุผลเป็นภาษาไทยเลย ซึ่งแสดงว่าสิ่งที่การจูนเปลี่ยนไม่ใช่ความสามารถทางภาษาที่สังเกตได้
แต่เป็น behavioral prior ที่ซ่อนอยู่

**ข้อสรุปที่ขยายจากงานของ Ferencz et al.** จากเดิมที่ว่า *"ป้ายกำกับประเทศไม่พอ"* เป็น
***"การแทรกแซงเชิงวัฒนธรรมแม้ในระดับน้ำหนักโมเดลก็ยังไม่รับประกัน cultural validity"***
สำหรับผู้ที่จะใช้ GABM จำลองประชากรนอกบริบทตะวันตก นัยเชิงปฏิบัติคือการเลือกโมเดลที่จูนภาษาท้องถิ่น
**ไม่สามารถใช้แทนการตรวจสอบ validity ได้** และต้องรายงานผลจากหลายโมเดลเสมอ

ข้อสังเกตเพิ่มเติมที่สอดคล้องกับประเด็น internal validity ของ Ferencz et al. คือช่วงของ attack rate
ในเงื่อนไข C กว้างถึง 0.640–0.858 เพียงจากการเปลี่ยนโมเดล ซึ่งกว้างกว่าผลของการมีหรือไม่มีชั้นผู้นำ
ในบางโมเดลเสียอีก **การเลือก LLM จึงเป็นการตัดสินใจเชิงแบบจำลองที่สำคัญไม่น้อยกว่าการเลือกโครงสร้าง
ของแบบจำลองเอง**

## 6.2 ต่อยอดจาก Aoki & Ghaffarzadegan — policy inertia ในรูปแบบอิ่มตัว

Aoki & Ghaffarzadegan (2026) รายงานจาก regression ว่านโยบายสัปดาห์ก่อนเป็นตัวทำนายระดับมาตรการ
ที่แรงที่สุด (p<0.001) ซึ่งบ่งชี้ policy inertia ที่สูงมาก ผลของโครงงานนี้เป็น **กรณีอิ่มตัวของปรากฏการณ์
เดียวกัน** คือนโยบายไม่เปลี่ยนเลยตลอด 25 จาก 26 สัปดาห์ในเกือบทุกรัน แม้ยอดผู้ป่วยจะขึ้นถึง 986 ต่อแสน
ต่อวันก็ตาม

สิ่งที่โครงงานนี้เพิ่มเข้ามาคือการแยกให้เห็นว่า inertia นี้ **ไม่ได้เกิดจากการอ่านข้อมูลไม่ออก** เพราะเหตุผล
ที่โมเดลเขียนกำกับรายงานทั้งระดับ แนวโน้ม และสัดส่วนคนออกไปทำงานได้ถูกต้องทุกสัปดาห์ สิ่งที่เกิดขึ้น
จึงเป็น **การแยกขาดระหว่างการให้เหตุผลกับการกระทำ (dissociation)** คือโมเดลสรุปสถานการณ์ได้ถูก
แต่ไม่แปลงข้อสรุปนั้นเป็นการเลือกที่ต่างออกไป ซึ่งเป็นรูปแบบความล้มเหลวที่ชี้เป้าได้ชัดกว่าการสรุปว่า
"โมเดลตัดสินใจไม่ดี"

ความแตกต่างเชิงการออกแบบที่สำคัญคือ **ประชาชนในโครงงานนี้เป็น LLM agent ด้วย** ขณะที่ในงานของ
Aoki & Ghaffarzadegan ประชาชนเป็นสมการ `b = 1/(1 + k·C)` การที่ผู้นำทุกโมเดลตัดสินใจเหมือนกัน
แทบทั้งหมดจึงทำให้เราสรุปได้ว่า **ความต่างของผลในเงื่อนไข D ที่กว้างถึง 0.268–0.723 มาจากประชาชน
ทั้งหมด ไม่ได้มาจากผู้นำ** ซึ่งเป็นการแยกส่วนที่งานของเขาทำไม่ได้โดยโครงสร้าง

ที่สำคัญกว่านั้นคืองานของเขาเสนอทางแก้ไว้แล้ว **knowledge intervention** ซึ่งเป็นข้อความราว 200 คำ
ที่อธิบาย feedback loop ของการระบาดให้ agent ฟัง และให้ผลลด cumulative cases ลงหนึ่งในสาม
dissociation ที่เราพบน่าจะตอบสนองต่อการแทรกแซงแบบเดียวกัน เพราะปัญหาไม่ใช่ว่าโมเดลไม่เห็นตัวเลข
แต่คือโมเดลไม่เชื่อมตัวเลขกับผลที่จะตามมา การทดสอบข้อนี้เป็นงานถัดไปที่ชัดเจนที่สุด

ข้อสังเกตที่สอดคล้องอีกข้อคือ Aoki & Ghaffarzadegan พบว่าความรุนแรงที่ระลึกได้มี coefficient ติดลบ
ซึ่งพวกเขาตีความว่าเป็น adaptation หรือ normalization ในข้อมูลของเรา เหตุผลของผู้นำเปลี่ยนจาก
"Rising cases, need to slow spread" ไปเป็น "Cases stable; encourage remote work" เมื่อการระบาด
ขึ้นถึงที่ราบสูง **ทั้งที่ระดับสัมบูรณ์สูงมาก** การที่โมเดลตอบสนองต่อ *อนุพันธ์* มากกว่า *ระดับ*
จึงเป็นคำอธิบายที่เป็นไปได้ของทั้งสองงาน

## 6.3 ต่อยอดจาก Williams et al. — พฤติกรรม endogenous ไม่ได้แปลว่าการระบาดเบาลงเสมอ

Williams et al. (2023) แสดงว่าการให้พฤติกรรมตอบสนองต่อข้อมูลสุขภาพและข้อมูลชุมชนทำให้เส้นการระบาด
เปลี่ยนไปจาก baseline โครงงานนี้พบสิ่งที่ต้องอภิปรายอย่างระมัดระวัง คือ **สี่ในห้าโมเดลให้การระบาด
*รุนแรงกว่า* เงื่อนไข A ที่ไม่มีการตอบสนองเชิงพฤติกรรมเลย** โดยมี q̄_out ระหว่าง 1.103 ถึง 1.280

มีสองการตีความที่เป็นไปได้ และข้อมูลที่มีอยู่ยังไม่พอจะชี้ขาดระหว่างสองข้อนี้ **การตีความแรก** คือนี่เป็น
ผลการทดลองที่มีความหมาย กล่าวคือ LLM ประเมินแรงกดดันทางเศรษฐกิจของ persona สูงกว่าที่สมมติไว้
ใน `baseline_mix` โมเดลเหล่านี้จึงจำลอง "คนที่หยุดงานไม่ได้" ได้สมจริง แต่ไม่จำลองการลดกิจกรรม
โดยสมัครใจ ซึ่งสอดคล้องกับผลในหัวข้อ 5.4 ที่พบว่ากรอบ "รายได้" ครอบงำเหตุผลถึง 54–65%
ในสี่โมเดลนั้น **การตีความที่สอง** คือเป็น artefact ของ `baseline_mix.work_onsite = 0.55`
ซึ่งเป็นค่าที่ตั้งขึ้นโดยไม่มีแหล่งอ้างอิง หัวข้อ 5.9 ทดสอบข้อนี้โดยตรง

ไม่ว่าผลจะออกทางใด บทเรียนเชิงวิธีวิทยาก็เหมือนกัน คือ **การวัดว่า "พฤติกรรมเปลี่ยนการระบาดหรือไม่"
ต้องมี baseline ของพฤติกรรมในวันปกติที่มีแหล่งอ้างอิง** มิฉะนั้นตัวเลข q_out จะตีความไม่ได้เลย
ซึ่งเป็นข้อกำหนดที่งาน GABM ที่ทบทวนมาทั้งสามชิ้นไม่ได้ระบุไว้ชัดเจน

## 6.4 บทเรียนเชิงปฏิบัติสำหรับงาน GABM นอกบริบทตะวันตก

1. **ต้องทดสอบหลายโมเดลเสมอ และควรจัดให้เป็น factorial ไม่ใช่เลือกมาเปรียบเทียบลอย ๆ**
   เพราะการเปรียบเทียบโมเดลที่จูนกับไม่จูนมักข้ามตระกูลไปพร้อมกัน ทำให้แยกสองปัจจัยไม่ออก
2. **ต้องตรวจ position bias ในชุดตัวเลือก** ซึ่งเป็นการทดสอบที่ราคาถูกมาก (รันเพิ่มสองลำดับ) แต่เปลี่ยน
   ความหมายของตัวเลขที่รายงานได้ทั้งหมด งานที่ทบทวนทั้งสามชิ้นไม่ได้รายงานการทดสอบนี้
3. **ต้องดูความหลากหลายของเหตุผล ไม่ใช่ดูแค่ผลลัพธ์รวม** เพราะ reason collapse ที่พบในตระกูล Qwen
   มองไม่เห็นเลยจาก attack rate แต่เป็นสัญญาณชัดว่าโมเดลไม่ได้ประเมินสถานการณ์ใหม่จริง
4. **ต้องแยกการอ่านข้อมูลออกจากการกระทำเมื่อประเมิน agent ที่ตัดสินใจเชิงนโยบาย** เพราะ agent
   อาจสรุปสถานการณ์ได้ถูกต้องสมบูรณ์แล้วยังเลือกเหมือนเดิม ซึ่งการดูเฉพาะผลลัพธ์จะตีความผิดเป็น
   "ชั้นผู้นำได้ผลดี"

# 7. ข้อจำกัด

เรียงตามความร้ายแรงต่อการตีความผล

1. **ผู้นำไม่แปลงการอ่านสถานการณ์เป็นการกระทำ** `strict` ถูกใช้ 4 ครั้งจาก 390 และอยู่ในรันที่มียอดเคส
   สูงสุดต่ำที่สุดของโมเดลนั้น ผลของเงื่อนไข D จึงเทียบเท่านโยบายคงที่ ไม่ใช่นโยบายที่ปรับตามสถานการณ์
   และไม่ควรตีความว่า "ชั้นผู้นำ LLM มีประสิทธิผล"
2. **`contacts.baseline_mix` เป็น assumption ที่ไม่มีแหล่งอ้างอิง** และข้อสังเกตที่ว่าเงื่อนไข C รุนแรงกว่า A
   ขึ้นกับพารามิเตอร์นี้โดยตรง _[ความร้ายแรงขึ้นกับผลในหัวข้อ 5.9]_
3. **สัดส่วนกิจกรรมรายตัวไม่คงทนต่อลำดับตัวเลือกใน prompt** โดย `essential_errand` ของ `qwen7b`
   แกว่งระหว่าง 0.000 ถึง 0.681 ข้อสรุปเชิงเปรียบเทียบระหว่างโมเดลยังใช้ได้เพราะควบคุมลำดับให้เหมือนกัน
   แต่ตัวเลขสัดส่วนเดี่ยว ๆ ใช้อ้างไม่ได้
4. **กรอบเวลา 180 วันไม่เพียงพอสำหรับโมเดลที่ระบาดช้า** เงื่อนไข D ของ `typhoon8b` มี peak ที่วันที่ 166
   และวันสุดท้ายยังมีผู้ติดเชื้อ 2.1% ของประชากร ตัวเลขที่รายงานทั้งหมดจึงเป็น *attack rate สะสม 180 วัน*
   ไม่ใช่ขนาดการระบาดสุดท้าย _[บรรเทาด้วยผลในหัวข้อ 5.10]_
5. **ขนาดครัวเรือนไม่ได้เข้าสู่แบบจำลอง** ค่า `household_size` ถูกบอกแก่ agent เป็นข้อความใน persona
   แต่ไม่ได้ถูกใช้คำนวณการสัมผัสในครัวเรือน เพราะ `w_home` เป็นค่าเดียวกันทั้งประชากร เป็นช่องว่างเชิง
   วิธีวิทยาที่ควรแก้ในเวอร์ชันถัดไปโดยให้ `w_home` แปรตามขนาดครัวเรือนจริงจาก Digital Census 2568
6. **การวิเคราะห์ความไวเป็นแบบ one-at-a-time** จึงจับปฏิสัมพันธ์ระหว่างพารามิเตอร์ไม่ได้ การทำให้ครบ
   ต้องใช้วิธีเชิง variance เช่น Sobol ซึ่งต้องรันหลายร้อยครั้งและเกินงบประมาณการคำนวณของโครงงาน
   นอกจากนี้การกระจายงบ GPU ทำให้ความครอบคลุมไม่เท่ากันระหว่างโมเดล _[รายละเอียดในหัวข้อ 5.8]_
7. **18 จาก 28 พารามิเตอร์มีสถานะ `assumption`** มีเพียง 5 ตัวที่มีสถานะ `data` ซึ่งเป็นเหตุผลหลัก
   ที่งานนี้ต้องถือเป็น scenario study ไม่ใช่การพยากรณ์
8. **3 seeds ต่อเงื่อนไข** ค่า SD ที่ต่ำมาก (0.001–0.030) มาจากประชากร N = 1,000,000 ซึ่งกลบ
   ความผันผวนเชิงสุ่มของ SEIR ไม่ได้หมายความว่า LLM ให้คำตอบเหมือนกันทุกครั้ง
9. **40 agents แทนประชากรหนึ่งล้านคน** เป็นการ scale ที่ต้องอธิบายประกอบเสมอ และข้อสรุปจำกัดอยู่กับ
   โมเดลขนาด 7–8B ที่ quantize แบบ 4-bit เท่านั้น การ quantize อาจกระทบพฤติกรรมในทางที่ไม่ได้วัด
10. **เป็น scenario study ไม่ใช่ forecast ที่ calibrate** การเทียบกับโลกจริงเป็นเชิงคุณภาพเท่านั้น
    เช่นเดียวกับงานทั้งสามชิ้นที่ทบทวนมา
