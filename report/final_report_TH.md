## บทคัดย่อ

งานจำลองโรคระบาดด้วย generative agent (GABM) ที่ใช้ LLM เป็นผู้ตัดสินใจกำลังขยายตัวอย่างรวดเร็ว แต่เกือบทั้งหมดพัฒนาและตรวจสอบในบริบทตะวันตก เมื่อจะนำมาใช้กับประชากรไทย ทางเลือกที่ดูเป็นธรรมชาติที่สุดคือเปลี่ยนไปใช้โมเดลที่จูนด้วยภาษาและข้อมูลไทย งานนี้ทดสอบว่าทางเลือกนั้นได้ผลหรือไม่

เราสร้างแบบจำลอง SEIR ของจังหวัดสังเคราะห์ในประเทศไทย (N = 1,000,000, R₀ = 2.0) ที่มี LLM agent จำนวน 40 ตัวเลือกกิจกรรมรายวันจากสี่ตัวเลือก การเลือกนั้นถูกแปลงเป็นอัตราการสัมผัสผ่านเมทริกซ์การสัมผัสของประเทศไทยจาก Prem et al. (2021) การออกแบบเป็นแผงโมเดลแบบ **2×2** (ตระกูลโมเดล × การจูนภาษา) ซึ่งแยกสองปัจจัยที่งานก่อนหน้าปะปนกัน แผงประกอบด้วย `llama8b`/`typhoon8b` และ `qwen7b`/`openthaigpt7b` พร้อมตัวควบคุมระดับภูมิภาค `seallm7b` ทดสอบใน 4 เงื่อนไข ตั้งแต่ SEIR ล้วนไปจนถึงเงื่อนไขที่มีผู้นำ LLM กำหนดนโยบายรายสัปดาห์ รวมการตัดสินใจ 410,400 ครั้ง

ผลหลักคือการจูนภาษาไทยกลับเครื่องหมายระหว่างสองตระกูล ในตระกูล Llama การจูนลด attack rate สะสม 180 วันลง 0.181 แต่ในตระกูล Qwen กลับเพิ่มขึ้น 0.027 ในเงื่อนไขที่มีผู้นำ ผลทั้งสองเป็น −0.344 และ +0.056 ตามลำดับ ทั้งสี่ผลให้ p = 0.0022 จาก exact permutation test ที่ 6 seeds ซึ่งเป็นค่าต่ำสุดที่การออกแบบนี้ให้ได้ ค่า p จึงสะท้อนจำนวน seed และต้องอ่านคู่กับขนาดของผล ตัวควบคุมระดับภูมิภาคอยู่ในกลุ่มเดียวกับโมเดลฐาน

การวิเคราะห์เหตุผล 36,000 รายการชี้กลไกที่ตรงกับเครื่องหมายของผล การจูนลดการอ้างกรอบ "รายได้" จาก 54% เหลือ 19% ในตระกูลหนึ่ง แต่เพิ่มจาก 56% เป็น 65% ในอีกตระกูลหนึ่ง ผู้นำ LLM รายงานสถานการณ์ได้ถูกต้องทุกสัปดาห์แต่แทบไม่เปลี่ยนนโยบาย โดยเลือกระดับเข้มงวดสูงสุดเพียง 5 ครั้งจาก 702 ครั้ง ซึ่งเป็นการแยกขาดระหว่างการให้เหตุผลกับการกระทำ

ข้อสรุปนี้คงทนต่อการสลับลำดับตัวเลือกใน prompt สามแบบ ต่อการกวาดพารามิเตอร์การสัมผัส (ขยับผลได้มากที่สุด 0.025 เทียบกับขนาดของผลที่ 0.181) และต่อการเปลี่ยนสมมติฐานพฤติกรรมวันปกติ นัยเชิงปฏิบัติคือการเลือกโมเดลที่จูนภาษาท้องถิ่นไม่สามารถใช้แทนการตรวจสอบความสมเหตุสมผลได้ เพราะเพียงการเปลี่ยนโมเดลก็ทำให้ attack rate เคลื่อนในช่วง 0.638–0.859 ซึ่งกว้างกว่าผลของการเปลี่ยนโครงสร้างแบบจำลองในหลายกรณี

# 1. บทนำ

## 1.1 ที่มาและความสำคัญ

แบบจำลองโรคระบาดเชิงกลไกอย่าง SEIR อธิบายการแพร่เชื้อได้ดี แต่จัดการกับพฤติกรรมมนุษย์ได้ไม่ดีนัก ทั้งที่พฤติกรรมเป็นตัวกำหนดเส้นทางการระบาดโดยตรง Williams et al. (2023) ชี้ว่าแม้ modeler จะยอมรับความสำคัญของพฤติกรรม แต่งานที่ ground กับข้อมูลจริงส่วนใหญ่ยังป้อนพฤติกรรมเข้ามาแบบ exogenous คือใช้อนุกรมเวลาของการเดินทางหรือฤดูกาลเป็นข้อมูลนำเข้า มีเพียงส่วนน้อยที่กำหนดพฤติกรรมแบบ endogenous ให้ตอบสนองต่อสถานะของโรคที่กำลังดำเนินอยู่ การขาด endogenous formulation นี้ทำให้เกิดความเอนเอียงในการพยากรณ์ระยะยาว เพราะแบบจำลองไม่สามารถจับได้ว่าประชาชนจะปรับตัวอย่างไรเมื่อสถานการณ์เปลี่ยน

อุปสรรคที่ทำให้แก้ปัญหานี้ยากมีสี่ประการ ประการแรก พฤติกรรมมนุษย์ซับซ้อนและหลากหลายข้ามบุคคล ชุมชน และวัฒนธรรม ประการที่สอง ยังไม่มีทฤษฎีที่ผ่านการ validate ว่ามนุษย์เปลี่ยนพฤติกรรมอย่างไรเมื่อเผชิญโรคระบาด ประการที่สาม ความร่วมมือกับนักสังคมศาสตร์และพฤติกรรมศาสตร์ยังจำกัด ประการที่สี่ การได้ข้อมูลพฤติกรรมที่เชื่อถือได้เพื่อ validate กลไกทำได้ยาก

การมาถึงของ Large Language Model เปิดทางให้แก้อุปสรรคสองข้อแรกได้บางส่วน แนวทาง **Generative Agent-Based Modeling (GABM)** ใช้ LLM เป็นตัวแทนของมนุษย์ที่ตัดสินใจเองในแต่ละวัน โดย modeler ไม่ต้องเขียนกฎการตัดสินใจลงไปล่วงหน้า พฤติกรรมจึงเป็น endogenous โดยธรรมชาติ

## 1.2 ปัญหาที่ยังเปิดอยู่: พฤติกรรมที่เห็นเป็นของใคร

แนวทางนี้เปิดคำถามใหม่ Ferencz et al. (2026) ตั้งคำถามตรง ๆ ว่าพฤติกรรมที่ LLM agent แสดงออกมานั้นเป็นของใคร คือเป็นการจำลองมนุษย์จริง หรือเป็นเพียง *behavioral prior* ที่ติดมากับโมเดลแต่ละตัวจากข้อมูลฝึกและกระบวนการ alignment

คำถามนี้มีสองระดับ ระดับ internal validity คือถ้าเปลี่ยน LLM แล้วผลการระบาดเปลี่ยน ข้อสรุปเชิงนโยบายที่ได้ก็ไม่มีความหมาย ระดับ cultural validity คือสมมติฐานที่นักวิจัยจำนวนมากใช้โดยไม่ตรวจสอบ ว่า *"บอก LLM ว่า agent เป็นคนประเทศ X แล้วจะได้พฤติกรรมแบบประเทศ X"*

ปัญหา cultural validity เด่นชัดเป็นพิเศษนอกบริบทตะวันตก เพราะ LLM ส่วนใหญ่ฝึกด้วยข้อมูลภาษาอังกฤษเป็นหลัก ถ้าจะใช้ GABM จำลองประชากรไทย ทางแก้ที่ดูเป็นธรรมชาติที่สุดคือเลือกใช้โมเดลที่จูนด้วยภาษาไทย การแทรกแซงนี้แรงกว่าการใส่ป้ายกำกับประเทศลงใน prompt อย่างมาก เพราะเปลี่ยนน้ำหนักของโมเดลเอง

ยังไม่มีงานใดทดสอบว่าวิธีนี้ได้ผลจริงหรือไม่ ในเชิงการออกแบบ การเปรียบเทียบโมเดลที่จูนไทยกับโมเดลที่ไม่จูนมักข้ามตระกูลไปพร้อมกัน จึงแยกไม่ออกว่าความต่างที่เห็นมาจาก *การจูนภาษา* หรือจาก *ตระกูลโมเดล*

## 1.3 คำถามวิจัย

- RQ1: การจูนภาษาไทยเปลี่ยนพฤติกรรมของ LLM agent ในแบบจำลองโรคระบาดหรือไม่ และเปลี่ยนไปในทิศทางใด เมื่อควบคุมตระกูลโมเดลแล้ว
- RQ2: ถ้าเปลี่ยน กลไกที่ทำให้เปลี่ยนคืออะไร และสามารถตรวจสอบได้จากสิ่งที่โมเดลผลิตออกมาหรือไม่
- RQ3: ผู้นำ LLM ที่ตัดสินใจเชิงนโยบายรายสัปดาห์ตอบสนองต่อสถานการณ์ระบาดที่เห็นหรือไม่

## 1.4 สิ่งที่งานนี้นำเสนอ

1. การออกแบบ 2×2 (ตระกูลโมเดล × การจูนภาษา) ซึ่งแยกสองปัจจัยที่งานก่อนหน้าปะปนกันออกจากกัน โดยใช้ `llama8b`/`typhoon8b` และ `qwen7b`/`openthaigpt7b` พร้อมตัวควบคุมระดับภูมิภาค `seallm7b`
2. หลักฐานว่าผลของการจูนภาษาไทยกลับเครื่องหมายระหว่างสองตระกูล การจูนทำให้ตระกูลหนึ่งระมัดระวังขึ้นมาก แต่ทำให้อีกตระกูลระมัดระวังน้อยลง
3. กลไกที่ตรวจสอบได้จากข้อความ การวิเคราะห์เหตุผล 36,000 รายการพบว่าการจูนเปลี่ยน *กรอบ* ที่โมเดลใช้ตีความสถานการณ์ และเปลี่ยนคนละทิศในสองตระกูล ซึ่งตรงกับเครื่องหมายของผลที่วัดได้
4. หลักฐานเชิงปริมาณว่าผู้นำ LLM แยกขาดระหว่างการให้เหตุผลกับการกระทำ โดยรายงานสถานการณ์ถูกต้องทุกสัปดาห์แต่เลือกนโยบายเดิมแทบตลอด
5. ชุดการทดสอบความคงทนที่งาน GABM ส่วนใหญ่ไม่ทำ โดยเฉพาะการสลับลำดับตัวเลือกใน prompt เพื่อแยกพฤติกรรมจริงออกจาก position bias

# 2. งานที่เกี่ยวข้อง

งานสามชิ้นที่เป็นฐานของโครงงานนี้วางคำถามต่อกันเป็นลำดับ ชิ้นแรกแสดงว่า LLM ใช้จำลองพฤติกรรมประชาชนได้ ชิ้นที่สองตั้งคำถามว่าพฤติกรรมนั้นเชื่อถือได้แค่ไหน และชิ้นที่สามย้ายความสนใจจากประชาชนไปที่ผู้กำหนดนโยบาย

## 2.1 GABM กับพฤติกรรมประชาชน — Williams et al. (2023)

งานนี้เสนอ Generative Agent-Based Model ที่ใช้ generative agents เป็น representative proxies ของมนุษย์ โดยไม่มีการบังคับกฎการตัดสินใจใด ๆ จาก modeler ซึ่งต่างจาก ABM ดั้งเดิมอย่างชัดเจน

การทดลองแบ่งเป็นสามเงื่อนไขที่เพิ่มข้อมูลป้อนกลับทีละชั้น เงื่อนไขแรกคือ *base run* ที่ agent รู้เพียง persona ของตัวเอง เงื่อนไขที่สองคือ *self-health feedback* ที่เพิ่มอาการเจ็บป่วยของตนเอง และเงื่อนไขที่สามคือ *full feedback* ที่เพิ่มข่าวยอดผู้ติดเชื้อในชุมชน implementation ใช้ Python + Mesa กับ gpt-3.5-turbo-0301 อายุ agent สุ่มแบบ uniform ในช่วง 18–64 ปี และบุคลิก Big Five ให้โอกาส 50/50 ระหว่างขั้วบวกและลบของแต่ละ trait ระยะโรคกำหนดไว้ 6 วัน โดยวันที่ 1–2 ไม่มีอาการแต่แพร่เชื้อได้ วันที่ 3 และ 6 ไอเล็กน้อย และวันที่ 4–5 มีไข้และไอ

ในเชิงวิธีวิทยา ผู้เขียนใช้ชื่อไวรัสและชื่อเมืองสมมติเพื่อเลี่ยง bias เรื่อง COVID-19 ที่ฝังอยู่ใน LLM อยู่แล้ว ประชากรทดลองมี n = 100 ในรอบแรกและ n = 1,000 ในรอบขยาย contact rate 5 และ infectivity 0.1 ให้ R₀ ≈ 3 (รอบขยายทดสอบ R₀ = 2, 2.5 และ 3 ด้วย) การวิเคราะห์ใช้ decision log รายบุคคลรายวันประมาณ 67,000 observations

ช่องว่างที่งานนี้เปิดไว้มีสามข้อ ข้อแรก การตัดสินใจเป็นทวิภาค (อยู่บ้านหรือออกไปทำงาน) ซึ่งแยกการสัมผัสจากงาน ธุระ และครัวเรือนออกจากกันไม่ได้ ข้อที่สอง งานนี้ใช้โมเดลเดียว จึงไม่ได้ตอบว่าผลขึ้นกับการเลือกโมเดลหรือไม่ ข้อที่สาม การเทียบกับโลกจริงเป็นเชิงคุณภาพเท่านั้น ไม่มีการ fit กับ epidemic curve ของประเทศใด

## 2.2 พฤติกรรมเป็นของใคร — Ferencz et al. (2026), Epi-LLM

งานนี้ใกล้เคียงกับคำถามของโครงงานนี้ที่สุด และเป็นงานที่กำหนดช่องว่างที่เราเข้าไปเติม

ผู้เขียนเสนอ Epi-LLM framework ซึ่งอ้างว่าเป็นงานแรกที่รวม LLM เข้ากับ agent-based epidemic model และ behavioural epi-game ที่เก็บจากมนุษย์จริง แบบจำลองโรคสร้างบน Starsim ใช้ SEIR ระยะ 15 วันและคำนวณการแพร่เชื้อรายชั่วโมง เครือข่ายการสัมผัสเป็น dynamic random network ที่ parameterize จาก empirical contact degree distribution ของ AUIB epigame โดย fit ด้วย log-normal ส่วน agent เลือกกักตัวหรือไม่แบบทวิภาครายวันภายใต้ economic trade-off ที่เป็นตัวเลขจริง คือได้ 5 แต้มถ้ากักตัวเทียบกับ 10–15 แต้มถ้าออกไปใช้ชีวิต นอกจากนี้ agent ถูก initialize ด้วย health beliefs สี่มิติจาก Health Belief Model ที่ดึงค่ามาจากคำตอบ survey ของมนุษย์จริงในการศึกษา AUIB epigame ที่ American University of Iraq-Baghdad

การเปรียบเทียบโมเดลออกแบบมาอย่างรัดกุม ผู้เขียนทดสอบ 4 โมเดลคือ DeepSeek V3, Llama 3 70B, Nemotron 120B และ GPT-OSS 120B ซึ่งครอบคลุมสองตระกูลสถาปัตยกรรม (dense transformer และ Mixture-of-Experts) ที่สเกล 70B–120B เพื่อแยกผลของสถาปัตยกรรมออกจากผลของขนาดโมเดล ตรรกะนี้เป็นตรรกะเดียวกับที่โครงงานนี้ใช้แยกการจูนภาษาออกจากตระกูลโมเดล

ส่วนที่เกี่ยวข้องกับเราโดยตรงที่สุดคือ geographic label experiment ซึ่งกำหนดให้ agent อยู่ที่ China, Iraq, Kenya หรือ UK อันเป็นสี่ภูมิภาคที่มีบรรทัดฐานการปฏิบัติตามมาตรการและบริบทการกำกับดูแลสาธารณสุขต่างกันอย่างชัดเจน การทดลองนี้ทดสอบสมมติฐานว่าป้ายกำกับประเทศเพียงอย่างเดียวให้พฤติกรรมตามประเทศนั้นหรือไม่

ช่องว่างที่เหลือไว้คือ การใส่ป้ายกำกับประเทศลงใน prompt เป็นการแทรกแซงเชิงวัฒนธรรมที่อ่อนที่สุดเท่าที่ทำได้ เพราะเปลี่ยนแค่ข้อความนำเข้าโดยไม่แตะโมเดล ยังไม่มีงานใดทดสอบการแทรกแซงที่แรงกว่านั้น คือการจูนน้ำหนักโมเดลด้วยภาษาและข้อมูลท้องถิ่น ว่าจะให้ cultural validity ได้หรือไม่ โครงงานนี้เข้าไปเติมช่องว่างนั้นโดยตรง

## 2.3 ผู้นำ LLM และ policy inertia — Aoki & Ghaffarzadegan (2026)

งาน GABM ก่อนหน้าเน้นพฤติกรรมของประชาชน แต่ในความเป็นจริง การตัดสินใจเชิงนโยบายซ้ำ ๆ ของผู้บริหารก็เป็นปัจจัยหลักเช่นกัน การตัดสินใจนี้เกิดภายใต้ feedback ที่ซับซ้อน ซึ่งเป็นสถานการณ์ที่มนุษย์มักทำได้แย่เมื่อระบบมี delay และ feedback loop คำถามของงานนี้คือ AI agent จะทำได้ดีแค่ไหน และอะไรทำให้ทำได้ดีขึ้น

ผู้เขียนสร้าง generative AI agent สวมบทบาทนายกเทศมนตรีชื่อ Jennifer ที่ฝังอยู่ใน SEIR environment ประชากร 1 ล้านคน β₀ = 0.2 ต่อวัน ระยะฟักตัว 4 วัน และระยะแพร่เชื้อ 10 วัน โครงงานนี้รับพารามิเตอร์โรคชุดนี้มาใช้ทั้งหมดเพื่อให้เปรียบเทียบกันได้

อัตราการแพร่ถูกแตกองค์ประกอบเป็น β = β₀ · b · g · ε โดย b คือการปรับพฤติกรรมโดยสมัครใจ g คือมาตรการรัฐในช่วง 0–1 และ ε คือสัญญาณรบกวนรายวัน โดย α = 0.8 หมายความว่ามาตรการเข้มสุดลดการแพร่ได้ 80% การทดลองแบ่งเป็น World 1 ที่นโยบายเป็นตัวแปรเดียว (b = 1) และ World 2 ที่เพิ่มพฤติกรรมสมัครใจ b = 1/(1 + k·C₍t−1₎) ซึ่งให้ยอดผู้ป่วยที่ล่าช้ามีผลต่อพฤติกรรมป้องกัน เงื่อนไข B ของโครงงานนี้รับสูตรดังกล่าวมาใช้โดยตรง

agent เลือกระดับการปิดกิจการ 0–100% ทุก 7 วัน จำลอง 365 วัน และเริ่มตัดสินใจในสัปดาห์ที่ 6 ความจำใช้ recency-weighted stochastic retrieval โดยเก็บ tuple ของสัปดาห์ ระดับมาตรการ และยอดจริง แล้วสุ่มดึง 5 เหตุการณ์ด้วยน้ำหนัก exp(0.1(i−n)) LLM ที่ใช้คือ GPT-5 nano ผ่าน OpenAI API ที่ temperature 1.0 ใช้ราว 520 API calls ต่อ ensemble run การออกแบบเป็น 2×4 คือสอง world คูณสี่ configuration (Base, Knowledge, Ensemble 10 agents และ Ensemble + Knowledge) โดย knowledge intervention คือข้อความประมาณ 200 คำที่อธิบาย feedback loop ของการระบาดให้ agent ฟัง

ผลใน World 1 เทียบกับ base คือ knowledge ลด cumulative cases ลงหนึ่งในสาม ensemble เพียงอย่างเดียวกลับทำให้แย่ลงหนึ่งในสาม และ ensemble + knowledge ลดลงครึ่งหนึ่ง ส่วนใน World 2 ความต่างระหว่างเงื่อนไขบีบแคบลงเพราะพฤติกรรมสมัครใจกดการแพร่อยู่แล้ว

ผลจาก regression ของการตัดสินใจเกี่ยวข้องกับเรามากที่สุด ยอดผู้ป่วยสัปดาห์ก่อนทำนายทั้งการพยากรณ์ (p<0.001) และระดับมาตรการ (p<0.01) แต่นโยบายสัปดาห์ก่อนเป็นตัวทำนายที่แรงที่สุด (p<0.001) ซึ่งบ่งชี้ policy inertia ที่สูงมาก ส่วนความรุนแรงที่ระลึกได้จากความจำมี coefficient ติดลบ (p<0.001) ซึ่งบ่งชี้ adaptation หรือ normalization ต่อสถานการณ์เลวร้าย

ข้อสรุปของผู้เขียนคือ AI-assisted policymaking ที่ได้ผลต้องเป็นการผสาน AI เข้ากับโครงสร้างความรู้เชิงโดเมนที่ scaffold การให้เหตุผลเชิงสาเหตุ ไม่ใช่การปล่อยความสามารถดิบของโมเดล ผู้เขียนยอมรับข้อจำกัดว่า SEIR ที่ใช้ไม่มี spatial heterogeneity, age structure, healthcare capacity หรือ economic feedback และ agent ได้ข้อมูลผู้ป่วยรายสัปดาห์ที่สมบูรณ์แบบ ต่างจากผู้กำหนดนโยบายจริงที่เผชิญ reporting delay และ measurement error

ช่องว่างที่เหลือไว้คือ ประชาชนในงานนี้ไม่ใช่ LLM agent แต่เป็นสมการ `b = 1/(1 + k·C)` จึงแยกไม่ได้ว่าผลลัพธ์ที่ได้มาจากผู้นำหรือจากประชาชนคนละเท่าไร

## 3.1 สถาปัตยกรรมโดยรวม

ระบบปิด feedback loop ระหว่างสองส่วนที่แยกจากกันอย่างชัดเจน คือส่วนที่ตัดสินใจ (LLM) กับส่วนที่คำนวณการแพร่เชื้อ (SEIR) โดยสื่อสารกันผ่านตัวเลขเดียวคือ **contact modifier**

```
ประชาชน (LLM) เลือกกิจกรรม ── สัดส่วน action ──► ContactModel แปลงเป็น q_out
        ▲                                                   │
        │ สถานการณ์เมื่อวาน (ยอดเคส, มาตรการ, อาการตัวเอง)      ▼
   SEIR (รายวัน) ◄──────────── beta_eff = f(q_out, นโยบาย) ───┘
        ▲
   ผู้นำ (LLM) เลือกระดับมาตรการทุก 7 วัน  (เฉพาะเงื่อนไข D)
```

การแยกนี้ทำให้ตรวจสอบได้ว่าความต่างระหว่างโมเดลมาจากพฤติกรรมล้วน ๆ ไม่ใช่จากการที่ LLM ไปแตะ state ของโรคโดยตรง โครงสร้างโค้ดแบ่งเป็นแพ็กเกจ `gabm/` ที่มีโมดูล `seir.py` (กลไกโรค), `contacts.py` (การแปลง action เป็นการสัมผัส), `llm.py` (backend และการตรวจความถูกต้องของคำตอบ), `policy.py` (เงื่อนไข B และผู้นำ), `sim.py` (daily loop), `agents.py`, `io.py` และ `analysis.py`

## 3.2 กลไกโรค

SEIR เชิงกลไกเดินทีละวันด้วย `solve_ivp` พร้อมตรวจการอนุรักษ์ S + E + I + R = N ทุกวัน พารามิเตอร์รับมาจาก Aoki & Ghaffarzadegan (2026) ทั้งชุด ได้แก่ ประชากร N = 1,000,000, β₀ = 0.2 ต่อวัน, ระยะฟักตัว 4 วัน และระยะแพร่เชื้อ 10 วัน จึงได้ R₀ = β₀ × infectious_days = 2.0 สัดส่วนผู้มีอาการคือ 0.7 และการระบาดเริ่มต้นด้วยผู้ติดเชื้อระยะฟักตัวและระยะแพร่เชื้ออย่างละ 0.2% ของประชากร

## 3.3 การแปลงพฤติกรรมเป็นการสัมผัส

การขยายจาก action ทวิภาคเป็นสี่ทางเลือกจะมีความหมายก็ต่อเมื่อแต่ละทางเลือกแปลงเป็นระดับการสัมผัสที่ตรวจสอบได้ หัวข้อนี้จึงแสดงการแปลงทั้งหมดอย่างครบถ้วน ระดับการสัมผัสต่อ action มาจากเมทริกซ์การสัมผัสตามสถานที่ของไทยใน Prem et al. (2021) คอลัมน์ `adult_20_64` ซึ่งให้ค่า home 4.98, work 3.857, school 0.037 และ others 5.147 คนต่อวัน

```python
# gabm/contacts.py
work_per_worker = (loc["work"] + loc["school"]) / p["employment_rate"]   # 3.894 / 0.67 = 5.812
self.c_out = {
    "stay_home":        0.0,
    "work_onsite":      work_per_worker + p["f_work_other"] * loc["others"],
    "essential_errand": p["f_errand"]  * loc["others"],
    "visit_family":     p["f_visit"]   * loc["others"] + p["f_visit_home"] * self.home,
}
self.base_out = sum(self.baseline_mix[a] * self.c_out[a] for a in self.actions)
self.w_home   = self.home / (self.home + self.base_out)

def beta_eff(self, beta0, q_out, q_policy=1.0):
    return beta0 * (self.w_home + (1 - self.w_home) * q_out * q_policy)
```

การหารด้วย `employment_rate` = 0.67 เป็นการแปลงการสัมผัสที่ทำงานซึ่งเฉลี่ยทั้งประชากร ให้เป็นการสัมผัสต่อ *ผู้ที่ไปทำงานจริง* เพราะ action นี้ถูกเลือกเฉพาะโดย agent ที่ออกไปทำงาน

ค่าที่ได้จากคอนฟิกหลักคือ `base_out` = 4.835 และ `w_home` = 0.507 ระดับการสัมผัสสัมพัทธ์คำนวณจาก `(1 − w_home)·(c_out / base_out) + w_home` ได้ผลดังตาราง

| action | c_out (คนต่อวัน) | การสัมผัสสัมพัทธ์ |
|---|---|---|
| `work_onsite` | 7.356 | 1.257 |
| `visit_family` | 4.034 | 0.918 |
| `essential_errand` | 2.573 | 0.770 |
| `stay_home` | 0 | 0.507 |

`stay_home` ไม่เท่ากับการสัมผัสเป็นศูนย์ เพราะการสัมผัสในครัวเรือนถูกเก็บไว้เสมอ ซึ่งต่างจาก action แบบทวิภาคของ Williams et al. และ Epi-LLM ที่การอยู่บ้านมักหมายถึงการตัดการสัมผัสทิ้ง ค่า `w_home` = 0.507 หมายความว่าครึ่งหนึ่งของการสัมผัสทั้งหมดเกิดในบ้านและไม่ขึ้นกับการตัดสินใจรายวัน จึงเป็นเพดานบนของสิ่งที่พฤติกรรมจะเปลี่ยนได้

ค่า `q_out` คือค่าเฉลี่ยถ่วงน้ำหนักของการสัมผัสสัมพัทธ์ตามสัดส่วนที่ agent เลือกจริงในวันนั้น โดยนิยามแล้วประชากรฐานที่เลือกตาม `baseline_mix` จะให้ `q_out` = 1 พอดี ดังนั้น `q_out` > 1 หมายถึง agent ออกนอกบ้านมากกว่าวันปกติ

## 3.4 ประชากรสังเคราะห์และ persona

สร้าง 40 persona จาก marginal distribution ที่กำหนดใน `config/base.yaml` ด้วย `persona_seed` คงที่ แบ่งเป็นหกกลุ่มอาชีพ ได้แก่ เกษตร/ประมง 11 คน, ค้าขาย/บริการ 8 คน, การผลิต/ก่อสร้าง 7 คน, ไม่ได้ทำงาน 6 คน, พนักงานออฟฟิศ 5 คน และภาครัฐ 3 คน แต่ละ persona มีคุณลักษณะที่เข้าไปอยู่ใน prompt โดยตรง ได้แก่ กลุ่มอายุ อาชีพ ความสามารถทำงานจากบ้าน ระดับการสูญเสียรายได้ ขนาดครัวเรือน การอยู่ร่วมกับผู้สูงอายุหรือผู้ป่วยเรื้อรัง การรับรู้ความรุนแรงของโรค ความไว้วางใจข้อมูลทางการ และสถานะ essential worker

prompt ของประชาชนมีโครงสร้างดังนี้ (ตัวอย่างจริงจากวันที่ 0)

```
You are simulating the daily choice of one resident in a synthetic epidemic scenario set in a
province in Thailand. A new respiratory infection is spreading. Decide as this person would.

Resident profile:
- Age group: 40-49
- Main activity: farmer or fisher (own account)
- Can work from home: no                              ← แกน wfh_scale เปลี่ยนบรรทัดนี้
- Income loss if you do not go out to work: high
- Household size: 3 people                            ← ไม่ได้เข้าแบบจำลอง ดูหัวข้อ 7
- Lives with an elderly or chronically ill person: no
- How serious you think this disease is: medium
- Trust in official health information: high
- Your work is considered essential

Today is day 0 of the simulation.
- Your health: You feel healthy and have no symptoms.
- Newly reported cases in your province today: 0.0 per 100,000 (7-day average 0.0; trend: unknown)
- Current government measures: None. Normal activities are allowed.

Choose exactly ONE main activity for today:
- stay_home / work_onsite / essential_errand / visit_family
Reply with JSON only: {"action": "...", "reason": "<at most 15 words>"}
```

บรรทัด *Newly reported cases* เป็นช่องทางเดียวที่สถานะของโรคป้อนกลับมาถึง agent และเป็นสิ่งที่ทำให้พฤติกรรมเป็น endogenous ตามที่หัวข้อ 1.1 อธิบาย

## 3.5 การตรวจความถูกต้องของคำตอบ

ทุกโมเดลใช้ prompt เดียวกันและ schema เดียวกัน ระบบ parse คำตอบและตรวจว่า action อยู่ในชุดที่อนุญาต ถ้าผิดจะลองใหม่หนึ่งครั้ง และถ้ายังผิดจะใช้ action ของวันก่อนพร้อมติดธง `fallback` ระบบบันทึก raw output ทุกครั้งไม่ว่าจะสำเร็จหรือไม่ จึงไม่มี fallback ที่เกิดขึ้นเงียบ ๆ

## 3.6 เงื่อนไขการทดลอง

| เงื่อนไข | สิ่งที่กำหนดพฤติกรรม | q_out |
|---|---|---|
| A | ไม่มี — SEIR ล้วน | = 1 เสมอ |
| B | กฎตอบสนองต่อยอดเคส `m(t) = 1/(1 + α·cases7)` ตาม Aoki & Ghaffarzadegan | = m(t) |
| C | ประชาชนเป็น LLM 40 agents เลือก 4 ทางเลือก | จากสัดส่วน action ถ่วงน้ำหนัก |
| D | C บวกผู้นำ LLM ที่เลือกระดับมาตรการทุก 7 วัน | C บวก `q_policy` และ action ที่ถูกห้าม |

ระดับมาตรการสามระดับให้ค่า `q_policy = 1 − k·d` โดย k = 0.8 และ d เป็น 0.0 สำหรับ `open`, 0.4 สำหรับ `limited` และ 0.8 สำหรับ `strict` ซึ่งระดับสุดท้ายห้าม `visit_family` ด้วย ผู้นำไม่แตะ state ของ SEIR โดยตรงแม้แต่น้อย

เงื่อนไข D ถูกกำกับด้วย **gate** คือจะรันก็ต่อเมื่อเงื่อนไข C ของโมเดลนั้นเสร็จครบทั้งสาม seed ตามค่า `sim.seeds` ใน `config/base.yaml` และมี `fallback_rate` ต่ำกว่า 5% เพื่อไม่ให้ชั้นผู้นำถูกวางทับบนพฤติกรรมประชาชนที่ไม่น่าเชื่อถือ

# 5. ผลการทดลอง

ลำดับการนำเสนอเริ่มจากการยืนยันว่าเครื่องมือถูกต้อง แล้วจึงเสนอผลหลัก กลไกที่อธิบายผลหลัก และปิดท้ายด้วยการทดสอบความคงทน

## 5.1 การตรวจสอบแกน SEIR

เงื่อนไข A ซึ่งไม่มีการตอบสนองเชิงพฤติกรรมเลยให้ attack rate ที่วันที่ 180 เท่ากับ 0.795 แต่ที่กรอบเวลานี้การระบาดยังไม่สิ้นสุด โดยยังเหลือผู้ติดเชื้ออยู่ 0.38% ของประชากร ค่านี้จึงยังไม่ใช่ final size และนำไปเทียบกับคำตอบเชิงวิเคราะห์โดยตรงไม่ได้

เนื่องจากเงื่อนไข A ไม่เรียก LLM เลย การรันต่อจนลู่เข้าจึงไม่มีต้นทุน GPU และใช้เวลาไม่กี่วินาที ผลคือ attack rate คงที่ที่ 0.798176 ตั้งแต่วันที่ 365 เป็นต้นไป และไม่เปลี่ยนอีกที่ 730 และ 1,095 วัน (สัดส่วนผู้ติดเชื้อลดลงเหลือ 4×10⁻⁷, 5×10⁻¹⁵ และ 7×10⁻²³ ตามลำดับ)

คำตอบเชิงวิเคราะห์ที่ใช้เทียบไม่ใช่ final size ของประชากรที่อ่อนแอทั้งหมด เพราะแบบจำลองหว่านเชื้อเริ่มต้นไว้ที่ E = I = 0.002 ทำให้สัดส่วนผู้อ่อนแอตั้งต้นเป็น S₀/N = 0.996 สมการที่ตรงกับเงื่อนไขเริ่มต้นนี้คือ *s* = *s*₀·exp(−R₀(1 − *s*)) ไม่ใช่ *z* = 1 − exp(−R₀*z*)

| | attack rate |
|---|---|
| สูตร final size มาตรฐาน (ประชากรอ่อนแอทั้งหมด) | 0.796812 |
| สูตรที่ตรงกับเงื่อนไขเริ่มต้น S₀/N = 0.996 | 0.798176 |
| เงื่อนไข A ที่ลู่เข้าแล้ว (365 วันขึ้นไป) | 0.798176 |

ทั้งสองค่าตรงกันถึงทศนิยมหกตำแหน่งตั้งแต่วันที่ 365 และเมื่อปล่อยหางให้หมดจริงที่ 730 วัน (เหลือผู้ติดเชื้อ 5.4×10⁻¹⁵) ส่วนต่างสัมบูรณ์ลดเหลือ 3.8×10⁻¹³ ซึ่งอยู่ในระดับความคลาดเคลื่อนของ integrator เอง (`solve_ivp` ที่ `rtol = 1e-8`) ผลนี้แสดงว่าเงื่อนไข A ทำซ้ำ final size เชิงวิเคราะห์ของสมการที่ตรงกับเงื่อนไขเริ่มต้นได้ รายละเอียดอยู่ใน `scripts/analysis/seir_validation.py`

เงื่อนไข B ที่ใช้กฎตอบสนองของ Aoki & Ghaffarzadegan ให้ 0.469 ที่วันที่ 180 ซึ่งต่ำกว่า A อย่างชัดเจนตามที่คาด

การเปรียบเทียบระหว่างเงื่อนไขในหัวข้อถัดจากนี้ทั้งหมดใช้ค่าที่วันที่ 180 เท่ากันทุกเงื่อนไข จึงเทียบกันได้ แม้บางเงื่อนไขจะยังไม่ถึง final size ของตัวเอง ค่า 0.795 ของเงื่อนไข A ที่ใช้เป็นจุดอ้างอิงในหัวข้อ 5.3 และ 5.9 จึงเป็นค่าที่วันที่ 180 ไม่ใช่ค่าที่ลู่เข้าแล้ว ผลของการที่เงื่อนไขต่าง ๆ ยังไม่สิ้นสุดที่ 180 วันถูกตรวจแยกไว้ในหัวข้อ 5.10

## 5.2 ความน่าเชื่อถือของชั้น LLM

| เงื่อนไข | การตัดสินใจต่อโมเดล | schema ถูกตั้งแต่ครั้งแรก | fallback |
|---|---|---|---|
| C (6 seeds) | 43,200 | 99.81–100% | 0.0% |
| D (6 seeds; `seallm7b` 3 seeds) | 43,200 (`seallm7b` 21,600) | 99.86–100% | 0.0% |

จากการตัดสินใจทั้งสิ้น 410,400 ครั้ง ไม่มี fallback เกิดขึ้นแม้แต่ครั้งเดียว โมเดลที่ต่ำที่สุดคือ `seallm7b` ที่ 99.81% โดยมีการ retry 60 ครั้งในเงื่อนไข C และ 31 ครั้งในเงื่อนไข D แล้วผ่านทั้งหมด รองลงมาคือ `typhoon8b` ที่ 15 และ 17 ครั้ง ส่วนอีกสามโมเดลรวมกัน retry เพียง 2 ครั้ง และไม่มีรันใดถูกตัดกลางคัน ชั้น LLM จึงไม่ใช่แหล่งของความแปรปรวนในผลที่รายงานต่อไปนี้

## 5.3 ผลหลัก — การจูนภาษาไทยกลับเครื่องหมายระหว่างตระกูล (RQ1)

![](../outputs/figures/04_2x2_localisation.png)

*รูปที่ 1: attack rate สะสม 180 วัน จัดตามการออกแบบ 2×2 ลูกศรแสดงทิศและขนาดของผลการจูนภาษา เส้นประคือเงื่อนไข A ที่ไม่มีการตอบสนองเชิงพฤติกรรม*

ผลในเงื่อนไข C เฉลี่ย 6 seeds แสดงในตารางต่อไปนี้ (SD ในวงเล็บ)

| | โมเดลฐาน | จูนไทย | ผลของการจูน | p (permutation) |
|---|---|---|---|---|
| Llama 3.1 8B | 0.820 (0.002) | 0.638 (0.004) | −0.181 | 0.0022 |
| Qwen 2.5 7B | 0.833 (0.005) | 0.859 (0.003) | +0.027 | 0.0022 |

ผลในเงื่อนไข D เฉลี่ย 6 seeds เช่นเดียวกับเงื่อนไข C

| | โมเดลฐาน | จูนไทย | ผลของการจูน | p (permutation) |
|---|---|---|---|---|
| Llama 3.1 8B | 0.608 (0.021) | 0.264 (0.015) | −0.344 | 0.0022 |
| Qwen 2.5 7B | 0.669 (0.017) | 0.725 (0.008) | +0.056 | 0.0022 |

ผลของการจูนภาษาไทยติดลบในตระกูล Llama และเป็นบวกในตระกูล Qwen ทั้งในเงื่อนไข C และเงื่อนไข D กล่าวคือการจูนทำให้ agent ระมัดระวังขึ้นมากในตระกูลหนึ่ง แต่ทำให้ระมัดระวังน้อยลงในอีกตระกูลหนึ่ง

ตัวควบคุม `seallm7b` ให้ C = 0.845 (6 seeds) และ D = 0.693 (3 seeds) ซึ่งอยู่ในกลุ่มเดียวกับโมเดลฐานทั้งสองตัว และไม่ได้ระมัดระวังแบบ `typhoon8b` ผลนี้ชี้ว่าการจูนภาษาระดับภูมิภาคอย่างเดียวไม่ก่อให้เกิดผลแบบที่การจูนภาษาไทยก่อในตระกูล Llama

ขนาดของผลในตระกูล Llama (−0.181) ใหญ่กว่า SD ข้าม seed ที่กว้างกว่าของคู่นั้นราว 46 เท่า และในตระกูล Qwen (+0.027) ใหญ่กว่าราว 5 เท่า ทั้งคู่จึงไม่ใช่สัญญาณรบกวน SD ที่ต่ำมากนี้เป็นผลของประชากร N = 1,000,000 ซึ่งกลบความผันผวนเชิงสุ่มของ SEIR ไปเกือบหมด ค่านี้จึงไม่ได้หมายความว่า LLM ตอบเหมือนกันทุกครั้ง

การทดสอบนัยสำคัญใช้ **exact permutation test** โดยถือ seed เป็นหน่วยสุ่ม สลับป้ายโมเดลครบทั้ง C(12, 6) = 924 แบบ ได้ p สองหาง = 0.0022 ทั้งสองตระกูล ซึ่งเป็นค่าต่ำสุดที่การออกแบบนี้ให้ได้เมื่อ n = 6 ต่อโมเดล ค่า p ที่ถึงค่าต่ำสุดเช่นนี้สะท้อนจำนวน seed ไม่ใช่ความแรงของหลักฐาน ความแรงของหลักฐานจึงพิจารณาจากขนาดของผลข้างต้น ที่ n = 3 เพดานอยู่ที่ p = 0.10 ซึ่งรายงานว่ามีนัยสำคัญไม่ได้เลยแม้ผลจะใหญ่กว่า SD หลายสิบเท่า การเพิ่มเป็น 6 seeds จึงทำให้รายงานค่า p ที่ต่ำกว่า 0.05 ได้ แต่ไม่ได้เพิ่มหลักฐานใหม่

seed ทั้งหกใช้ `persona_seed` เดียวกัน (2026) การเพิ่ม seed จึงลดความไม่แน่นอนรอบ ๆ การสุ่มบุคลิกชุดเดิมหนึ่งชุดเท่านั้น ส่วนความไม่แน่นอนจากการสุ่มบุคลิกเองยังไม่ถูกสุ่มเลย ข้อสรุปในหัวข้อนี้จึงครอบคลุมเฉพาะ persona ชุดเดียว (ดู §5.8.3 ซึ่งการเปลี่ยนคุณลักษณะเดียวของ agent หนึ่งตัวย้ายคำตอบของ `typhoon8b` ไป 111 จาก 180 วัน)

ตารางต่อไปนี้เทียบผลของแต่ละเงื่อนไขกับ baseline

| เงื่อนไข | attack rate | peak I | peak day | q̄_out |
|---|---|---|---|---|
| A — ไม่ตอบสนอง | 0.795 | 11.0% | 87 | 1.000 (นิยาม) |
| B — rule-based | 0.469 | 3.8% | 105 | 0.475 |
| C `typhoon8b` | 0.638 | 6.4% | 117 | 0.645 |
| C `llama8b` | 0.820 | 12.0% | 82 | 1.104 |
| C `qwen7b` | 0.833 | 13.1% | 76 | 1.178 |
| C `seallm7b` | 0.845 | 13.6% | 76 | 1.220 |

*(แถว C เป็นค่าเฉลี่ย 6 seeds แถว A และ B มีรันเดียวเพราะไม่มีองค์ประกอบสุ่มจาก LLM)*

สี่ในห้าโมเดลให้ q̄_out มากกว่า 1 ซึ่งหมายความว่า agent ออกนอกบ้านมากกว่าประชากรฐานทั้งที่กำลังมีโรคระบาด ค่านี้ขึ้นกับพารามิเตอร์ `contacts.baseline_mix` โดยตรง ซึ่งมีสถานะ `assumption` และยังไม่มีแหล่งอ้างอิง หัวข้อ 5.9 ทดสอบประเด็นนี้โดยเฉพาะ ภายใต้สมมติฐานที่อนุรักษ์นิยมกว่า จำนวนโมเดลที่มี q̄_out มากกว่า 1 ลดเหลือสามในห้า (`llama8b` ลงมาที่ 0.971) ส่วนจำนวนโมเดลที่ให้ attack rate สูงกว่าเงื่อนไข A ซึ่งนับด้วยเกณฑ์ต่างจาก q̄_out ก็ลดจากสี่เหลือสามในห้าเช่นกัน และเป็นสามโมเดลชุดเดียวกันคือ `qwen7b`, `openthaigpt7b` และ `seallm7b` ตัวเลข q̄_out ในตารางนี้จึงผูกกับสมมติฐาน `baseline_mix` เดิม

## 5.4 กลไก — การจูนภาษาเปลี่ยนกรอบการให้เหตุผล (RQ2)

เพื่อตอบว่าอะไรทำให้ผลในหัวข้อ 5.3 เกิดขึ้น เราวิเคราะห์ฟิลด์ `reason` ที่โมเดลเขียนกำกับทุกการตัดสินใจ จำนวน 7,200 รายการต่อโมเดล (seed 1) รวม 36,000 รายการ

![](../outputs/figures/04_reason_diversity.png)

*รูปที่ 2: ซ้าย: สัดส่วนเหตุผลที่ไม่ซ้ำกัน ขวา: สัดส่วนเหตุผลที่อ้างถึงรายได้*

| โมเดล | เหตุผลที่ไม่ซ้ำกัน | เหตุผลที่พบบ่อยที่สุด | สัดส่วนของเหตุผลนั้น | กรอบ "รายได้" | กรอบ "ความจำเป็น" |
|---|---|---|---|---|---|
| `llama8b` | 76.5% | "Work is considered essential and income loss is high…" | 0.7% | 54% | 34% |
| `typhoon8b` | 65.2% | "work is considered essential" | 2.4% | 19% | 36% |
| `seallm7b` | 64.8% | "I need to maintain my income…" | 2.0% | 59% | 24% |
| `qwen7b` | 19.0% | "Need income to support family" | 11.6% | 56% | 32% |
| `openthaigpt7b` | 17.1% | "Need income to support family" | 16.0% | 65% | 23% |

ตระกูล Qwen เกิด **reason collapse** โมเดลทั้งสองตัวในตระกูลนี้ผลิตเหตุผลที่ไม่ซ้ำกันเพียง 17–19% ของการตัดสินใจทั้งหมด และเหตุผลประโยคเดียวครอบคลุมถึง 16% ในกรณีของ `openthaigpt7b` ขณะที่ตระกูล Llama และ SeaLLM อยู่ที่ 65–77% ผลนี้เป็นคำอธิบายว่าเหตุใดตระกูล Qwen จึงเลือกไปทำงานซ้ำ ๆ คือมันผลิตเหตุผลซ้ำ ๆ ไม่ได้ประเมินสถานการณ์ใหม่ในแต่ละวัน

การจูนภาษาไทยเปลี่ยนกรอบที่โมเดลใช้คิด และเปลี่ยนคนละทิศในสองตระกูล ดังตารางต่อไปนี้

| ตระกูล | กรอบ "รายได้" | ทิศของผลใน 5.3 |
|---|---|---|
| `llama8b` → `typhoon8b` | 54% → 19% | −0.181 |
| `qwen7b` → `openthaigpt7b` | 56% → 65% | +0.027 |

การจัดข้อความเข้ากรอบใช้การจับคำด้วย regex แบบไม่สนตัวพิมพ์ใน `scripts/analysis/reason_analysis.py` กรอบ "รายได้" คือรูปแบบ `income|earn|money|wage|pay|รายได้|เงิน|ค่าจ้าง` วิธีนี้มีขอบเขตสามประการ ประการแรก กรอบไม่ได้แยกขาดจากกัน ข้อความเดียวเข้าได้หลายกรอบพร้อมกัน ผลรวมของทุกกรอบจึงเกิน 100% ได้ และตัวเลขแต่ละกรอบเป็นสัดส่วนของข้อความที่*กล่าวถึง*เรื่องนั้น ไม่ใช่สัดส่วนที่*จัดเป็น*เรื่องนั้น ประการที่สอง ตัวเลขทั้งหมดมาจาก seed 1 เท่านั้น (รันที่ระบุไว้ในตัวแปร `RUNS` ของสคริปต์) ไม่ใช่ค่าเฉลี่ยหก seed อย่างตัวเลขในหัวข้อ 5.3

ประการที่สาม การจับคำไม่เข้าใจการปฏิเสธ ข้อความที่เขียนว่าไม่ได้ห่วงเรื่องรายได้ก็ถูกนับเข้ากรอบนี้เช่นกัน ความสอดคล้องระหว่างทิศของกรอบกับเครื่องหมายของผลจึงเป็นความสัมพันธ์ที่ตรวจสอบซ้ำได้ ไม่ใช่การพิสูจน์เชิงสาเหตุ

ในตระกูล Llama การจูนไทยลดกรอบ "รายได้" ลงเกือบสามเท่าและเพิ่มกรอบ "ความจำเป็นและความระมัดระวัง" agent จึงอยู่บ้านมากขึ้นและการระบาดเล็กลง ส่วนในตระกูล Qwen การจูนไทยกลับเพิ่มกรอบ "รายได้" และทำให้ความหลากหลายของเหตุผลยุบลงอีก agent จึงออกไปทำงานมากขึ้นและการระบาดใหญ่ขึ้น ทิศทางของการเปลี่ยนแปลงในกรอบการให้เหตุผลตรงกับเครื่องหมายของผลในหัวข้อ 5.3 ทั้งสองตระกูล ผลหลักจึงไม่ใช่ความบังเอิญเชิงตัวเลข แต่มีกลไกที่ตรวจสอบได้ในข้อความที่โมเดลผลิตออกมาจริง

ไม่มีโมเดลใดเขียนเหตุผลเป็นภาษาไทยเลย แม้แต่สองโมเดลที่จูนภาษาไทย เพราะ prompt ที่ให้ไปเป็นภาษาอังกฤษ การจูนภาษาไทยจึงส่งผลที่ *เนื้อหาของการตัดสินใจ* ไม่ใช่ที่ *ภาษาของเอาต์พุต* ผลนี้ขัดกับความคาดหมายตามสัญชาตญาณ และยืนยันว่าสิ่งที่การจูนเปลี่ยนคือ behavioral prior ไม่ใช่เพียงความสามารถทางภาษา

การตรวจ `leader.jsonl` โดยละเอียดพบข้อเท็จจริงสองอย่างที่แยกจากกัน อย่างแรก ผู้นำอ่านข้อมูลได้ถูกต้อง การตรวจฟิลด์ `reason` เทียบกับตัวเลขที่ป้อนเข้า prompt ทุกสัปดาห์พบว่ารายงานแนวโน้มตรงกับที่ป้อนทุกครั้ง และอ้างตัวเลขได้ถูก เช่น `typhoon8b` ในสัปดาห์ที่ 18 ตอบว่า *"215.0 cases per 100,000 people per day, stable trend, 15% on-site work"* ซึ่งถูกต้องทั้งสามค่า และไม่มี fallback หรือ retry เลยในการตัดสินใจของผู้นำทั้ง 702 ครั้ง (27 รัน × 26 สัปดาห์)

อย่างที่สอง การเลือกระดับนโยบายแทบไม่ขึ้นกับสิ่งที่อ่าน เส้นทางนโยบายรายสัปดาห์แสดงในรูปที่ 3

*รูปที่ 3: เส้นทางนโยบายรายสัปดาห์ (แถบสีพื้นหลัง) เทียบกับยอดผู้ป่วยที่ผู้นำเห็น (เส้น) เส้นประที่ 528 คือระดับต่ำสุดที่เคยกระตุ้นให้โมเดลใดยกระดับเป็น `strict`*

จากการตัดสินใจทั้งหมด 702 ครั้ง (27 รัน × 26 สัปดาห์) `strict` ถูกเลือกเพียง 5 ครั้งและกระจุกอยู่ในสองรัน คือ `llama8b` seed 2 สี่ครั้งและ `llama8b` seed 6 หนึ่งครั้ง รันส่วนใหญ่เลือก `open` ในสัปดาห์แรกตอนที่ยังไม่มีผู้ป่วย แล้วเปลี่ยนเป็น `limited` และคงอยู่อย่างนั้นตลอด 25 สัปดาห์ที่เหลือ ส่วน `typhoon8b` สามรันข้าม `open` ไปเลือก `limited` ตั้งแต่สัปดาห์แรก

หลักฐานสองข้อชี้ว่าการยกระดับไม่ได้เป็นฟังก์ชันของความรุนแรง

1. สองรันที่ยกระดับคือ `llama8b` seed 2 และ seed 6 ซึ่งเป็นสองรันที่ผู้นำเห็นยอดเคสสูงสุด *ต่ำที่สุด* ในหก seed ของโมเดลเดียวกัน (528 และ 602 เทียบกับ 625, 644, 645 และ 653) ถ้าการยกระดับขึ้นกับจำนวนเคส อีกสี่ seed ย่อมต้องยกระดับก่อน แต่ไม่ยกเลยสักรัน
2. `openthaigpt7b` เห็นยอดเคส 986 ต่อแสนต่อวัน ซึ่งสูงเกือบสองเท่าของจุดที่ `llama8b` ยกระดับ และยังคงเลือก `limited` โดยให้เหตุผลว่าสถานการณ์ "stable"

สิ่งที่ `llama8b` seed 2 ทำได้ถูกต้องคือหลังยกระดับแล้วผ่อนลงเมื่อเคสลดลง โดยใช้ `strict` ในสัปดาห์ที่ 12–15 ขณะเคสลดจาก 528 เป็น 470 แล้วกลับเป็น `limited` ที่ระดับ 440 ซึ่งเป็นพฤติกรรม closed-loop ที่พึงประสงค์ แต่เกิดขึ้นในสองรันจาก 27 รัน จึงถือเป็นเหตุบังเอิญมากกว่าความสามารถ

ในเชิงการตีความ ผลที่ว่า D ดีกว่า C ไม่ใช่ผลของนโยบายที่ปรับตามสถานการณ์ แต่เป็นผลของการตั้งระดับ `limited` ค้างไว้ตลอด ซึ่งเทียบเท่ากับการใส่ระดับนโยบายคงที่เข้าไปในแบบจำลองโดยไม่ต้องใช้ LLM เลย เนื่องจากผู้นำทุกโมเดลตัดสินใจเหมือนกันแทบทั้งหมด ความต่างของผลในเงื่อนไข D ที่กว้างถึง 0.268–0.723 จึงมาจากประชาชน ไม่ได้มาจากผู้นำ

กลไกที่น่าจะเป็นคือทุกเหตุผลมีโครงสร้างเดียวกัน คือการถ่วงดุลระหว่างสุขภาพกับการทำมาหากิน ซึ่ง `limited` เป็นตัวเลือกกลางที่สนองกรอบนี้ได้เสมอไม่ว่าสถานการณ์จะเป็นอย่างไร

### 5.5.1 การแยกช่องทางของนโยบาย

ส่วนต่าง C−D ในตารางข้างบนรวมผลสองทางที่นโยบายลงมือพร้อมกันเข้าด้วยกัน ทางแรกคือตัวคูณ `q_policy` ซึ่งลดการแพร่เชื้อต่อการสัมผัสหนึ่งครั้งโดยตรงในสมการ β_eff ทางที่สองคือข้อความประกาศและรายการกิจกรรมที่ถูกแบน ซึ่งเปลี่ยน prompt ที่ผู้อยู่อาศัยเห็นและจึงเปลี่ยนการตัดสินใจของพวกเขา การรายงานเฉพาะส่วนต่างรวมโดยไม่แยกสองทางนี้เปิดช่องให้ถูกตั้งคำถามว่านับผลของนโยบายซ้ำสองรอบ

การแยกทำได้โดยไม่ต้องรันเพิ่มแม้แต่รันเดียว เพราะ `daily.csv` บันทึก `q_out` ของทุกวันในเงื่อนไข C และบันทึก `q_policy` กับ `level` ของทุกวันในเงื่อนไข D ไว้อยู่แล้ว นำอนุกรมที่บันทึกไว้มาประกอบใหม่แล้วเดิน SEIR ซ้ำด้วยฟังก์ชันเดียวกับที่การจำลองใช้

- ช่องทางกลไก = attack(C) − attack(พฤติกรรมของ C ภายใต้ `q_policy` ของ D)

ผู้นำแทบไม่สร้างความต่างระหว่างโมเดลเลย ใน 22 จาก 27 รัน ค่า `q_policy` เฉลี่ยเท่ากันเป๊ะที่ 0.6924 ซึ่งตรงกับการเลือก `open` ในสัปดาห์แรกแล้ว `limited` อีก 173 วันที่เหลือ ข้อยกเว้นมีห้ารัน คือ `llama8b` หนึ่งรันที่ใช้ `strict` อยู่ 28 วัน (0.6427) `llama8b` อีกหนึ่งรันที่ใช้ `strict` 7 วัน (0.6800) และ `typhoon8b` สามรันที่ข้าม `open` ไปเลือก `limited` ตั้งแต่วันแรก (0.6800) เมื่อสิ่งที่ผู้นำผลิตออกมาเหมือนกันเกือบทั้งหมด ช่องทางกลไกจึงเกือบคงที่เช่นกัน คืออยู่ในช่วง 0.107–0.129 สำหรับสี่โมเดล

ช่องทางพฤติกรรมต่างกันสิบสามเท่า จาก 0.218 ใน `typhoon8b` ลงมาเหลือ 0.017 ใน `openthaigpt7b` ผลนี้ยืนยันข้อสรุปของหัวข้อ 5.5 ด้วยตัวเลขแทนการอนุมาน คือความต่างของผลในเงื่อนไข D มาจากประชาชน ไม่ได้มาจากผู้นำ

ทั้งสองช่องทางวัดเป็นส่วนต่างของ attack rate จึงพ่วงความโค้งของเส้น final size มาด้วย โมเดลที่ทำงานอยู่ต่ำกว่าบนเส้นนั้นจะแปลงการเปลี่ยนแปลงของการแพร่เชื้อเท่ากันเป็นส่วนต่าง attack rate ที่ใหญ่กว่า ซึ่งเป็นเหตุผลที่ช่องทางกลไกของ `typhoon8b` (0.184) สูงกว่าโมเดลอื่นทั้งที่ได้รับนโยบายชุดเดียวกัน ตัววัดที่ปลอดความโค้งคือการลดลงของ q̄_out เอง ซึ่งเป็นการถามตรง ๆ ว่าเมื่อมีประกาศแล้วประชาชนลดกิจกรรมลงเท่าใด

ลำดับนี้ตรงกับลำดับของช่องทางพฤติกรรม และตรงกับผลการทดลองแทรกแซง agent เดียวในหัวข้อ 5.8.3 ที่หัวแถวและท้ายแถว คือ `typhoon8b` ตอบสนองมากที่สุดทั้งต่อคุณลักษณะของตัวเองและต่อประกาศของรัฐ ส่วน `openthaigpt7b` ตอบสนองน้อยที่สุดทั้งสองอย่าง (ตรงกลาง `qwen7b` กับ `seallm7b` สลับตำแหน่งกันระหว่างสองการวัด) การวัดสามแบบเป็นอิสระต่อกัน ได้แก่ ความไวต่อ persona ความไวต่อนโยบาย และขนาดของช่องทางพฤติกรรม และทั้งสามให้ลำดับหัวท้ายเดียวกัน ผลนี้หนุนการตีความว่าสิ่งที่ต่างกันคือโมเดลใช้ข้อมูลใน prompt มากน้อยเพียงใด ไม่ใช่ความระมัดระวังโดยรวมของโมเดล

การแยกนี้มีขอบเขตจำกัด ทั้งสองช่องทางไม่ใช่ counterfactual ที่สะอาด เพราะ "พฤติกรรมของ C ภายใต้นโยบายของ D" เป็นสถานการณ์ที่ไม่เคยเกิดขึ้นจริง ประชาชนในเงื่อนไข D ประพฤติต่างจากในเงื่อนไข C จริง ๆ ส่วนตกค้างซึ่งอยู่ระหว่าง −0.028 ถึง +0.024 คือขนาดของ interaction ระหว่างสองช่องทาง การที่มันเล็กเมื่อเทียบกับส่วนต่างรวมทำให้การแยกนี้ใช้เป็นการประมาณได้ แต่การวัดที่สะอาดกว่าต้องรันเงื่อนไขเพิ่มที่ให้ประชาชนเห็นประกาศโดยปิด `q_policy` ไว้ ซึ่งยังไม่ได้ทำ

รันเดียวที่ผู้นำยกระดับเป็น `strict` จริง (`llama8b` seed 2) ได้ช่องทางกลไกสูงขึ้นจาก 0.117 ใน seed อื่นทั้งสองเป็น 0.172 ขณะที่ช่องทางพฤติกรรมแทบไม่ขยับ (0.057–0.062 เป็น 0.055) กล่าวคือแม้ในกรณีที่ผู้นำทำสิ่งที่ควรทำ ประโยชน์ที่เพิ่มขึ้นก็มาจากตัวคูณการแพร่เชื้อเกือบทั้งหมด ไม่ได้มาจากการที่ประชาชนตอบสนองต่อประกาศที่เข้มขึ้น ข้อสังเกตนี้มาจากการเทียบข้าม seed ซึ่งต่างกันที่การสุ่มของ LLM ด้วย จึงมีสถานะเป็นข้อบ่งชี้มากกว่าข้อสรุป

## 5.6 ความสมเหตุสมผลของพฤติกรรม

เพื่อยืนยันว่า agent ตอบสนองต่อเงื่อนไขส่วนบุคคลอย่างมีเหตุผล ไม่ใช่เลือกแบบสุ่ม เราตรวจสองมิติ มิติแรกคือกลุ่มอาชีพ ตารางต่อไปนี้แสดงสัดส่วนที่เลือก `stay_home` (seed 1)

ในกลุ่มที่อยู่ในกำลังแรงงาน ทุกโมเดลให้กลุ่ม office ซึ่งทำงานจากบ้านได้อยู่บ้านมากที่สุด ทิศทางนี้ตรงกับที่คาดไว้ทั้งห้าโมเดล ส่วนกลุ่มที่อยู่บ้านน้อยที่สุดไม่ตรงกัน เป็น public ใน `qwen7b` `openthaigpt7b` และ `seallm7b` และเป็น trade ใน `llama8b` และ `typhoon8b` โดยกลุ่ม agri ไม่เคยต่ำสุดในโมเดลใดเลย ข้ออ้างว่าลำดับถูกต้องจึงจำกัดอยู่ที่ตำแหน่งสูงสุดเท่านั้น ไม่ใช่ทั้งลำดับ

แบบจำลองไม่ได้ห้าม agent ในกลุ่ม `notwork` เลือก `work_onsite` ไว้ เพราะ `persona_text` ใส่เพียงบรรทัด `Not in paid work` ลงใน prompt โดยไม่มีการตัดตัวเลือกออก ความสอดคล้องจึงขึ้นกับว่าโมเดลอ่านบรรทัดนั้นหรือไม่ และผลออกมาต่างกันมาก `typhoon8b` `qwen7b` และ `openthaigpt7b` ไม่เลือก `work_onsite` เลยสักครั้ง ขณะที่ `llama8b` เลือก 8 จาก 1,080 ครั้ง (0.7%) และ `seallm7b` เลือก 227 จาก 1,080 ครั้ง (21.0%) ที่ seed นี้ เมื่อรวมทั้งหก seed สัดส่วนของ `seallm7b` อยู่ที่ 19.7% ซึ่งสอดคล้องกับตารางในหัวข้อ 5.8.3

คอลัมน์ "ไม่มีอาการ" รวม agent ที่หายป่วยแล้วเข้าไปด้วย เพราะทั้งสองกลุ่มเห็นข้อความสุขภาพที่ไม่มีอาการใน prompt นอกจากนี้ จำนวนวันที่มีอาการมีเพียง 193–247 จาก 7,200 การตัดสินใจต่อโมเดล ตัวเลขคอลัมน์นี้จึงตั้งอยู่บนฐานที่เล็กกว่าตัวเลขอื่นในรายงานนี้มาก ความแม่นจำกัดอยู่ที่ทศนิยมตำแหน่งแรก

## 5.7 ความคงทนต่อลำดับตัวเลือกใน prompt

สัดส่วนกิจกรรมรายตัวไม่คงทน `essential_errand` ของ `qwen7b` อยู่ที่ 0.681 เมื่อเป็นตัวเลือกอันดับสอง แต่เป็น 0.000 เมื่อเป็นอันดับสุดท้าย และ `stay_home` ของ `typhoon8b` ขยับจาก 0.390 เป็น 0.758 เพียงเพราะเปลี่ยนตำแหน่งในรายการ attack rate เองแกว่งตามลำดับตั้งแต่ 0.051 (`openthaigpt7b`) ถึง 0.284 (`typhoon8b`)

สัดส่วนกิจกรรมรายตัวจึงอ้างเป็นตัวเลขเดี่ยวไม่ได้ และต้องรายงานเป็นช่วงข้ามลำดับ ส่วนการเปรียบเทียบระหว่างโมเดลภายใต้ลำดับเดียวกันยังใช้ได้ เพราะทุกโมเดลเผชิญลำดับเดียวกัน ซึ่งเป็นเหตุผลที่โครงงานควบคุม prompt ให้เหมือนกันทุกโมเดลตั้งแต่ต้น

ตัวเลือก `visit_family` แทบไม่ถูกเลือกเลยในทุกโมเดล เมื่อยกขึ้นเป็นตัวเลือกแรกในสองลำดับ ได้ส่วนแบ่งสูงสุดเพียง 1.8% (`llama8b`) ส่วน `qwen7b` และ `openthaigpt7b` เป็น 0.000 พอดีแม้อยู่อันดับแรก จึงสรุปได้ว่าเป็นพฤติกรรมจริงของโมเดล ไม่ใช่ข้อบกพร่องของการออกแบบ ระดับการสัมผัสสัมพัทธ์ของ `visit_family` อยู่ที่ 0.918 ซึ่งต่ำกว่าค่าเฉลี่ยประชากร ผลกระทบเชิงระบาดวิทยาจึงน้อยมาก โมเดลทั้งห้าใช้กรอบ "ลดการสัมผัส" แบบสากล มากกว่ากรอบวัฒนธรรมเฉพาะถิ่นเรื่องความผูกพันในครอบครัว แม้แต่โมเดลที่จูนภาษาไทย

ข้อมูลจากสำนักงานสถิติแห่งชาติสนับสนุนพฤติกรรมนี้มากกว่าจะขัดแย้ง สำมะโนประชากรและเคหะ 2553 ให้ขนาดครัวเรือนเฉลี่ย 3.1 คนและครัวเรือนคนเดียว 18.4% (เพิ่มจาก 9.4% ในปี 2543) ส่วน Digital Census 2568 ฉบับเบื้องต้นให้ขนาดครัวเรือนเฉลี่ย 2.5 คน แนวโน้มชี้ว่าครัวเรือนไทยเล็กลงและอยู่คนเดียวมากขึ้นอย่างต่อเนื่อง

## 5.8 ความไวต่อพารามิเตอร์

การกวาดครั้งนี้มีขอบเขตดังนี้ สามแกนแรกรันบน `llama8b` เท่านั้น ส่วน `wfh_scale` รันครบทั้งห้าโมเดล เหตุผลคืองบ GPU ไม่ใช่การออกแบบ คิวของคลัสเตอร์จำกัดงาน GPU ไว้หนึ่งงานต่อผู้ใช้ งาน array จึงรันต่อกันเป็นลำดับ ไม่ใช่ขนาน `wfh_scale` ถูกเลือกให้รันครบเพราะเป็นแกนเดียวที่แก้ prompt โดยตรง จึงตอบได้ว่า agent อ่านคุณลักษณะของตัวเองแล้วทำตามหรือไม่ ทุกรันในหัวข้อนี้ใช้ seed 1 และ 180 วัน

### 5.8.1 ไม่มีแกนใดขยับเงื่อนไข C ได้พอที่จะล้มข้อสรุป

| แกน | เงื่อนไข C (`llama8b`) | ช่วงที่ขยับได้ | เงื่อนไข B | ช่วงที่ขยับได้ |

| `f_errand` | 0.817 → 0.819 | 0.003 | 0.463 → 0.475 | 0.012 |

ในเงื่อนไข C ค่าที่ขยับได้มากที่สุดข้ามทุกโมเดลและทุกแกนคือ 0.025 (`typhoon8b` บนแกน `wfh_scale`) ขณะที่ผลการจูนภาษาในตระกูล Llama อยู่ที่ 0.181 ซึ่งใหญ่กว่าราวเจ็ดเท่า ผลหลักของโครงงานจึงไม่ได้ขึ้นกับการเลือกค่าพารามิเตอร์ตัวใดตัวหนึ่งในสี่แกนที่กวาด

### 5.8.2 ทำไมเงื่อนไข B จึงไวกว่า และทำไมเครื่องหมายจึงกลับกัน

ตัวเลข 0.176 เทียบกับ 0.023 บนแกนเดียวกันอาจดูเหมือนว่าการมีชั้น LLM ทำให้แบบจำลอง "ด้าน" ต่อโครงสร้างการสัมผัส แต่พีชคณิตของสมการ β อธิบายได้ตรง ๆ

β_eff = β₀ · [w_home + (1 − w_home) · q̄_out · q_policy]

การเพิ่ม `w_home_scale` ทำให้ w_home สูงขึ้น ซึ่งเท่ากับย้ายน้ำหนักจากพจน์ที่ถูกคูณด้วย q̄_out ไปยังพจน์ที่ไม่ถูกคูณ ทิศของผลจึงขึ้นกับว่า q̄_out อยู่ฝั่งไหนของ 1

| `w_home_scale` | w_home | R₀ ประสิทธิผล — B (q̄ = 0.475) | C `llama8b` (q̄ = 1.103) |
|---|---|---|---|
| 0.5 | 0.346 | 1.313 | 2.135 |
| 1.0 | 0.507 | 1.483 | 2.101 |
| 1.5 | 0.601 | 1.581 | 2.082 |

ในเงื่อนไข B ที่ q̄_out = 0.475 การเพิ่มน้ำหนักบ้านคือการลบผลของการอยู่บ้านออกไป R₀ จึงเพิ่มจาก 1.313 เป็น 1.581 และ attack rate เพิ่มจาก 0.364 เป็น 0.540 ส่วนในเงื่อนไข C ที่ q̄_out = 1.103 ซึ่งเกิน 1 เล็กน้อย การเพิ่มน้ำหนักบ้านกลับดึง β_eff เข้าหา β₀ R₀ จึงลดลงเล็กน้อยจาก 2.135 เป็น 2.082 และ attack rate ลดจาก 0.833 เป็น 0.809 ผลนี้ตรงกับที่สมการทำนายทั้งขนาดและเครื่องหมาย ความไวที่ต่ำกว่าของเงื่อนไข C จึงไม่ใช่ข้อบกพร่องของการ coupling แต่เป็นผลโดยตรงของการที่ agent เลือกออกนอกบ้านมาก

เหตุผลที่สองคือจุดทำงานของเงื่อนไข C อยู่บนส่วนที่ชันน้อยของเส้น final size ที่ attack rate 0.47 ค่า da/dR₀ ประมาณ 0.88 แต่ที่ attack rate 0.82 เหลือประมาณ 0.24 ความคงทนที่รายงานในหัวข้อ 5.8.1 จึงส่วนหนึ่งมาจากการที่เงื่อนไข C อยู่ใกล้เพดานของการระบาดอยู่แล้ว ข้อสรุปเรื่องความคงทนจึงจำกัดอยู่ในระบอบที่ทดสอบ และไม่ครอบคลุมทุกระบอบของพารามิเตอร์

### 5.8.3 การทดลองแทรกแซงคุณลักษณะเดียวใน agent เดียว

`wfh_scale` เป็นแกนเดียวที่แก้ prompt โดยตรง เมื่อเทียบ `wfh_scale = 0.5` กับ `1.0` ปรากฏว่าทั้งสองรันต่างกันที่ agent คนเดียวคือ agent 13 และต่างกันที่บรรทัดเดียวคือ `Can work from home` ซึ่งเปลี่ยนจาก `no` เป็น `yes` ส่วนที่เหลือทั้งหมด ได้แก่ persona อีก 39 คน seed และ prompt เหมือนกันหมด การทดลองนี้จึงเป็นการแทรกแซงที่สะอาดที่สุดเท่าที่ข้อมูลชุดนี้ให้ได้ และเป็นการวัดโดยตรงว่าโมเดลใช้คุณลักษณะของ persona จริงหรือไม่

| โมเดล | วันที่ agent 13 เปลี่ยนคำตอบ | `stay_home` ของ agent 13 เมื่อ `no` → เมื่อ `yes` | คำตอบที่เปลี่ยนทั้งประชากร |
|---|---|---|---|
| `typhoon8b` | 111 / 180 | 48 → 157 | 199 / 7,200 |
| `llama8b` | 61 / 180 | 0 → 61 | 104 / 7,200 |
| `seallm7b` | 25 / 180 | 0 → 25 | 44 / 7,200 |
| `qwen7b` | 4 / 180 | 0 → 4 | 40 / 7,200 |
| `openthaigpt7b` | 0 / 180 | 0 → 0 | 0 / 7,200 |

`openthaigpt7b` ตอบ `work_onsite` ทั้ง 180 วันไม่ว่าบรรทัดนั้นจะเป็น `yes` หรือ `no` ไม่มีคำตอบใดใน 7,200 คำตอบเปลี่ยนเลย และเส้นทางการระบาดจึงเหมือนกันทุกประการถึงทศนิยมหกตำแหน่ง (0.857937 ทั้งสองรัน) โมเดลนี้ไม่ได้อ่านคุณลักษณะที่ควรเป็นตัวกำหนดคำตอบโดยตรงที่สุดในแบบจำลองนี้ ส่วน `typhoon8b` ซึ่งเป็นโมเดลที่ระมัดระวังที่สุดเปลี่ยนคำตอบ 111 จาก 180 วัน

ภาพระดับประชากรให้ข้อสรุปเดียวกัน ตารางต่อไปนี้คำนวณจากเงื่อนไข C ของรันหลักหก seed (`tag == ""` เท่านั้น ไม่รวมรันที่ติดแท็กทดสอบความคงทน)

กลุ่มเปรียบเทียบนิยามดังนี้ ตารางนี้ใช้เฉพาะ agent ที่อยู่ในกำลังแรงงาน 34 คน แล้วแบ่งตามบรรทัด `Can work from home: yes/no` ใน prompt ของตัวเอง agent อีก 6 คนที่ไม่ได้อยู่ในกำลังแรงงานถูกตัดออกจากทั้งสองกลุ่ม เพราะ `persona_text` ใส่บรรทัด `Not in paid work` ให้แทน prompt ของพวกเขาจึงไม่มีบรรทัด WFH ให้โมเดลอ่านเลย การนับพวกเขาเข้ากลุ่มใดกลุ่มหนึ่งจะวัดสิ่งอื่นแทนสิ่งที่ตั้งใจวัด

| โมเดล | P(`stay_home` \| prompt บอกว่าทำได้) | P(`stay_home` \| prompt บอกว่าทำไม่ได้) | ส่วนต่าง |
|---|---|---|---|
| `llama8b` | 0.737 | 0.051 | +0.686 |
| `typhoon8b` | 0.911 | 0.231 | +0.680 |
| `seallm7b` | 0.565 | 0.042 | +0.523 |
| `qwen7b` | 0.536 | 0.026 | +0.510 |
| `openthaigpt7b` | 0.205 | 0.003 | +0.202 |

ลำดับนี้ตรงกับการทดลองแทรกแซง agent 13 แทบทุกตำแหน่ง `seallm7b`, `qwen7b` และ `openthaigpt7b` เรียงตรงกันพอดี ส่วน `llama8b` กับ `typhoon8b` ต่างกันเพียง 0.006 ซึ่งถือว่าเสมอกันในทางปฏิบัติ หลักฐานสองชุดที่คำนวณคนละวิธีจึงชี้ไปทางเดียวกัน คือความต่างระหว่างโมเดลอยู่ที่ว่าโมเดลอ่านและใช้ข้อความใน prompt มากแค่ไหน ไม่ใช่ว่าโมเดลระมัดระวังโดยรวมเพียงใด

ทุกโมเดลแยกแยะคุณลักษณะนี้ได้ในทิศที่ถูก แต่ `openthaigpt7b` เลือก `stay_home` เพียง 20.5% แม้ prompt จะระบุว่าทำงานจากบ้านได้ เทียบกับ 91.1% ของ `typhoon8b` ข้อสังเกตนี้สอดคล้องกับหัวข้อ 5.6 ที่พบว่า `openthaigpt7b` ยังไปทำงานนอกบ้าน 66.8% ขณะมีไข้ และช่วยอธิบายว่าทำไมโมเดลนี้จึงให้ attack rate สูงที่สุดในแผง

คอลัมน์ซ้ายของตารางนี้มาจาก agent เพียง 4 คน จาก 34 คนที่อยู่ในกำลังแรงงาน (4,320 การตัดสินใจ) เพราะสัดส่วนผู้ทำงานจากบ้านได้ในจังหวัดสังเคราะห์นี้ต่ำตามข้อมูลตั้งต้น ส่วนต่างที่เห็นจึงให้ทิศทางที่มั่นคง แต่ความแม่นของทศนิยมตำแหน่งที่สองมีจำกัด

กลุ่มที่ไม่ได้อยู่ในกำลังแรงงานซึ่งถูกตัดออกให้ข้อมูลเสริม ตารางต่อไปนี้แสดงสัดส่วนการเลือกของ agent ทั้ง 6 คนนั้น รวม 6,480 การตัดสินใจต่อโมเดล จากเงื่อนไข C ทั้งหก seed

| โมเดล | `stay_home` | `essential_errand` | `work_onsite` | `visit_family` |
|---|---|---|---|---|
| `typhoon8b` | 0.900 | 0.100 | 0.000 | 0.000 |
| `seallm7b` | 0.787 | 0.016 | 0.197 | 0.000 |
| `llama8b` | 0.320 | 0.648 | 0.005 | 0.027 |
| `qwen7b` | 0.020 | 0.980 | 0.000 | 0.000 |
| `openthaigpt7b` | 0.007 | 0.993 | 0.000 | 0.000 |

ความไม่สมเหตุสมผลเชิงความหมายที่ชัดที่สุดคือ `seallm7b` ส่ง agent ที่ prompt ระบุว่า `Not in paid work` ออกไป `work_onsite` ถึง 19.7% ของวันทั้งหมด ซึ่งขัดกับข้อความใน prompt ของตัวเองโดยตรง ส่วน `qwen7b` และ `openthaigpt7b` ไม่ได้ขัดแย้งเชิงตรรกะแบบนั้น แต่เลือก `essential_errand` เกือบทุกวัน (98.0% และ 99.3%) ซึ่งหมายความว่าคนที่ไม่ได้ทำงานออกจากบ้านไปทำธุระทุกวันตลอดการระบาด เป็นรูปแบบที่ไม่สมจริงคนละแบบกัน ทั้งสองกรณีเป็นความบกพร่องที่ตัวเลข attack rate เพียงอย่างเดียวมองไม่เห็น

การกวาดแกนนี้เปลี่ยนจำนวน agent ที่ทำงานจากบ้านได้จาก 3 เป็น 4 เป็น 6 คน จากทั้งหมด 40 คนเท่านั้น ผลต่อ attack rate จึงถูกจำกัดโดยโครงสร้างตั้งแต่ต้น ตัวเลขที่ให้ข้อมูลคือการเปลี่ยนคำตอบระดับ agent ไม่ใช่ขนาดของผลต่อการระบาด

### 5.8.4 การตรวจความทำซ้ำได้ที่ได้มาโดยบังเอิญ

`wfh_scale = 1.0` ให้ค่าพารามิเตอร์เท่ากับรันหลักทุกประการ แต่เพราะ tag เป็นส่วนหนึ่งของ run id รันนี้จึงถูกประมวลผลใหม่ทั้งหมดแทนที่จะถูกข้าม ผลที่ได้ตรงกับรันหลักที่ seed 1 ทั้งห้าโมเดลถึงทศนิยมสี่ตำแหน่ง (`llama8b` 0.8177, `typhoon8b` 0.6417, `qwen7b` 0.8304, `seallm7b` 0.8461, `openthaigpt7b` 0.8579) ซึ่งยืนยันว่าสายงานทั้งเส้นรวมถึงการเรียก LLM เป็น deterministic เมื่อ seed และ config เท่ากัน

## 5.9 ความไวต่อ `baseline_mix`

หัวข้อ 5.3 รายงานว่าสี่ในห้าโมเดลให้ q̄_out มากกว่า 1 และสี่ในห้าให้ attack rate สูงกว่าเงื่อนไข A ที่ไม่มีการตอบสนองเชิงพฤติกรรมเลย ข้อสังเกตนี้หมายความว่าการใส่ agent ที่ "คิดเอง" เข้าไปทำให้การระบาดแย่ลง ซึ่งเป็นข้อสรุปที่หนักพอจะตรวจสอบก่อนยอมรับ

ข้อสรุปนั้นตั้งอยู่บนพารามิเตอร์ตัวเดียวคือ `contacts.baseline_mix` ซึ่งเป็นสมมติฐานว่าวันปกติประชากรแบ่งกิจกรรมกันอย่างไร ค่านี้นิยาม base_out ซึ่งเป็นตัวหารของ q̄_out ทั้งหมด และมีสถานะ `assumption` ใน `data/parameter_sources.csv` โดยไม่มีแหล่งอ้างอิง ถ้าสมมติว่าวันปกติคนออกไปทำงานน้อยเกินจริง q̄_out ก็จะดูสูงเกินจริงโดยอัตโนมัติ

## 5.10 ขอบฟ้าที่ยาวขึ้น — ลดหรือเพียงยืด

ตัวเลขทั้งหมดที่รายงานมาเป็น attack rate สะสม ณ วันที่ 180 ซึ่งเป็นจุดตัดที่เราเลือกเอง หัวข้อ 5.5 ชี้ว่าเงื่อนไข D ของ `typhoon8b` ขึ้นถึงจุดสูงสุดที่วันที่ 166 และยังมีผู้ติดเชื้อ 2.1% ของประชากรอยู่ที่วันที่ 180 นั่นแปลว่าการระบาดยังไม่จบ และตัวเลข 0.268 ของเงื่อนไข D อาจเป็นเพียงการยืดเวลา ไม่ใช่การลดจำนวนผู้ติดเชื้อสุทธิ ถ้าเป็นอย่างหลัง ข้อสรุปเรื่องประโยชน์ของผู้นำ LLM ก็จะต้องเขียนใหม่

เราจึงรัน `typhoon8b` เงื่อนไข C และ D ใหม่ที่ 365 วัน ด้วย seed 1 โดยเลือกโมเดลนี้เพราะเป็นกรณีที่ปัญหารุนแรงที่สุดในแผง การรันหนึ่งโมเดลหนึ่ง seed เป็นข้อจำกัดด้านงบ GPU ผลในหัวข้อนี้จึงเป็นการสำรวจ ไม่ใช่การวัด และใช้เทียบข้ามโมเดลไม่ได้

ก่อนตีความ ได้ตรวจแล้วว่า 180 วันแรกของรัน 365 วันตรงกับรัน 180 วันเดิมทุกคอลัมน์ทุกวัน (ผลต่างสูงสุด 0.0 ใน `S`, `I`, `q_out` และ `share_stay_home`) รัน 365 วันจึงเป็นการต่อเส้นเดิม ไม่ใช่การรันใหม่ที่บังเอิญคล้ายกัน

| 90 | 0.250 | 5.03% | 0.095 | 1.45% |

| 150 | 0.580 | 4.44% | 0.221 | 2.24% |
| 180 | 0.643 | 2.04% | 0.284 | 2.10% |

เงื่อนไข C จบแล้วจริง ๆ ที่วันที่ 365 เหลือผู้ติดเชื้อ 0.004% ของประชากร และ attack rate เพิ่มจาก 0.643 เป็น 0.679 เท่านั้น (+0.036 หรือ 5.6%) เงื่อนไข D ยังไม่จบ เหลือผู้ติดเชื้อ 0.14% และ attack rate เพิ่มจาก 0.284 เป็น 0.422 (+0.138 หรือ 49%) จุดสูงสุดของ D อยู่ที่ 2.3% ในวันที่ 160 เทียบกับ 6.4% ในวันที่ 118 ของ C คือต่ำกว่า 65% และช้ากว่า 42 วัน

# 6. อภิปราย

## 6.1 ต่อยอดจาก Ferencz et al. — การจูนภาษาก็ยังไม่รับประกัน cultural validity

Ferencz et al. (2026) ตั้งคำถามว่าการบอก LLM ว่า agent มาจากประเทศใดประเทศหนึ่งจะให้พฤติกรรมแบบประเทศนั้นหรือไม่ และทดสอบด้วย geographic label ใน prompt ซึ่งเป็นการแทรกแซงเชิงวัฒนธรรมที่อ่อนที่สุดเท่าที่ทำได้ เพราะเปลี่ยนเพียงข้อความนำเข้าโดยไม่แตะตัวโมเดล

โครงงานนี้ทดสอบการแทรกแซงที่แรงกว่านั้นมาก คือการจูนน้ำหนักของโมเดลด้วยภาษาและข้อมูลไทย ซึ่งเป็นสิ่งที่ผู้ใช้งาน GABM ในบริบทไทยน่าจะเลือกทำเป็นอันดับแรก คำตอบที่ได้คือยังไม่เพียงพอ

หลักฐานสามชั้นสนับสนุนข้อสรุปนี้ ชั้นแรกคือผลของการจูนกลับเครื่องหมายระหว่างสองตระกูล (−0.181 เทียบ +0.027) ซึ่งหมายความว่า *สิ่งที่กำหนดพฤติกรรมคือปฏิสัมพันธ์ระหว่างโมเดลฐานกับข้อมูลที่ใช้จูน ไม่ใช่การมีอยู่ของการจูน* ชั้นที่สองคือ `seallm7b` ซึ่งจูนทั้งภูมิภาคเอเชียตะวันออกเฉียงใต้ กลับอยู่ในกลุ่มเดียวกับโมเดลฐานทั้งสองตัว แสดงว่าการจูนภาษาในภูมิภาคโดยทั่วไปก็ไม่ได้ให้ผลแบบเดียวกับการจูนภาษาไทยในตระกูล Llama ชั้นที่สามคือไม่มีโมเดลใดเขียนเหตุผลเป็นภาษาไทยเลย ซึ่งแสดงว่าสิ่งที่การจูนเปลี่ยนไม่ใช่ความสามารถทางภาษาที่สังเกตได้ แต่เป็น behavioral prior ที่ซ่อนอยู่

หลักฐานชั้นที่สี่มาจากการทดลองแทรกแซงคุณลักษณะเดียวในหัวข้อ 5.8.3 เมื่อพลิกบรรทัด `Can work from home` ของ agent คนเดียวจาก `no` เป็น `yes` โดยคงทุกอย่างที่เหลือไว้ `typhoon8b` เปลี่ยนคำตอบ 111 จาก 180 วัน แต่ `openthaigpt7b` ไม่เปลี่ยนแม้แต่วันเดียว โมเดลที่จูนไทยในตระกูล Qwen จึงไม่ได้อ่านคุณลักษณะของ persona ที่ควรกำหนดคำตอบโดยตรงที่สุด ความล้มเหลวนี้ลึกกว่าการไม่มีความรู้เชิงวัฒนธรรม เพราะเป็นการไม่ตอบสนองต่อข้อมูลเฉพาะบุคคลใน prompt เลย การจูนภาษาท้องถิ่นจึงอาจทำให้ความสามารถในการปรับคำตอบตาม persona *แย่ลง* ได้ในบางตระกูล

ข้อสรุปจึงขยายจากงานของ Ferencz et al. จากเดิมที่ว่า *"ป้ายกำกับประเทศไม่พอ"* เป็น *"การแทรกแซงเชิงวัฒนธรรมแม้ในระดับน้ำหนักโมเดลก็ยังไม่รับประกัน cultural validity"* สำหรับผู้ที่จะใช้ GABM จำลองประชากรนอกบริบทตะวันตก นัยเชิงปฏิบัติคือการเลือกโมเดลที่จูนภาษาท้องถิ่นไม่สามารถใช้แทนการตรวจสอบ validity ได้ และผลควรรายงานจากหลายโมเดลเสมอ

ช่วงของ attack rate ในเงื่อนไข C กว้างถึง 0.638–0.859 เพียงจากการเปลี่ยนโมเดล ซึ่งสอดคล้องกับประเด็น internal validity ของ Ferencz et al. ช่วงนี้กว้างกว่าผลของการมีหรือไม่มีชั้นผู้นำในบางโมเดลเสียอีก การเลือก LLM จึงเป็นการตัดสินใจเชิงแบบจำลองที่สำคัญไม่น้อยกว่าการเลือกโครงสร้างของแบบจำลองเอง

## 6.2 ต่อยอดจาก Aoki & Ghaffarzadegan — policy inertia ในรูปแบบอิ่มตัว

Aoki & Ghaffarzadegan (2026) รายงานจาก regression ว่านโยบายสัปดาห์ก่อนเป็นตัวทำนายระดับมาตรการที่แรงที่สุด (p<0.001) ซึ่งบ่งชี้ policy inertia ที่สูงมาก ผลของโครงงานนี้เป็นกรณีอิ่มตัวของปรากฏการณ์เดียวกัน คือนโยบายไม่เปลี่ยนเลยตลอด 25 จาก 26 สัปดาห์ในเกือบทุกรัน แม้ยอดผู้ป่วยจะขึ้นถึง 986 ต่อแสนต่อวันก็ตาม

สิ่งที่โครงงานนี้เพิ่มเข้ามาคือการแยกให้เห็นว่า inertia นี้ไม่ได้เกิดจากการอ่านข้อมูลไม่ออก เพราะเหตุผลที่โมเดลเขียนกำกับรายงานทั้งระดับ แนวโน้ม และสัดส่วนคนออกไปทำงานได้ถูกต้องทุกสัปดาห์ สิ่งที่เกิดขึ้นจึงเป็นการแยกขาดระหว่างการให้เหตุผลกับการกระทำ หรือ **dissociation** คือโมเดลสรุปสถานการณ์ได้ถูกแต่ไม่แปลงข้อสรุปนั้นเป็นการเลือกที่ต่างออกไป รูปแบบความล้มเหลวนี้ชี้เป้าได้ชัดกว่าการสรุปว่า "โมเดลตัดสินใจไม่ดี"

ความแตกต่างเชิงการออกแบบที่สำคัญคือประชาชนในโครงงานนี้เป็น LLM agent ด้วย ขณะที่ในงานของ Aoki & Ghaffarzadegan ประชาชนเป็นสมการ `b = 1/(1 + k·C)` การที่ผู้นำทุกโมเดลตัดสินใจเหมือนกันแทบทั้งหมดจึงทำให้สรุปได้ว่าความต่างของผลในเงื่อนไข D ที่กว้างถึง 0.268–0.723 มาจากประชาชนทั้งหมด ไม่ได้มาจากผู้นำ ซึ่งเป็นการแยกส่วนที่งานของเขาทำไม่ได้โดยโครงสร้าง

งานของเขาเสนอทางแก้ไว้แล้วคือ knowledge intervention ซึ่งเป็นข้อความราว 200 คำที่อธิบาย feedback loop ของการระบาดให้ agent ฟัง และให้ผลลด cumulative cases ลงหนึ่งในสาม dissociation ที่เราพบน่าจะตอบสนองต่อการแทรกแซงแบบเดียวกัน เพราะปัญหาไม่ใช่ว่าโมเดลไม่เห็นตัวเลข แต่คือโมเดลไม่เชื่อมตัวเลขกับผลที่จะตามมา การทดสอบข้อนี้เป็นงานถัดไปที่ชัดเจนที่สุด

หัวข้อ 5.10 เพิ่มเงื่อนไขหนึ่งข้อให้กับการอ่านผลของเงื่อนไข D เมื่อรัน `typhoon8b` ต่อถึง 365 วัน ส่วนต่างระหว่าง C กับ D แคบลงจาก 0.359 เหลือ 0.258 คือเหลือราว 72% ประมาณ 30% ของประโยชน์ที่วัดได้ที่ 180 วันจึงเป็นการยืดเวลาล้วน ๆ ซึ่งไม่ใช่สิ่งไร้ค่าในทางระบาดวิทยา เพราะจุดสูงสุดลดลง 65% และเลื่อนออกไป 42 วัน คือนิยามของ flatten the curve แต่ผลนี้เป็นเหตุผลเพิ่มอีกข้อที่ตัวเลขเงื่อนไข D อ่านเป็นประสิทธิผลของผู้นำ LLM ไม่ได้

ข้อสังเกตที่สอดคล้องอีกข้อคือ Aoki & Ghaffarzadegan พบว่าความรุนแรงที่ระลึกได้มี coefficient ติดลบ ซึ่งพวกเขาตีความว่าเป็น adaptation หรือ normalization ในข้อมูลของเรา เหตุผลของผู้นำเปลี่ยนจาก "Rising cases, need to slow spread" ไปเป็น "Cases stable; encourage remote work" เมื่อการระบาดขึ้นถึงที่ราบสูง ทั้งที่ระดับสัมบูรณ์สูงมาก การที่โมเดลตอบสนองต่อ *อนุพันธ์* มากกว่า *ระดับ* จึงเป็นคำอธิบายที่เป็นไปได้ของทั้งสองงาน

## 6.3 ต่อยอดจาก Williams et al. — พฤติกรรม endogenous ไม่ได้แปลว่าการระบาดเบาลงเสมอ

Williams et al. (2023) แสดงว่าการให้พฤติกรรมตอบสนองต่อข้อมูลสุขภาพและข้อมูลชุมชนทำให้เส้นการระบาดเปลี่ยนไปจาก baseline ในโครงงานนี้ สี่ในห้าโมเดลให้ attack rate สูงกว่าเงื่อนไข A ที่ไม่มีการตอบสนองเชิงพฤติกรรมเลย และทั้งสี่โมเดลมี q̄_out ระหว่าง 1.104 ถึง 1.285

มีสองการตีความที่เป็นไปได้ และข้อมูลที่มีอยู่ยังไม่พอจะชี้ขาดระหว่างสองข้อนี้ การตีความแรกคือนี่เป็นผลการทดลองที่มีความหมาย กล่าวคือ LLM ประเมินแรงกดดันทางเศรษฐกิจของ persona สูงกว่าที่สมมติไว้ใน `baseline_mix` โมเดลเหล่านี้จึงจำลอง "คนที่หยุดงานไม่ได้" ได้สมจริง แต่ไม่จำลองการลดกิจกรรมโดยสมัครใจ ซึ่งสอดคล้องกับผลในหัวข้อ 5.4 ที่พบว่ากรอบ "รายได้" ครอบงำเหตุผลถึง 54–65% ในสี่โมเดลนั้น การตีความที่สองคือเป็น artefact ของ `baseline_mix.work_onsite = 0.55` ซึ่งเป็นค่าที่ตั้งขึ้นโดยไม่มีแหล่งอ้างอิง

หัวข้อ 5.9 ทดสอบข้อนี้โดยตรงและให้คำตอบที่อยู่ตรงกลาง เมื่อยก `work_onsite` ของวันปกติขึ้นเป็น 0.67 ซึ่งเป็นขอบบนที่ป้องกันได้ q̄_out ลดลงราว 0.13 ในสี่โมเดล (0.128 ถึง 0.148) ส่วน `typhoon8b` ลดลง 0.079 และ `llama8b` ข้ามเส้นมาอยู่ต่ำกว่าเงื่อนไข A ส่วน `qwen7b`, `openthaigpt7b` และ `seallm7b` ยังคงให้ attack rate สูงกว่าเงื่อนไข A อยู่ ข้อสังเกตนี้จึงไม่ใช่ artefact ทั้งหมด แม้จะอ่อนกว่าที่ตัวเลขชุดแรกบ่งชี้ สามโมเดลชุดเดียวกันนี้ยังมี q̄_out มากกว่า 1 คือยังจำลองประชากรที่ออกนอกบ้านมากกว่าวันปกติทั้งที่กำลังมีโรคระบาด ซึ่งสอดคล้องกับกรอบ "รายได้" ที่ครอบงำเหตุผลในหัวข้อ 5.4

บทเรียนเชิงวิธีวิทยาที่ตามมาชัดเจนกว่าเดิมคือการวัดว่า "พฤติกรรมเปลี่ยนการระบาดหรือไม่" ต้องอาศัย baseline ของพฤติกรรมในวันปกติที่มีแหล่งอ้างอิง มิฉะนั้นตัวเลข q_out จะตีความไม่ได้เลย และอันดับของโมเดลเทียบกับ baseline ก็เลื่อนได้ตามค่าที่เลือก ข้อกำหนดนี้งาน GABM ที่ทบทวนมาทั้งสามชิ้นไม่ได้ระบุไว้ชัดเจน ในกรณีของเรา การเปลี่ยนสมมติฐานตัวเดียวทำให้จำนวนโมเดลที่ "แย่กว่าไม่ทำอะไรเลย" ลดจากสี่เหลือสาม

## 6.4 บทเรียนเชิงปฏิบัติสำหรับงาน GABM นอกบริบทตะวันตก

1. การทดสอบหลายโมเดลจำเป็นเสมอ และการจัดเป็น factorial ดีกว่าการเลือกโมเดลมาเปรียบเทียบลอย ๆ เพราะการเปรียบเทียบโมเดลที่จูนกับไม่จูนมักข้ามตระกูลไปพร้อมกัน ทำให้แยกสองปัจจัยไม่ออก
2. การตรวจ position bias ในชุดตัวเลือกเป็นการทดสอบที่ราคาถูกมาก (รันเพิ่มสองลำดับ) แต่เปลี่ยนความหมายของตัวเลขที่รายงานได้ทั้งหมด งานที่ทบทวนทั้งสามชิ้นไม่ได้รายงานการทดสอบนี้
3. ความหลากหลายของเหตุผลควรถูกตรวจควบคู่กับผลลัพธ์รวม เพราะ reason collapse ที่พบในตระกูล Qwen มองไม่เห็นเลยจาก attack rate แต่เป็นสัญญาณชัดว่าโมเดลไม่ได้ประเมินสถานการณ์ใหม่จริง
4. เมื่อประเมิน agent ที่ตัดสินใจเชิงนโยบาย การอ่านข้อมูลควรแยกออกจากการกระทำ เพราะ agent อาจสรุปสถานการณ์ได้ถูกต้องสมบูรณ์แล้วยังเลือกเหมือนเดิม ซึ่งการดูเฉพาะผลลัพธ์จะตีความผิดเป็น "ชั้นผู้นำได้ผลดี"

# 7. ข้อจำกัด

ข้อจำกัดต่อไปนี้เรียงตามความร้ายแรงต่อการตีความผล

1. ผู้นำไม่แปลงการอ่านสถานการณ์เป็นการกระทำ `strict` ถูกใช้ 5 ครั้งจาก 702 และอยู่ในสองรันที่ผู้นำเห็นยอดเคสต่ำที่สุดของโมเดลนั้น ผลของเงื่อนไข D จึงเทียบเท่ากับนโยบายคงที่ ไม่ใช่นโยบายที่ปรับตามสถานการณ์ ผลนี้จึงไม่สะท้อนว่าชั้นผู้นำ LLM มีประสิทธิผล
2. `contacts.baseline_mix` เป็น `assumption` ที่ไม่มีแหล่งอ้างอิง หัวข้อ 5.9 แสดงว่าข้อสรุปหลักของโครงงาน (ผลการจูนภาษาในแต่ละตระกูล) ไม่ขึ้นกับค่านี้ เครื่องหมายไม่เปลี่ยนและขนาดใกล้เคียงเดิม ส่วนข้อสังเกตรองที่ว่าเงื่อนไข C รุนแรงกว่า A ขึ้นกับค่านี้จริง เมื่อใช้ค่าที่อนุรักษ์นิยมกว่า จำนวนโมเดลที่ให้ attack rate สูงกว่า A ลดจากสี่เหลือสาม และจำนวนโมเดลที่มี q̄_out มากกว่า 1 ลดจากสี่เหลือสามเช่นกัน โมเดลสองชุดนี้เป็นชุดเดียวกัน คือ `qwen7b`, `openthaigpt7b` และ `seallm7b` ตัวเลข q̄_out ทุกค่าในรายงานนี้จึงผูกกับสมมติฐาน ไม่ใช่ปริมาณที่วัดได้
3. สัดส่วนกิจกรรมรายตัวไม่คงทนต่อลำดับตัวเลือกใน prompt โดย `essential_errand` ของ `qwen7b` แกว่งระหว่าง 0.000 ถึง 0.681 ข้อสรุปเชิงเปรียบเทียบระหว่างโมเดลยังใช้ได้เพราะควบคุมลำดับให้เหมือนกัน แต่ตัวเลขสัดส่วนเดี่ยว ๆ ใช้อ้างไม่ได้
4. กรอบเวลา 180 วันไม่เพียงพอสำหรับโมเดลที่ระบาดช้า เงื่อนไข D ของ `typhoon8b` มี peak ที่วันที่ 166 และวันสุดท้ายยังมีผู้ติดเชื้อ 2.1% ของประชากร ตัวเลขที่รายงานทั้งหมดจึงเป็น *attack rate สะสม 180 วัน* ไม่ใช่ขนาดการระบาดสุดท้าย หัวข้อ 5.10 วัดขนาดของปัญหาไว้ที่โมเดลหนึ่ง seed หนึ่ง คือส่วนต่างระหว่าง C กับ D ลดลงเหลือ 72% เมื่อรันถึง 365 วัน ผลนี้บรรเทาแต่ไม่ลบข้อจำกัดนี้ และยังไม่ได้ตรวจกับโมเดลอื่น
5. ขนาดครัวเรือนไม่ได้เข้าสู่แบบจำลอง ค่า `household_size` ถูกบอกแก่ agent เป็นข้อความใน persona แต่ไม่ได้ถูกใช้คำนวณการสัมผัสในครัวเรือน เพราะ `w_home` เป็นค่าเดียวกันทั้งประชากร ช่องว่างเชิงวิธีวิทยานี้แก้ได้ในเวอร์ชันถัดไปโดยให้ `w_home` แปรตามขนาดครัวเรือนจริงจาก Digital Census 2568
6. การวิเคราะห์ความไวเป็นแบบ one-at-a-time จึงจับปฏิสัมพันธ์ระหว่างพารามิเตอร์ไม่ได้ การวิเคราะห์ที่ครบต้องใช้วิธีเชิง variance เช่น Sobol ซึ่งต้องรันหลายร้อยครั้งและเกินงบประมาณการคำนวณของโครงงาน นอกจากนี้การกระจายงบ GPU ทำให้ความครอบคลุมไม่เท่ากันระหว่างโมเดล สามแกนที่เกี่ยวกับโครงสร้างการสัมผัสรันบน `llama8b` เท่านั้น มีเพียง `wfh_scale` ที่รันครบทั้งห้าโมเดล ความคงทนที่รายงานในหัวข้อ 5.8.1 สำหรับอีกสี่โมเดลจึงอนุมานจากกลไกร่วม (ข้อโต้แย้งเรื่อง q̄_out และ w_home ในหัวข้อ 5.8.2) ไม่ได้วัดโดยตรง
7. พารามิเตอร์ 18 จาก 28 ตัวมีสถานะ `assumption` และมีเพียง 5 ตัวที่มีสถานะ `data` ซึ่งเป็นเหตุผลหลักที่งานนี้เป็น scenario study ไม่ใช่การพยากรณ์
8. เงื่อนไข C และ D ใช้ 6 seeds ยกเว้นตัวควบคุม `seallm7b` ซึ่งเงื่อนไข D ยังมี 3 seeds ค่า p = 0.0022 ของทั้งสองเงื่อนไขชนพื้นของ exact permutation test พอดี จึงบอกจำนวน seed ไม่ได้บอกความแรงของหลักฐาน และต้องอ้างคู่กับขนาดของผลเสมอ ค่า SD ที่ต่ำมาก (0.001–0.030) มาจากประชากร N = 1,000,000 ซึ่งกลบความผันผวนเชิงสุ่มของ SEIR ไม่ได้หมายความว่า LLM ให้คำตอบเหมือนกันทุกครั้ง ข้อจำกัดที่หนักกว่าจำนวน seed คือ seed ทุกตัวใช้ `persona_seed` เดียวกัน ความไม่แน่นอนจากการสุ่มบุคลิกจึงยังไม่ถูกสุ่มเลยแม้แต่ครั้งเดียว
9. การใช้ 40 agents แทนประชากรหนึ่งล้านคนเป็นการ scale ซึ่งผลทุกค่าตั้งอยู่ภายใต้เงื่อนไขนั้น ข้อสรุปจำกัดอยู่กับโมเดลขนาด 7–8B ที่ quantize แบบ 4-bit เท่านั้น และการ quantize อาจกระทบพฤติกรรมในทางที่ไม่ได้วัด
10. งานนี้เป็น scenario study ไม่ใช่ forecast ที่ calibrate การเทียบกับโลกจริงเป็นเชิงคุณภาพเท่านั้น เช่นเดียวกับงานทั้งสามชิ้นที่ทบทวนมา

# 8. สรุป

โครงงานนี้ถามว่าการจูนภาษาไทยทำให้ LLM จำลองพฤติกรรมของคนไทยในแบบจำลองโรคระบาดได้ดีขึ้นหรือไม่ และตอบด้วยการออกแบบ 2×2 ที่แยกตระกูลโมเดลออกจากการจูนภาษา ซึ่งเป็นสองปัจจัยที่งานก่อนหน้าปะปนกัน ผลจากการตัดสินใจ 410,400 ครั้งบนโมเดลห้าตัว สี่เงื่อนไข และหก seed ในเงื่อนไข C และ D (ยกเว้นเงื่อนไข D ของ `seallm7b` ซึ่งมีสาม seed) สรุปได้สี่ข้อ

ข้อที่หนึ่ง (RQ1): การจูนภาษาไทยไม่มีทิศทางที่แน่นอน ผลของการจูนติดลบในตระกูล Llama (−0.181 ในเงื่อนไข C และ −0.344 ในเงื่อนไข D) แต่เป็นบวกในตระกูล Qwen (+0.027 และ +0.056) กล่าวคือ *สิ่งที่กำหนดพฤติกรรมคือปฏิสัมพันธ์ระหว่างโมเดลฐานกับข้อมูลที่ใช้จูน ไม่ใช่การมีอยู่ของการจูน* ตัวควบคุมระดับภูมิภาค `seallm7b` อยู่ในกลุ่มเดียวกับโมเดลฐานทั้งสองตัว ซึ่งยืนยันว่าการจูนภาษาในภูมิภาคโดยทั่วไปก็ไม่ได้ให้ผลแบบเดียวกัน

ข้อที่สอง (RQ2): กลไกตรวจสอบได้จากข้อความที่โมเดลผลิตเอง การวิเคราะห์เหตุผล 36,000 รายการพบว่าการจูนในตระกูล Llama ลดการอ้างกรอบ "รายได้" จาก 54% เหลือ 19% ขณะที่การจูนในตระกูล Qwen เพิ่มจาก 56% เป็น 65% ซึ่งตรงกับเครื่องหมายของผลที่วัดได้ทั้งสองตระกูล ความหลากหลายของเหตุผลต่างกันกว่าสี่เท่าระหว่างสองตระกูล (76.5% เทียบ 17.1% ของเหตุผลที่ไม่ซ้ำ) การทดลองแทรกแซงคุณลักษณะเดียวยืนยันอีกชั้นหนึ่งว่า `openthaigpt7b` ไม่เปลี่ยนคำตอบแม้แต่ครั้งเดียวใน 180 วันเมื่อพลิกบรรทัด `Can work from home` ของ agent ที่เกี่ยวข้อง ขณะที่ `typhoon8b` เปลี่ยน 111 ครั้ง

ข้อที่สาม (RQ3): ผู้นำ LLM อ่านสถานการณ์ถูกแต่ไม่แปลงเป็นการกระทำ ระดับ `strict` ถูกเลือก 5 ครั้งจาก 702 และทั้งหมดอยู่ในสองรันที่ผู้นำเห็นยอดเคสสูงสุด *ต่ำที่สุด* ของโมเดลนั้น (528 และ 602 ต่อแสนต่อวัน จากหกรัน) ขณะที่ `openthaigpt7b` คงระดับ `limited` ไว้ตลอดแม้ยอดจะขึ้นถึง 986 ต่อแสนต่อวัน เหตุผลที่โมเดลเขียนกำกับรายงานระดับและแนวโน้มได้ถูกต้องทุกสัปดาห์ ความล้มเหลวจึงอยู่ที่การแปลงข้อสรุปเป็นการเลือก ไม่ใช่ที่การอ่านข้อมูล รูปแบบนี้ชี้เป้าการแก้ไขได้ชัดกว่าการสรุปว่า "โมเดลตัดสินใจไม่ดี"

ข้อที่สี่: ข้อสรุปหลักคงทน แต่ข้อสังเกตรองไม่คงทน เครื่องหมายของผลการจูนไม่เปลี่ยนเมื่อสลับลำดับตัวเลือกใน prompt ทั้งสามแบบ ไม่เปลี่ยนเมื่อกวาดพารามิเตอร์สี่แกน (ขยับได้มากสุด 0.025 เทียบกับขนาดผล 0.181) และไม่เปลี่ยนเมื่อเปลี่ยนสมมติฐาน `baseline_mix` เป็นขอบบนที่ป้องกันได้ ในทางกลับกัน ข้อสังเกตที่ว่า agent LLM ทำให้การระบาดแย่กว่าการไม่ตอบสนองเลยอ่อนลงจากสี่โมเดลเหลือสามเมื่อเปลี่ยนสมมติฐานนั้น และส่วนต่างระหว่างเงื่อนไข D กับ C เหลือ 72% เมื่อรันถึง 365 วัน ทั้งสองข้อเป็นผลที่ผูกกับตัวเลือกเชิงวิธีวิทยา ไม่ใช่ปริมาณที่วัดได้โดยตรง

ในเชิงนัยปฏิบัติ สำหรับผู้ที่จะใช้ GABM จำลองประชากรนอกบริบทตะวันตก การเลือกโมเดลที่จูนภาษาท้องถิ่นไม่สามารถใช้แทนการตรวจสอบ validity ได้ ช่วงของ attack rate ที่เกิดจากการเปลี่ยนโมเดลเพียงอย่างเดียวกว้างถึง 0.638–0.859 ซึ่งกว้างกว่าผลของการเพิ่มชั้นผู้นำในบางโมเดลเสียอีก การเลือก LLM จึงเป็นการตัดสินใจเชิงแบบจำลองที่สำคัญไม่น้อยกว่าการเลือกโครงสร้างของแบบจำลองเอง และผลควรรายงานจากหลายโมเดลพร้อมการทดสอบ position bias เสมอ

งานถัดไปที่ชัดเจนที่สุดคือการทดสอบ knowledge intervention ของ Aoki & Ghaffarzadegan กับ dissociation ที่พบในเงื่อนไข D เพราะปัญหาไม่ใช่ว่าโมเดลไม่เห็นตัวเลข แต่คือไม่เชื่อมตัวเลขกับผลที่จะตามมา รองลงมาคือการให้ `w_home` แปรตามขนาดครัวเรือนจริง เพื่อให้ `household_size` ที่บอกแก่ agent มีผลในกลไกด้วย ไม่ใช่เป็นเพียงข้อความใน prompt
