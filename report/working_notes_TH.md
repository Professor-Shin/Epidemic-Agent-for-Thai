## 2. Baseline และเรื่องที่น่ากังวลที่สุด: C ระบาดหนักกว่า A

| เงื่อนไข | attack rate | peak I | peak day | q̄_out |
|---|---|---|---|---|
| A (SEIR เปล่า) | 0.795 | 11.0% | 87 | 1.000 (นิยาม) |
| B (rule-based) | 0.469 | 3.8% | 105 | 0.475 |
| C llama8b | 0.819 | 12.0% | 82 | 1.103 |
| C typhoon8b | 0.640 | 6.4% | 117 | 0.647 |
| C qwen7b | 0.830 | 13.1% | 76 | 1.169 |
| C openthaigpt7b | 0.858 | 14.6% | 72 | 1.280 |
| C seallm7b | 0.845 | 13.6% | 76 | 1.219 |

A = 0.795 ตรงกับ final size เชิงวิเคราะห์ของ R₀ = 2.0 (0.797) → แกน SEIR ถูกต้อง

**ปัญหา: 4 ใน 5 โมเดลให้ q̄_out > 1 แปลว่าเอเจนต์ LLM ออกนอกบ้าน _มากกว่า_ ประชากรฐาน ทั้งที่กำลังมีโรคระบาด**

นี่ไม่ใช่บั๊กในโค้ด แต่เป็นผลของการตั้งค่า `contacts.baseline_mix` ซึ่งติดสถานะ `assumption` ใน `data/parameter_sources.csv`:

```
baseline_mix = {stay_home 0.20, work_onsite 0.55, essential_errand 0.15, visit_family 0.10}
```

ค่า relative contact ที่คำนวณได้จาก Prem et al. Thailand matrix (`adult_20_64`: home 4.98, work 3.857, others 5.147) โดย `relative_i = (1 − w_home)·(c_out_i / base_out) + w_home`, `w_home = 0.507`, `base_out = 4.835`:

| action | c_out | relative contact |
|---|---|---|
| work_onsite | 7.356 | **1.257** |
| visit_family | 4.034 | 0.918 |
| essential_errand | 2.573 | 0.770 |
| stay_home | 0 | 0.507 |

เอเจนต์ LLM เลือก `work_onsite` 66–80% ขณะที่ baseline_mix สมมติไว้ 55% ส่วนต่างนี้เองที่ดัน q_out ขึ้นเกิน 1

**สองการตีความ เลือกอันใดอันหนึ่งแล้วเขียนให้ตรง**

1. *เป็นผลการทดลอง* — LLM ประเมินแรงกดดันทางเศรษฐกิจของ persona สูงกว่าที่เราสมมติ โมเดลเหล่านี้จึงจำลอง "คนที่หยุดงานไม่ได้" ได้สมจริง แต่ไม่จำลองการลดกิจกรรมโดยสมัครใจ
2. *เป็น artefact ของ baseline* — ถ้า `baseline_mix.work_onsite` ควรเป็น 0.67 (เท่ากับ `employment_rate`) แทน 0.55 ค่า q_out จะลงมาใกล้ 1 และ C จะไม่สูงกว่า A

**ความเห็น: ต้องเขียนทั้งสองอย่าง** เพราะ `baseline_mix` เป็น assumption ที่ไม่มีแหล่งอ้างอิง การเคลมว่า "LLM ทำให้ระบาดหนักขึ้น" โดยไม่บอกว่าผลนี้ขึ้นกับ assumption ตัวเดียวเป็นการเคลมเกินข้อมูล ถ้ามีเวลา ควรรัน C ซ้ำด้วย `baseline_mix.work_onsite = 0.67` อย่างน้อยหนึ่งโมเดลเพื่อดูว่าผล 2×2 (เครื่องหมายของ effect) เปลี่ยนไหม — เดาว่าไม่เปลี่ยน เพราะมันเลื่อนทุกโมเดลเท่า ๆ กัน แต่ควรมีหลักฐาน

## 4. เงื่อนไข D: ผู้นำอ่านสถานการณ์ถูก แต่การกระทำไม่ขึ้นกับสถานการณ์

D ลด attack rate ลงจาก C ในทุกโมเดล:

| โมเดล | C | D | ส่วนต่าง | peak เคสที่ผู้นำเห็น (ต่อแสนต่อวัน) |
|---|---|---|---|---|
| typhoon8b | 0.640 | 0.268 | −0.371 | 228 |
| llama8b | 0.819 | 0.601 | −0.218 | 644 |
| qwen7b | 0.830 | 0.666 | −0.164 | 832 |
| seallm7b | 0.845 | 0.693 | −0.152 | 824 |
| openthaigpt7b | 0.858 | 0.723 | −0.135 | 986 |

ดูผิวเผินเหมือนชั้นผู้นำได้ผล แต่เมื่อเปิด `leader.jsonl` ดูการตัดสินใจรายสัปดาห์ทั้ง 15 runs พบสองข้อเท็จจริงที่ต้องแยกจากกันให้ชัด

### 4.1 ผู้นำอ่านข้อมูลถูกต้อง — ข้อนี้ผ่าน

ตรวจฟิลด์ `reason` เทียบกับตัวเลขที่ป้อนเข้า prompt ในทุกสัปดาห์ของ `D_qwen7b_s1_e12d6e4d`, `D_typhoon8b_s1_b823e074`, `D_llama8b_s2_054ddc7a`:

- รายงาน trend ตรงกับที่ป้อนทุกครั้ง (rising → stable → falling ไล่ตามลำดับจริง)
- อ้างตัวเลขเคสและสัดส่วนคนออกไปทำงานได้ถูก เช่น typhoon8b วันที่ 126 ตอบว่า "215.0 cases per 100,000 people per day, stable trend, 15% on-site work"
- ไม่มี fallback และไม่มี retry เลยใน 390 การตัดสินใจ

**ดังนั้นไม่ใช่ปัญหาว่าโมเดลอ่านไม่ออก** ข้อนี้เขียนเป็นผลบวกได้

### 4.2 แต่การเลือกระดับนโยบายแทบไม่ขึ้นกับสิ่งที่อ่าน — ข้อนี้คือปัญหา

ลำดับการตัดสินใจรายสัปดาห์ (o = open, l = limited, s = strict, 26 สัปดาห์):

```
llama8b       s1  olllllllllllllllllllllllll   peak 625
llama8b       s2  olllllllllllssssllllllllll   peak 528   ← run เดียวที่ใช้ strict
llama8b       s3  olllllllllllllllllllllllll   peak 644
qwen7b        s1  olllllllllllllllllllllllll   peak 832
openthaigpt7b s1  olllllllllllllllllllllllll   peak 986
typhoon8b     s1  olllllllllllllllllllllllll   peak 228
```

**จาก 390 การตัดสินใจ `strict` ถูกเลือก 4 ครั้ง อยู่ใน run เดียว** ที่เหลือเลือก `open` สัปดาห์แรก (ตอนเคสเป็นศูนย์) แล้วเปลี่ยนเป็น `limited` และค้างอยู่อย่างนั้น 25 สัปดาห์

หลักฐานชี้ขาดว่าการยกระดับไม่ได้ขึ้นกับความรุนแรงของการระบาด:

- **llama8b seed 2 ซึ่งเป็น run เดียวที่ยกระดับ มี peak ต่ำที่สุดในสาม seeds ของตัวเอง (528 เทียบกับ 625 และ 644)** ถ้าการยกระดับเป็นฟังก์ชันของจำนวนเคส seed 1 และ 3 ต้องยกระดับก่อน แต่ไม่ยก
- **openthaigpt7b เห็นเคส 986 ต่อแสนต่อวัน — สูงกว่าจุดที่ llama8b ยกระดับเกือบสองเท่า — และยังเลือก `limited`**
- qwen7b ที่ 831 ต่อแสนต่อวัน ให้เหตุผลว่า "Cases stable; encourage remote work, maintain essential activities"

ส่วนที่ llama8b seed 2 ทำได้ถูกต้องคือ **หลังยกระดับแล้วมันผ่อนลงเมื่อเคสลด** (strict วันที่ 84–105 ขณะเคส 528→470 แล้วกลับเป็น limited ที่ 440) นั่นเป็นพฤติกรรม closed-loop ที่ถูกต้อง — แต่เกิดขึ้นครั้งเดียวใน 390 ครั้ง จึงถือเป็นเหตุบังเอิญ ไม่ใช่ความสามารถ

### 4.3 ผลต่อการตีความ

1. **ผล "D ดีกว่า C" ไม่ใช่ผลของนโยบายที่ปรับตามสถานการณ์** แต่เป็นผลของการตั้ง `limited` ค้างไว้ตลอด ซึ่งเทียบเท่ากับการใส่ policy level คงที่ — ไม่ต้องใช้ LLM ก็ได้ผลเดียวกัน
2. **ความต่างของ D ระหว่างโมเดล (0.268 ถึง 0.723) มาจากประชาชน ไม่ใช่ผู้นำ** เพราะผู้นำตัดสินใจเหมือนกันหมด ความต่างคือเอเจนต์แต่ละโมเดลตอบสนองต่อ `limited` ไม่เท่ากัน
3. ประโยคที่เขียนได้คือ **"ผู้นำ LLM รายงานสถานการณ์ได้ถูกต้องแต่ไม่แปลงเป็นการกระทำ"** — เป็น dissociation ระหว่างการให้เหตุผลกับการเลือก ซึ่งเป็น negative result ที่มีน้ำหนักกว่าการบอกว่าผู้นำช่วยลดการระบาด และตรงกับวรรณกรรมเรื่อง LLM ให้เหตุผลถูกแต่เลือกตามอคติของตัวเลือก

**กลไกที่น่าจะเป็น:** ทุกเหตุผลมีโครงสร้างเดียวกันคือ "balance health and livelihoods" ซึ่ง `limited` เป็นคำตอบกลางที่สนองกรอบนี้ได้เสมอ โมเดลจึงยึดตัวเลือกกลางโดยไม่สนระดับความรุนแรง — เป็น position/middle-option bias แบบเดียวกับที่เจอใน action order check (§5.2) แต่เกิดกับผู้นำ

**ข้อสังเกตเพิ่ม:** qwen7b สัปดาห์ที่ 161 ให้เหตุผลเป็นภาษาจีน ("Cases declining,但仍需限制以防止反弹") เป็น language leakage ครั้งเดียวที่พบ ไม่กระทบผลแต่ควรกล่าวถึงเมื่อพูดเรื่องคุณภาพเอาต์พุต

**ถ้าจะแก้** ต้องทำให้ผู้นำเห็นระดับความรุนแรงเชิงสัมบูรณ์ชัดกว่า trend (เช่น ใส่เกณฑ์อ้างอิงว่าเท่าไรถือว่าวิกฤต) หรือบังคับให้ระบุตัวเลขก่อนเลือก — **แต่อย่าแก้ตอนนี้** เพราะจะเปลี่ยน run id ทั้ง 15 runs ของ D เก็บเป็นข้อเสนอเวอร์ชันถัดไป

## 6. `visit_family` — สรุปว่าไม่ต้องแก้อะไร

คำถามเดิม: ตัด `visit_family` ออก หรือแก้ prompt?

**คำตอบ: ไม่ต้องทำทั้งสองอย่าง** มีหลักฐานสามชั้น

1. **ไม่ใช่ artefact ของลำดับ** — ถูกยกขึ้นอันดับหนึ่งใน 2 ลำดับ ได้ส่วนแบ่งสูงสุด 1.8% (llama8b) และ qwen7b กับ openthaigpt7b เป็น 0.000 เป๊ะแม้อยู่อันดับแรก
2. **ไม่สำคัญเชิงระบาดวิทยาอยู่แล้ว** — relative contact 0.918 ต่ำกว่าค่าเฉลี่ย 1.0 และ sweep `f_visit` 0.15→0.5 ขยับ attack rate แค่ 0.007 เทียบกับ `w_home_scale` 0.176
3. **counterfactual** — บังคับสัดส่วน `visit_family` ให้เท่ากับ baseline 10% ขยับ R_eff แค่ −0.043 ถึง +0.019 และทิศทางกลับกันใน 4 จาก 5 โมเดล

การแก้ prompt ตอนนี้จะเปลี่ยน run id ทั้ง 30 runs เพื่อแลกกับสิ่งที่พิสูจน์แล้วว่าไม่เปลี่ยนผล **ไม่คุ้ม**

**เขียนเป็นผลการทดลองแทน:** เอเจนต์ LLM ทั้ง 5 ตัวไม่เลือกไปเยี่ยมญาติระหว่างการระบาด แม้จะถูกเสนอเป็นตัวเลือกแรก น่าสนใจเพราะขัดกับภาพจำเรื่องครอบครัวขยายในบริบทไทย และเป็นหลักฐานว่าโมเดลใช้กรอบ "ลดการสัมผัส" แบบสากลมากกว่ากรอบวัฒนธรรมเฉพาะถิ่น

## 6.5 วิเคราะห์เหตุผลเชิงคุณภาพ — เจอกลไกของผล 2×2 แล้ว

ทำตามที่รายงาน #3 สัญญาไว้ วิเคราะห์ฟิลด์ `reason` ทั้ง 7,200 รายการต่อโมเดล (seed 1)

| โมเดล | เหตุผลไม่ซ้ำ | เหตุผลที่พบบ่อยสุด | สัดส่วน | กรอบ "รายได้" | กรอบ "จำเป็น" |
|---|---|---|---|---|---|
| llama8b | **76.5%** | "Work is considered essential and income loss is high…" | 0.7% | 54% | 34% |
| typhoon8b | **65.2%** | "work is considered essential" | 2.4% | **19%** | 36% |
| seallm7b | 64.8% | "I need to maintain my income…" | 2.0% | 59% | 24% |
| qwen7b | **19.0%** | "Need income to support family" | 11.6% | 56% | 32% |
| openthaigpt7b | **17.1%** | "Need income to support family" | **16.0%** | **65%** | 23% |

**สองเรื่องที่ได้จากตารางนี้ และทั้งคู่เขียนลงรายงานจริงได้**

1. **ตระกูล Qwen เกิด reason collapse** — ผลิตเหตุผลไม่ซ้ำแค่ 17–19% เทียบกับ 65–77% ของตระกูลอื่น เหตุผลเดียวกินถึง 16% นี่คือคำตอบของคำถามที่ค้างจากรายงาน #3 ว่าทำไม qwen เลือกไปทำงานซ้ำ ๆ — **เพราะมันผลิตเหตุผลซ้ำ ๆ ไม่ได้ประเมินใหม่ทุกวัน**

2. **กลไกของผล 2×2 อยู่ที่กรอบการให้เหตุผล ไม่ใช่ความบังเอิญเชิงตัวเลข**
   - Llama family: จูนไทยแล้วกรอบ "รายได้" ลดจาก 54% → **19%** → อยู่บ้านมากขึ้น → ระบาดเล็กลง
   - Qwen family: จูนไทยแล้วกรอบ "รายได้" **เพิ่ม** 56% → **65%** และ collapse หนักขึ้น → ออกไปทำงานมากขึ้น → ระบาดใหญ่ขึ้น

   ตรงกับเครื่องหมายของ effect ทั้งสองตระกูลพอดี → มี causal story ที่ตรวจสอบได้ในข้อความจริง ไม่ใช่แค่ correlation ระหว่าง attack rate

**ข้อสังเกตที่ไม่คาดคิด:** ไม่มีโมเดลใดตอบเหตุผลเป็นภาษาไทยเลย แม้แต่ typhoon8b และ openthaigpt7b เพราะ prompt เป็นอังกฤษ → **การจูนภาษาไทยส่งผลที่เนื้อหาการตัดสินใจ ไม่ใช่ที่ภาษาของเอาต์พุต** ข้อนี้น่าเขียนเพราะขัดกับสิ่งที่คนทั่วไปคาด

## 7. ข้อจำกัดที่ต้องอยู่ในรายงานจริง

เรียงตามความสำคัญ ข้อ 1–3 ปิดไม่ได้ ต้องเขียน

1. **ผู้นำใน D ไม่แปลงการอ่านสถานการณ์เป็นการกระทำ** — รายงาน trend และตัวเลขถูกต้องทุกสัปดาห์ แต่เลือก `limited` ค้าง 25/26 สัปดาห์ `strict` ถูกใช้ 4 ครั้งจาก 390 และอยู่ใน run ที่มี peak ต่ำที่สุดของโมเดลนั้น ผล D จึงเทียบเท่า fixed policy ไม่ใช่ adaptive policy (§4)
2. **`baseline_mix` เป็น assumption ที่ไม่มีแหล่งอ้างอิง** และผล "C > A" ขึ้นกับมันโดยตรง (§2)
3. **สัดส่วน action ไม่ robust ต่อลำดับใน prompt** แม้ทิศทางของผลหลักจะ robust (§5.2)
4. **180 วันไม่พอสำหรับ typhoon8b** ตัวเลขเป็น cumulative ไม่ใช่ final size (§3.3)
5. **`household_size` ไม่เข้าแบบจำลอง** เป็นแค่ข้อความใน prompt (§6.1)
6. **sensitivity ทำบน B เท่านั้น** ยังไม่รู้ว่าผล LLM ไวต่อโครงสร้าง contact แค่ไหน
7. **แกน `wfh_scale` ประกาศไว้แต่ไม่ได้รัน**
8. **3 seeds ต่อเงื่อนไข** SD ที่เล็กมากมาจาก N ใหญ่ ไม่ได้แปลว่า LLM เสถียร
9. **40 เอเจนต์แทนประชากร 1 ล้านคน** เป็นการ scale ที่ต้องอธิบายให้ชัด
10. **mistral7b (negative control) ยังไม่ได้รันในชุด 180 วัน** ถ้าจะเคลมว่ามันเป็นตัวควบคุมต้องรัน
11. **openthaigpt7b เลือกไปทำงาน 66.8% ขณะมีไข้และไอ** และส่งกลุ่ม notwork ออกไปทำธุระ 99.7% — ความสมจริงต่ำในสองมิตินี้ ต้องระบุ (§6.6)
